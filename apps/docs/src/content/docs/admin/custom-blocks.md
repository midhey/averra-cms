Для разработчика студии — владельца установки. После страницы вы соберёте свой блок, как в
WordPress с ACF Pro: поля для редактора, шаблон и стили, — и он появится в каталоге «Добавить
блок» рядом со встроенными. Без пересборки образа и без кода на сервере: блок живёт в базе этой
установки, обновление Averra его не трогает.

16 встроенных блоков и темы — пресеты: с ними сайт собирается за вечер. Свой блок — для того, что
делает сайт непохожим на другие: тарифы с наклейкой, карточка объекта, таблица сравнения.

## Кто что может

- **Владелец** создаёт, меняет, публикует, удаляет, выгружает и загружает свои блоки — раздел
  «Свои блоки» в панели, — и пишет [скрипт сайта](#скрипт-сайта).
- **Администратор сайта и редактор** ставят опубликованные свои блоки на страницы и заполняют их,
  как встроенные. Сами определения им не видны.
- **Нейронка через MCP** видит опубликованные свои блоки в `list_blocks` и заполняет их на
  страницах. Если у токена есть право на черновики своих блоков (у нового — по умолчанию, меняется
  в [Доступ для ИИ](/averra-cms/mcp/tokens/#в-админке)), она ещё и
  предлагает новые блоки — **черновиком**: проверяет шаблон и смотрит рендер, а опубликовать блок
  можете только вы, прочитав код в «Свои блоки». Публиковать, удалять и откатывать блоки токен не
  может. Подробно — [Свои блоки через MCP](/averra-cms/mcp/tools/#свои-блоки-четыре-инструмента).

Почему так — [решение](/averra-cms/decisions/custom-blocks/).

## Пример: «Тарифы с наклейкой»

1. «Свои блоки» → **«Создать блок»**. Название — «Тарифы с наклейкой», ключ — `tariffs` (латиница,
   его предложат из названия). На странице блок будет с типом `custom:tariffs`; ключ после
   создания не меняется.
2. Вкладка **«Поля»**. Заготовка уже с «Заголовком» (`title`) и «Текстом» (`text`). Добавьте поле,
   смените вид на «Повторитель», подпись — «Тарифы», ключ — `plans`. Внутри повторителя —
   «Название» (`title`, обязательное), «Наклейка» (`sticker`), «Цена» (`price`), «Фото» (вид
   «Картинка», `photo`) и «Кнопка» (вид «Ссылка», `button`).
3. Вкладка **«Шаблон»** — HTML с Liquid:

   ```liquid
   <h2 class="title">{{ title }}</h2>
   {% if text %}<div class="intro">{{ text | paragraphs }}</div>{% endif %}
   <ul class="plans" role="list">
     {% for plan in plans %}
     <li class="plan">
       {% if plan.sticker %}<span class="sticker">{{ plan.sticker }}</span>{% endif %}
       {{ plan.photo | image: '(min-width: 64rem) 33vw, 100vw', 'photo' }}
       <h3>{{ plan.title }}</h3>
       <p class="price">{{ plan.price }}</p>
       {% if plan.button %}
       <a class="button" href="{{ plan.button | link }}">{{ plan.button.label }}</a>
       {% endif %}
     </li>
     {% endfor %}
   </ul>
   ```

4. Вкладка **«CSS»** — стили только этого блока, цвета — ролями темы:

   ```css
   .plans {
     display: grid;
     grid-template-columns: minmax(0, 1fr);
     gap: var(--space-4);
     padding: 0;
     list-style: none;
   }

   @media (min-width: 64rem) {
     .plans {
       grid-template-columns: repeat(3, minmax(0, 1fr));
     }
   }

   .plan {
     padding: var(--space-4);
     border: 1px solid var(--color-border);
     border-radius: var(--radius);
   }

   .sticker {
     display: inline-block;
     padding: var(--space-1) var(--space-2);
     color: var(--color-on-accent);
     background: var(--color-accent);
     border-radius: var(--radius);
   }

   .title {
     font-family: var(--font-heading);
     font-size: var(--text-2xl);
   }

   .intro {
     max-width: 40rem;
     color: var(--color-muted);
   }

   .price {
     font-size: var(--text-2xl);
     font-weight: 700;
   }

   .button {
     display: inline-block;
     padding: var(--space-2) var(--space-4);
     color: var(--color-on-accent);
     text-decoration: none;
     background: var(--color-accent);
     border-radius: var(--radius);
   }

   .button:hover {
     text-decoration: underline;
   }
   ```

   Ссылки и кнопки тема сама не оформляет: класс из шаблона (`button`) получает вид в CSS блока.
   Картинка из фильтра `image` по умолчанию не шире карточки и сохраняет пропорции; другой размер
   — правилом для `.photo img` в CSS блока.

5. Вкладка **«Пример»** — данные, с которыми блок встаёт на страницу: та же форма, что у
   редактора. Цен и фактов не выдумывайте — заглушки в квадратных скобках («от [цена] ₽»).
6. Справа — **живой предпросмотр** на настоящем рендере в теме сайта, на телефоне, планшете и
   десктопе.
7. **«Опубликовать»**. Теперь в редакторе страницы «Добавить блок» → раздел **«Свои»** →
   «Тарифы с наклейкой».

## Готовые поведения

Простые эффекты не требуют своего скрипта — их дают атрибуты в шаблоне, скрипт Averra подключается
сам и только на страницах, где они есть:

| Атрибут | Что делает |
|---|---|
| `data-av-reveal` (`up`, `fade`, `left`, `right`, `zoom`) | элемент появляется, когда до него долистали |
| `data-av-details` на `<details>` | ответ раскрывается плавно |
| `data-av-hint="flip"` или `"wiggle"` | один раз поворачивает или покачивает элемент, когда его стало видно |
| `data-av-draw` | линия под текстом рисуется при появлении; `data-av-draw="svg"` — линии внутри SVG |
| `data-av-window` на `<a href="/zapis/">` | открывает страницу-окно поверх (без JS — переход) |

Без JavaScript и при «уменьшить движение» всё видно сразу. У поля «ссылка» есть флажок «Открывать в
окне»: `{% if cta.window %}data-av-window{% endif %}`. Подробно —
[Свои блоки для разработчика](/averra-cms/dev/custom-blocks/#готовые-поведения).

## Скрипт блока

Вкладка **«Скрипт»** — необязательный JavaScript блока: появление при прокрутке, плавное раскрытие,
подсказка. Это улучшение поверх рабочего HTML: без скрипта текст блока виден, ссылки ведут, формы
отправляются. Начальное состояние в CSS — финальное, скрипт добавляет класс и только тогда прячет
или анимирует.

- Код — тело async-функции: можно `await`, нельзя `import`. Переменная `blocks` — корни этих блоков
  на странице (`section[data-custom-block="<ключ>"]`) по порядку. Ищите элементы внутри блока:

  ```js
  const calm = matchMedia('(prefers-reduced-motion: reduce)').matches
  for (const block of blocks) {
    if (calm) continue
    block.classList.add('will-reveal')
    new IntersectionObserver(([entry], observer) => {
      if (!entry.isIntersecting) return
      block.classList.add('revealed')
      observer.disconnect()
    }).observe(block)
  }
  ```

  CSS к нему: прячется только то, что пометил скрипт, — `.will-reveal:not(.revealed) { opacity: 0 }`
  через `:scope.will-reveal:not(.revealed)`.
- На сайте скрипт — отдельный файл и подключается **только на страницах с блоком и один раз**,
  сколько бы экземпляров ни стояло. Выполняется после загрузки страницы. Ошибка в нём пишется в
  консоль и не ломает страницу и другие скрипты.
- Нельзя `eval`, `new Function`, строку в `setTimeout` и `document.write` — их запрещает
  [CSP сайта](/averra-cms/dev/security/#csp-сайта), проверка покажет совет. Ошибка разбора не даёт
  опубликовать блок.
- Внешние файлы скрипт блока не грузит: CSP пускает только сам сайт. Нужен виджет — его домен
  разрешают в [скрипте сайта](#скрипт-сайта).
- **«Выполнять скрипт»** над предпросмотром — блок в изолированной рамке со скриптом: ему
  недоступны вход в админку, её данные и запросы, формы там не отправляются. Без флажка
  предпросмотр обычный, скрипты не выполняются. Шрифты темы в изолированной рамке могут
  замениться системными — вид смотрите в обычном.

## Скрипт сайта

«Скрипт сайта» в панели — свой JavaScript на **каждой** странице сайта и **домены внешних
скриптов**. Только у владельца; нейронка — черновиком, по тому же праву, что черновики блоков.

- Код — как у скрипта блока, только без `blocks`. Сохраняется черновиком, на сайт попадает после
  «Опубликовать» (сайт пересобирается). Ошибка разбора не даёт опубликовать.
- **Домены внешних скриптов** — по одному на строку, `https://` и имя хоста без пути:
  `https://widget.example.ru`, `https://*.example.ru`. С них скрипту можно грузить код, стили,
  картинки, шрифты, фреймы и делать запросы — их разрешит CSP сайта. Метрику и GA4 добавлять не
  нужно: их домены CSP берёт из «SEO и аналитика». До 20 доменов.
- Справа — главная (черновик) с опубликованными своими блоками; «Выполнять скрипты» — та же
  изолированная рамка со скриптом сайта из формы и скриптами блоков главной.

Почему так — [Свой JS на сайте](/averra-cms/decisions/custom-js/).

## Черновик, публикация, история

- **«Сохранить»** — черновик определения. Сохранить можно и с ошибками в шаблоне, CSS, скрипте или примере:
  код пишут по частям. Число ошибок — на вкладках («Шаблон · 1»), строки с ошибками отмечены у
  номера знаком «!», с советом — «·». Кнопка «Строка N» в списке замечаний ставит курсор на
  строку.
- **«Опубликовать»** — только без ошибок. Блок появляется в каталоге редактора, сайт
  пересобирается: блок мог уже стоять на страницах.
- Публикуется ровно тот черновик, что открыт на экране. Если его тем временем поменяли — например,
  нейронка сохранила новый черновик через MCP, — публикация не пройдёт: экран покажет свежий
  черновик с предупреждением «Черновик изменили…». Прочитайте его и опубликуйте снова.
- Если новое определение не подходит к данным на опубликованных страницах (например, появилось
  обязательное поле), после публикации будет список таких страниц. На сайте блок у них не
  покажется, пока страницу не поправят и не опубликуют: публикация страницы с такими данными
  отвечает ошибкой у поля. Остальной сайт собирается как обычно.
- То же у своей шапки и подвала: если тексты, выбранные в «Шапка и подвал», не подходят под новые
  поля, после публикации будет предупреждение «Шапка сайта: поля своего вида не подходят (поле
  «…»)». На сайте тогда стандартная шапка, пока тексты не поправят и не опубликуют; «Шапка и
  подвал» показывает это над формой и у поля.
- **«История»** — опубликованные версии. «Вернуть в черновик» ставит версию черновиком, сайт не
  меняется до публикации.
- **«Удалить»** — только если блока нет ни на одной странице (в черновике или на сайте).

## Поля

| Вид | Что в шаблоне | Настройки |
|---|---|---|
| Текст | строка | не короче, не длиннее, по умолчанию |
| Многострочный текст | строка с переносами — фильтры `paragraphs`, `newline_to_br` | то же |
| Число | число | не меньше, не больше, только целое, по умолчанию |
| Переключатель | `true` / `false` | включено по умолчанию |
| Выбор из списка | значение варианта | варианты (значение и подпись), по умолчанию |
| Ссылка | `{ label, href }` — `href` по правилам встроенных: свои страницы, якоря, https, tel, mailto | — |
| Картинка | `{ mediaId, alt }` — фильтр `image`, alt обязателен | — |
| Повторитель | список пунктов — `{% for %}` | пунктов не меньше и не больше (до 50), поля пункта |
| Группа | объект — `{{ group.поле }}` | поля группы |

У каждого поля — подпись, ключ (имя переменной в шаблоне), подсказка для редактора и
«Обязательное». Пределы: 60 полей во всём блоке, 30 на уровне, три уровня (повторитель с группой
внутри — можно, глубже — нет).

## Что нельзя в шаблоне и CSS

Блок работает без JavaScript — как все блоки сайта; свой JS — только на вкладке «Скрипт». Поэтому в шаблоне нет `<script>`, `on…`-
обработчиков, ссылок `javascript:`, `<iframe>`, `<object>`, `<embed>` и `<form>` (заявки принимает
блок «Форма»), атрибутов `style` (стили — во вкладке CSS) и `form…`, чужих адресов картинок:
картинки только из медиатеки. В CSS нет `@import`, `@font-face` (шрифты — у темы) и чужих `url()`:
картинка в CSS — только из медиатеки, `url(media:<id картинки>)`. Селектор начинается с элемента
блока, `:scope` (вся секция блока) или `>` (верхние элементы шаблона, как и `:scope >`): `~` и `+` в
начале задели бы соседние блоки страницы. В шаблоне нет `data-`атрибутов, которыми сайт помечает
свою разметку (`data-cookie-consent`, `data-consent-…`, `data-video-…`, `data-header-…` и другие),
`id` сайта (`content`, `cookie-…`) и ссылок `popovertarget`, `for`, `aria-labelledby` на элементы
вне блока: блок не выдаст себя за уведомление о cookie и не перехватит чужие окна и подписи. Свой
`id` — с дефисом (`{{ block.id }}-menu`, `tariffs-menu`): имя без него (`menu`, `ym`) браузер сделал
бы переменной страницы, и скрипты сайта и счётчики сломались бы; по той же причине у картинки нет
`name`. Нет и `autofocus`, и `tabindex` больше 0: блок не уводит фокус и не встаёт в порядке Tab
раньше всей страницы. id соседнего блока страницы в своём блоке убирается при сборке — якорь меню
ведёт туда, куда должен. CSS проверяется по списку разрешённого — функции, псевдоклассы, `position`
без `fixed`; чего нет в списке — ошибка с понятным текстом. Конкретный цвет (`#fff`, `red`) — совет
взять роль темы: блок должен меняться вместе с темой. Подробно — [Разработчику → Свои
блоки](/averra-cms/dev/custom-blocks/).

## Шапка и подвал

Свой блок бывает и **видом шапки или подвала** на весь сайт. При создании выберите «Где блок»:
«Шапка сайта» или «Подвал сайта» (место после создания не меняется). Блок начнётся с рабочей
заготовки: логотип, меню строкой на широком экране и в «Меню» (`<details>`) на телефоне, кнопка;
у подвала — название, разделы, контакты и реквизиты. Предпросмотр рисует его на странице-образце
с меню, кнопкой и «Организацией».

- Поля такого блока — тексты, которые меняет администратор сайта (подпись, слоган, часы работы).
  Меню, кнопку, логотип, «Организацию» и ссылки на документы шаблон получает **данными**:
  `site.menu`, `site.button`, `site.logo`, `site.organization`, `site.legal`, `page.short` —
  полный список и пример — [Разработчику → Свои блоки](/averra-cms/dev/custom-blocks/#шапка-и-подвал).
- На страницу такой блок не ставится и в каталоге редактора его нет: опубликуйте его и выберите в
  [«Шапка и подвал»](/averra-cms/admin/header/#свой-вид-шапки) → «Вид шапки» («Вид подвала»).
- CSS: `:scope` — сама шапка; у липкой шапки со сборкой при прокрутке `:scope[data-condensed]` —
  собранная. Скрипт получает в `blocks` корень шапки. Меню телефона закрывается по Esc скриптом
  Averra — шаблон пишет его на `<details>`.
- Ссылки на политику, согласие и «Настройки cookie» Averra выводит под своим подвалом сама
  (кроме тех, что шаблон уже вывел).
- Удалить выбранный вид нельзя: сначала выберите другой в «Шапка и подвал» и опубликуйте.

## Перенос между установками

Так студия собирает свои пресеты: блок, сделанный для одного клиента, ставится на другой
установке.

- **«Выгрузить все»** — файл `custom-blocks-<дата>.json` с черновиками всех своих блоков.
- **«Загрузить из файла»** на другой установке. Файл проверяется схемой. Если ключ уже занят,
  на выбор: **переименовать** (свободное имя предложено), **заменить черновик** существующего
  (опубликованное не меняется; заменить можно только блоком того же места — шапку блоком
  страницы нельзя) или **пропустить**. Свои шапка и подвал переносятся так же. Загруженное —
  черновики: проверьте пример
  (картинки из чужой медиатеки нужно выбрать заново) и опубликуйте.
- Полная выгрузка сайта («Настройки сайта» → «Выгрузить все данные») тоже кладёт свои блоки — в
  `site.json`, поле `customBlocks` (скрипт блока — `scriptDraft` и `scriptPublished`), скрипт сайта —
  `site.script`.
