Для разработчика студии — владельца установки. После страницы вы соберёте свой блок, как в
WordPress с ACF Pro: поля для редактора, шаблон и стили, — и он появится в каталоге «Добавить
блок» рядом со встроенными. Без пересборки образа и без кода на сервере: блок живёт в базе этой
установки, обновление Averra его не трогает.

16 встроенных блоков и темы — пресеты: с ними сайт собирается за вечер. Свой блок — для того, что
делает сайт непохожим на другие: тарифы с наклейкой, карточка объекта, таблица сравнения.

## Кто что может

- **Владелец** создаёт, меняет, публикует, удаляет, выгружает и загружает свои блоки — раздел
  «Свои блоки» в панели.
- **Редактор и клиент** ставят опубликованные свои блоки на страницы и заполняют их, как
  встроенные. Сами определения им не видны.
- **Нейронка через MCP** видит опубликованные свои блоки в `list_blocks` и заполняет их на
  страницах. Менять определения токеном нельзя.

Почему так — [решение](/averra-cms/decisions/custom-blocks/).

## Пример: «Тарифы с наклейкой»

1. «Свои блоки» → **«Создать блок»**. Название — «Тарифы с наклейкой», ключ — `tariffs` (латиница,
   его предложат из названия). На странице блок будет с типом `custom:tariffs`; ключ после
   создания не меняется.
2. Вкладка **«Поля»**. Заготовка уже с «Заголовком» (`title`) и «Текстом» (`text`). Добавьте поле,
   смените вид на «Повторитель», подпись — «Тарифы», ключ — `plans`. Внутри повторителя —
   «Название» (`title`, обязательное), «Наклейка» (`sticker`), «Цена» (`price`), «Фото» (вид
   «Картинка», `photo`) и «Кнопка» (вид «Ссылка», `button`).
3. Вкладка **«Шаблон»** — HTML с Liquid:

   ```liquid
   <h2 class="title">{{ title }}</h2>
   {% if text %}<div class="intro">{{ text | paragraphs }}</div>{% endif %}
   <ul class="plans" role="list">
     {% for plan in plans %}
     <li class="plan">
       {% if plan.sticker %}<span class="sticker">{{ plan.sticker }}</span>{% endif %}
       {{ plan.photo | image: '(min-width: 64rem) 33vw, 100vw', 'photo' }}
       <h3>{{ plan.title }}</h3>
       <p class="price">{{ plan.price }}</p>
       {% if plan.button %}
       <a class="button" href="{{ plan.button | link }}">{{ plan.button.label }}</a>
       {% endif %}
     </li>
     {% endfor %}
   </ul>
   ```

4. Вкладка **«CSS»** — стили только этого блока, цвета — ролями темы:

   ```css
   .plans {
     display: grid;
     grid-template-columns: minmax(0, 1fr);
     gap: var(--space-4);
     padding: 0;
     list-style: none;
   }

   @media (min-width: 64rem) {
     .plans {
       grid-template-columns: repeat(3, minmax(0, 1fr));
     }
   }

   .plan {
     padding: var(--space-4);
     border: 1px solid var(--color-border);
     border-radius: var(--radius);
   }

   .sticker {
     display: inline-block;
     padding: var(--space-1) var(--space-2);
     color: var(--color-on-accent);
     background: var(--color-accent);
     border-radius: var(--radius);
   }

   .title {
     font-family: var(--font-heading);
     font-size: var(--text-2xl);
   }

   .intro {
     max-width: 40rem;
     color: var(--color-muted);
   }

   .price {
     font-size: var(--text-2xl);
     font-weight: 700;
   }

   .button {
     display: inline-block;
     padding: var(--space-2) var(--space-4);
     color: var(--color-on-accent);
     text-decoration: none;
     background: var(--color-accent);
     border-radius: var(--radius);
   }

   .button:hover {
     text-decoration: underline;
   }
   ```

   Ссылки и кнопки тема сама не оформляет: класс из шаблона (`button`) получает вид в CSS блока.
   Картинка из фильтра `image` по умолчанию не шире карточки и сохраняет пропорции; другой размер
   — правилом для `.photo img` в CSS блока.

5. Вкладка **«Пример»** — данные, с которыми блок встаёт на страницу: та же форма, что у
   редактора. Цен и фактов не выдумывайте — заглушки в квадратных скобках («от [цена] ₽»).
6. Справа — **живой предпросмотр** на настоящем рендере в теме сайта, на телефоне, планшете и
   десктопе.
7. **«Опубликовать»**. Теперь в редакторе страницы «Добавить блок» → раздел **«Свои»** →
   «Тарифы с наклейкой».

## Черновик, публикация, история

- **«Сохранить»** — черновик определения. Сохранить можно и с ошибками в шаблоне, CSS или примере:
  код пишут по частям. Число ошибок — на вкладках («Шаблон · 1»), строки с ошибками отмечены у
  номера знаком «!», с советом — «·». Кнопка «Строка N» в списке замечаний ставит курсор на
  строку.
- **«Опубликовать»** — только без ошибок. Блок появляется в каталоге редактора, сайт
  пересобирается: блок мог уже стоять на страницах.
- Если новое определение не подходит к данным на опубликованных страницах (например, появилось
  обязательное поле), после публикации будет список таких страниц. На сайте блок у них не
  покажется, пока страницу не поправят и не опубликуют: публикация страницы с такими данными
  отвечает ошибкой у поля. Остальной сайт собирается как обычно.
- **«История»** — опубликованные версии. «Вернуть в черновик» ставит версию черновиком, сайт не
  меняется до публикации.
- **«Удалить»** — только если блока нет ни на одной странице (в черновике или на сайте).

## Поля

| Вид | Что в шаблоне | Настройки |
|---|---|---|
| Текст | строка | не короче, не длиннее, по умолчанию |
| Многострочный текст | строка с переносами — фильтры `paragraphs`, `newline_to_br` | то же |
| Число | число | не меньше, не больше, только целое, по умолчанию |
| Переключатель | `true` / `false` | включено по умолчанию |
| Выбор из списка | значение варианта | варианты (значение и подпись), по умолчанию |
| Ссылка | `{ label, href }` — `href` по правилам встроенных: свои страницы, якоря, https, tel, mailto | — |
| Картинка | `{ mediaId, alt }` — фильтр `image`, alt обязателен | — |
| Повторитель | список пунктов — `{% for %}` | пунктов не меньше и не больше (до 50), поля пункта |
| Группа | объект — `{{ group.поле }}` | поля группы |

У каждого поля — подпись, ключ (имя переменной в шаблоне), подсказка для редактора и
«Обязательное». Пределы: 60 полей во всём блоке, 30 на уровне, три уровня (повторитель с группой
внутри — можно, глубже — нет).

## Что нельзя в шаблоне и CSS

Блок работает без JavaScript — как все блоки сайта. Поэтому в шаблоне нет `<script>`, `on…`-
обработчиков, ссылок `javascript:`, `<iframe>`, `<object>`, `<embed>` и `<form>` (заявки принимает
блок «Форма»), атрибутов `style` (стили — во вкладке CSS) и `form…`, чужих адресов картинок: картинки
только из медиатеки. В CSS нет `@import`, `@font-face` (шрифты — у темы) и чужих `url()`: картинка в CSS —
только из медиатеки, `url(media:<id картинки>)`. Селектор начинается с элемента блока, `:scope`
(вся секция блока) или `>` (верхние элементы шаблона, как и `:scope >`): `~` и `+` в начале
задели бы соседние блоки страницы. В шаблоне нет `data-`атрибутов, которыми сайт помечает свою
разметку (`data-cookie-consent`, `data-consent-…`, `data-video-…`, `data-header-…` и другие), `id`
сайта (`content`, `cookie-…`) и ссылок `popovertarget`, `for`, `aria-labelledby` на элементы вне
блока: блок не выдаст себя за уведомление о cookie и не перехватит чужие окна и подписи. Свой `id` —
с дефисом (`{{ block.id }}-menu`, `tariffs-menu`): имя без него (`menu`, `ym`) браузер сделал бы
переменной страницы, и скрипты сайта и счётчики сломались бы; по той же причине у картинки нет
`name`. Нет и `autofocus`, и `tabindex` больше 0: блок не уводит фокус и не встаёт в порядке Tab
раньше всей страницы. id
соседнего блока страницы в своём блоке убирается при сборке — якорь меню ведёт туда, куда должен. CSS проверяется по списку
разрешённого — функции, псевдоклассы, `position` без `fixed`; чего нет в списке — ошибка с
понятным текстом. Конкретный цвет (`#fff`, `red`) — совет взять роль
темы: блок должен меняться вместе с темой. Подробно — [Разработчику → Свои
блоки](/averra-cms/dev/custom-blocks/).

## Перенос между установками

Так студия собирает свои пресеты: блок, сделанный для одного клиента, ставится на другой
установке.

- **«Выгрузить все»** — файл `custom-blocks-<дата>.json` с черновиками всех своих блоков.
- **«Загрузить из файла»** на другой установке. Файл проверяется схемой. Если ключ уже занят,
  на выбор: **переименовать** (свободное имя предложено), **заменить черновик** существующего
  (опубликованное не меняется) или **пропустить**. Загруженное — черновики: проверьте пример
  (картинки из чужой медиатеки нужно выбрать заново) и опубликуйте.
- Полная выгрузка сайта («Настройки сайта» → «Выгрузить все данные») тоже кладёт свои блоки — в
  `site.json`, поле `customBlocks`.
