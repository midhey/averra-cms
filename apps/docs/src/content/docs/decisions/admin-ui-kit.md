Для разработчика админки: почему стили устроены через `@averra/ui` и строгую границу токенов.

## Решение

Стили админки — на foundation из frontend-kit владельца (`packages/ui`, чистый Sass) и теме Averra.
Токены в слоях primitives → semantic, компоненты берут только семантические роли, CSS-модули
`.module.scss`. Компоненты свои, в `apps/admin/src/ui`. Шрифты — со своего сервера.

## Почему

- **Тема меняет роли, а не компоненты.** Тёмная тема — ещё один набор значений ролей, без правок
  компонентов.
- **Граница токенов проверяется тестом:** сырой цвет или примитив в компоненте — ошибка
  `pnpm check`. Контраст темы тоже под тестом.
- **Доступность — в основе:** видимый фокус, `reduced-motion`, принудительные цвета, настоящие
  `button` и `label`.
- **Предпросмотр честный:** глобальные стили админки не попадают в iframe, лендинг выглядит как на
  сайте.
- **Без внешних запросов:** шрифты из `@fontsource`, Google Fonts нет.

## Чем платим

Компоненты пишем сами, а изменения кита переносим руками сравнением папок (как — в README пакета
`packages/ui`). Стиль, который не укладывается в роли, требует новой роли в токенах и теме.
