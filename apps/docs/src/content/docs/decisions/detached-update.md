Для студии и разработчика: почему обрыв связи посреди обновления не бросает установку на полпути.

## Решение

`averra.sh update` не обновляет сам: он запускает процесс, отвязанный от терминала и SSH (служба
systemd `averra-update-<время>`, без systemd — `setsid`), и только показывает его лог. Ход
обновления записывается отметкой по шагам. Повтор команды сначала **доводит прерванное** —
заканчивает обновление или откатывает, — а не решает по одной строке `.env`.

## Почему

- Обрыв SSH, закрытый терминал или Ctrl+C в `pnpm fleet update` иначе убили бы обновление между
  остановкой API и запуском новой версии — установка осталась бы лежать.
- Перезагрузка сервера посреди обновления тоже не должна оставлять установку в непонятном
  состоянии: по отметке видно, на каком шаге оборвалось, и что делать дальше.
- Студия обновляет много установок по очереди — нужен способ, который не требует сидеть у каждого
  сервера.

## Чем платим

Сложнее скрипт: отметки шагов, лог с ротацией, коды выхода, отдельная проблема «похоже, оборвалось»
в «Состоянии». Пока обновление не доведено, его бэкап и отложенная база не удаляются по сроку.
