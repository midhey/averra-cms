Для разработчика и студии: почему API без своего `AUTH_SECRET` не стартует на сервере, даже если
забыть переменные.

## Решение

Учебный режим — учебный секрет cookie из репозитория, демо-сайт, владелец из `DEV_OWNER_*`,
файловый ящик, учебный ключ почты — включается только когда выполнено **всё**:

- флаг `--dev` в командной строке API (его ставят только `pnpm dev` и e2e);
- `NODE_ENV` не `production`;
- `ADMIN_URL` и `API_URL` указывают на этот компьютер.

В любом другом случае, в том числе вовсе без переменных, API без своего `AUTH_SECRET` не стартует и
объясняет почему. Учебный секрет, вписанный руками, и его варианты (пробелы, кавычки, регистр, часть
строки) вне учебного режима не проходят. Добавочно на учебном секрете API отвечает только запросам к
localhost с этого компьютера.

## Почему

Раньше достаточно было забыть `NODE_ENV=production` на сервере: API молча стартовал с публичным
секретом, ставил cookie без `Secure` и заводил владельца с учебным паролем. Всё, что Better Auth
подписывает секретом, с публичным секретом ничего не стоит. Ждать, пока это станет дырой, не стали.

- **Флаг, а не переменная.** Переменную для `pnpm dev` кроссплатформенно не выставить без лишней
  зависимости, а случайно дописать `--dev` к команде запуска на сервере, в отличие от «забыть
  переменную», трудно.
- **Адреса — второй замок:** на сервере их задают всегда, иначе админка с настоящего домена не
  войдёт.
- **Проверка localhost — не главный замок:** прокси, который шлёт свой `Host` (nginx по умолчанию),
  её обходит. Поэтому главное — явный флаг.

## Чем платим

Разработчику нужен `pnpm dev` (или флаг `--dev`) — `start` без своих переменных не запустится.
`pnpm dev` на сервере запускать нельзя. Команды терминала работают на свежем клоне и без
`AUTH_SECRET`: сеть они не слушают, а демо-данных не заводят.
