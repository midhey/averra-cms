Для студии и разработчика: откуда на сервере клиента берутся образы и почему.

## Решение

Образы `averra-api` и `averra-web` собирает GitHub Actions для каждой версии после `pnpm check`,
под amd64 и arm64, и кладёт в GHCR. На VPS установщик и `averra.sh` скачивают их по
`AVERRA_VERSION`.

## Почему

| | GHCR (выбрано) | Сборка на месте |
|---|---|---|
| Память VPS | не нужна | `pnpm install` и сборка Vite на 1 ГБ легко падают |
| Время установки | минуты | десятки минут на слабом процессоре |
| Одинаковость | у всех клиентов один образ версии | у каждого сервера своя сборка |
| Откат | сменить версию | пересобрать прежний коммит |
| Доступ с VPS | без входа: пакеты публичные | исходный код на сервере |

## Чем платим

- Зависимость от GHCR (GitHub).
- Публичность пакета — ручной шаг: видимость от репозитория не наследуется, первый релиз создаёт
  закрытый пакет, и владелец один раз переключает его в Public
  ([Релизы](/averra-cms/dev/releases/)). Это необратимо: публичный пакет закрытым уже не сделать.
  Пока пакеты не переключены — серверам нужен токен с `read:packages` и флаг `--ghcr-user`.

Запасной путь — собрать образы у себя и передать на сервер (`docker save | ssh … docker load`) или
указать свой реестр флагами `--api-image` и `--web-image`.
