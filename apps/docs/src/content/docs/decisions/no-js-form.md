Для разработчика: как работает форма заявки на статическом сайте и почему без скриптов.

## Решение

- Форма — обычная `<form method="post">`. На сервере её `action` — `/api/forms/<сайт>/<страница>/<блок>`
  на свой же домен: Caddy передаёт этот путь в API.
- API проверяет заявку по **опубликованной** версии блока, сохраняет её и письма одной транзакцией и
  отвечает 303 на страницу с якорем `#<id блока>-sent`. CSS (`:target`) показывает текст успеха и
  прячет форму.
- Страница возврата — источник из `Origin` (иначе `Referer`) и путь страницы из адреса приёма.
  Других адресов API не знает и на них не перенаправляет.
- Ошибки — понятная HTML-страница от API с советом нажать «Назад». JSON — только если клиент
  попросил явно.
- Одна таблица правил полей даёт и HTML-атрибуты проверки в браузере, и проверку на сервере.

## Почему

- **Сайт остаётся статикой без JS** (принцип 5): быстрый, без лишнего кода и без поверхности атаки.
- **Свой домен — без CORS**, и сайт не зависит от адреса API. Браузер шлёт `Origin` с каждой POST-
  формой, поэтому посетитель возвращается на ту же страницу того же домена.
- **Путь — из маршрута, а не из `Referer`:** в чужой источник браузер по умолчанию шлёт `Referer`
  без пути.
- **Открытого редиректа нет:** вернуть можно только на источник, который сам прислал форму.
- **Браузер и сервер принимают одно и то же:** тест прогоняет образцы через обе стороны.

## Чем платим

- Отправка — с перезагрузкой страницы, без «живой» проверки полей сверх того, что умеет браузер.
- Обязательное многострочное поле из одних пробелов браузер пропустит, а сервер ответит страницей
  ошибки.
- Цель в Метрике на отправку без скрипта не поставить — варианты решаются вместе с аналитикой.
- Минимальное время заполнения честно не сделать — см. [Антиспам без капчи](/averra-cms/decisions/antispam/).
