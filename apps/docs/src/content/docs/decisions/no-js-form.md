Для разработчика: как работает форма заявки на статическом сайте и почему без скриптов.

## Решение

- Форма — обычная `<form method="post">`. На сервере её `action` — `/api/forms/<сайт>/<страница>/<блок>`
  на свой же домен: Caddy передаёт этот путь в API.
- API проверяет заявку по **опубликованной** версии блока, сохраняет её и письма одной транзакцией и
  отвечает 303 на страницу с параметром и якорем `?sent=<id блока>#<id блока>-sent`. CSS
  (`:target`) показывает текст успеха и прячет форму, а параметр — адрес «спасибо» для цели
  аналитики.
- Страница возврата — источник из `Origin` (иначе `Referer`) и путь страницы из адреса приёма.
  Других адресов API не знает и на них не перенаправляет.
- Ошибки — понятная HTML-страница от API с советом нажать «Назад». JSON — только если клиент
  попросил явно.
- Одна таблица правил полей даёт и HTML-атрибуты проверки в браузере, и проверку на сервере.
- Источник заявки — прогрессивное улучшение: внешний модуль сайта добавляет служебные поля
  `_av_utm_source`, `_av_utm_medium`, `_av_utm_campaign`, `_av_utm_content`, `_av_utm_term`,
  `_av_page_url`, `_av_referrer` к обычной POST-форме (блок, подвал, окно). На каждой странице
  метки из URL сохраняются в `sessionStorage` вкладки; новый набор заменяет прежнюю кампанию.
  Скрипт собирается Astro в файл `/_astro/…`, разрешённый CSP `script-src 'self'`.
  Он подключается на всех страницах только сайтов с формами: видимым блоком «Форма» на любой
  опубликованной странице (включая страницу-окно) или формой большого подвала. Наличие форм
  вычисляется в снимке один раз на сборку; скрытые блоки не учитываются. Поэтому метки
  сохраняются и при входе на страницу без формы, а сайт без форм не получает этот JavaScript.
  При отправке API проверяет метки Zod-схемой, обрезает их до 200 символов, отбрасывает
  многострочные значения, сохраняет страницу без запроса и фрагмента, Referer — только домен.
  Без JS API берёт метки из заголовка Referer того же источника, что Origin формы
  (без Origin — источника запроса API). Скрытый браузером запрос восстановить нельзя.

## Почему

- **Сайт остаётся статикой без JS** (принцип 5): быстрый, без лишнего кода и без поверхности атаки.
- **Свой домен — без CORS**, и сайт не зависит от адреса API. Браузер шлёт `Origin` с каждой POST-
  формой, поэтому посетитель возвращается на ту же страницу того же домена.
- **Путь — из маршрута, а не из `Referer`:** в чужой источник браузер по умолчанию шлёт `Referer`
  без пути.
- **Открытого редиректа нет:** вернуть можно только на источник, который сам прислал форму.
- **Браузер и сервер принимают одно и то же:** тест прогоняет образцы через обе стороны.

## Чем платим

- Отправка — с перезагрузкой страницы, без «живой» проверки полей сверх того, что умеет браузер.
- Обязательное многострочное поле из одних пробелов браузер пропустит, а сервер ответит страницей
  ошибки.
- Цель «заявка» в Метрике — «посещение страницы» по адресу с `sent=`, а не событие формы: так
  без своего скрипта ([SEO](/averra-cms/admin/seo/#цель-заявка-с-формы)).
- Минимальное время заполнения честно не сделать — см. [Антиспам без капчи](/averra-cms/decisions/antispam/).
