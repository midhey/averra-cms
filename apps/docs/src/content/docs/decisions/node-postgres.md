Для разработчика: почему две базы и как держится, что код работает на обеих.

## Решение

В разработке и тестах — PGlite: настоящий Postgres, собранный в WASM, в папке или в памяти. На
сервере — PostgreSQL в Docker по `DATABASE_URL` через драйвер node-postgres, пул 5 соединений.
Миграции одни на обе.

## Почему

- **Разработке не нужен Docker:** `pnpm install && pnpm dev` — и всё работает.
- **Тесты быстрые и изолированные:** у каждого теста своя база в памяти.
- **node-postgres, а не postgres.js:** сырые запросы читают результат как `{ rows }`, а так отдают
  и PGlite, и node-postgres. postgres.js отдаёт массив — тип базы в коде разошёлся бы.
- **На VPS 1–2 ГБ** маленький пул и небольшие буферы Postgres экономят память.

## Чем платим

- Драйверы всё-таки расходятся (типы, транзакции, пул), поэтому отдельный тест гоняет API на
  настоящем node-postgres через сервер протокола Postgres поверх PGlite.
- PGlite — один процесс: пока запущен `pnpm dev`, команды терминала не открывают базу (файл-замок).
- PGlite не выполняет запрос мимо открытой транзакции — внутри `db.transaction` все запросы только
  через `tx`.
