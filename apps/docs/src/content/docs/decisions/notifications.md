Для разработчика и студии: как устроены уведомления и почему так.

## Решение

- Уведомления — **модуль с каналами**: событие → получатели → каналы через один интерфейс
  `NotificationChannel`: отправка, проверка подключения, описание себя без секретов, имя
  получателя. Новый канал — адаптер и схема его настроек, без правок ядра: маршрутизация, очередь,
  «Проверить», вид в админке и письмо о смене получателей берут всё из адаптера.
- **Почта остаётся на `mail_outbox`**, остальные каналы — на своей очереди `notification_outbox`
  с теми же правилами: запись в транзакции действия, аренда, повторы с растущей паузой, данные —
  только до отправки или окончательной неудачи.
- **Telegram привязывает чат одноразовым кодом и опросом `getUpdates`**, пока код жив, а не
  webhook.
- **Служебные события — по переходу состояния**, запомненного в базе (`notification_watch`).
- Получателей заявок меняют владелец и клиент (`leads.settings`), каналы и служебные события —
  только владелец.

## Почему

- **Почта на своей очереди.** У `mail_outbox` почтовые правила: ключ ящика для лимита
  подтверждений, срок одноразовой ссылки, «Повторить», выжидание при отказе адресу отправителя.
  Обобщить её — переименовать и сменить смысл колонок живой таблицы, а миграции только совместимые
  вперёд. Очередь «уведомление → письмо» — два хопа и две копии персональных данных.
- **Транзакция с действием.** Не легло уведомление — нет и заявки, посетитель видит ошибку. Сбой
  Telegram — только повтор в очереди: приём заявок он не трогает.
- **Опрос вместо webhook.** Не нужен входящий маршрут в Caddy, публичный адрес и секрет
  `secret_token`; работает через тот же исходящий прокси, что и отправка (с российских VPS
  Telegram часто доступен только так); опрос идёт минуты, пока человек жмёт «Старт».
- **Код, а не chat id руками.** Chat id никто не знает, а ошибка в нём отправит заявки чужому.
  Код одноразовый, живёт 15 минут, в базе — его хеш, и аудитория записана в нём самом: код
  клиента не откроет служебные.
- **Переходы, а не круги.** Бэкап, который не прошёл ночью, — одно сообщение, а не двенадцать
  в час. Состояние в базе: обновление API не повторяет старые проблемы.
- **Смена получателей видна.** Привязали чат или сменили адрес — письмо владельцам и прежним
  получателям, как с адресами до модуля: заявки нельзя перенаправить молча.

## Чем платим

- Одна установка — один бот: два процесса, опрашивающие одного бота, мешают друг другу (409).
- Пока очередь Telegram выжидает после сбоя сети, сообщения приходят с опозданием до 30 минут.
  Если Telegram недоступен долго (типично для российского VPS без прокси), сообщения копятся:
  попытки они не тратят, «Каналы» и раздел «Заявки» предупреждают, что сообщения ждут дольше
  15 минут, а через `MAIL_RETENTION_DAYS` неотправленные удаляются. Запасной отправки письмом
  при «готовом, но недоступном» Telegram нет: заявки при этом лежат в разделе «Заявки».
- SOCKS5 идёт через `Socks5ProxyAgent` undici, а он помечен экспериментальным: интерфейс может
  смениться в минорной версии. Поэтому undici закреплён точной версией, а тесты с настоящим
  SOCKS5-рукопожатием (логин и пароль, кириллица, спецсимволы) обязаны проходить при каждом его
  обновлении. Убрать SOCKS нельзя — это основной путь для российских VPS, а через `ProxyAgent`
  SOCKS-прокси с закодированными логином и паролем не работает; свой SOCKS-клиент — больше кода
  ради одного конструктора. В журнале API при первом SOCKS — `ExperimentalWarning`, это ожидаемо.
- Спецсимволы в логине и пароле прокси — только %-кодами: «сырые» `#`, `?`, `@` — разделители
  URL, и угадывать, где кончается пароль, Averra не берётся. Адрес без кодов не примется с понятной
  ошибкой у поля.
- Колонка `sites.lead_recipients` устарела, но остаётся: модуль пишет в неё адреса почты, пока
  прежняя версия API может читать её при откате. Сама Averra её больше не читает (выгрузка сайта
  берёт получателей из `notification_recipients`). Удалить — вторым шагом.
- Уведомление о заявке в Telegram — передача персональных данных иностранному сервису: решает
  клиент как оператор ([Персональные данные](/averra-cms/install/personal-data/)).
