Для студии и разработчика: почему в админке нет выбора сайта, откуда берётся сайт установки и что
стало с несколькими сайтами в одной базе.

## Решение

Averra ставится как WordPress: **одна установка на сервере — один сайт**. Заходишь на домен
админки — и сразу работаешь с этим сайтом: без списка сайтов, переключателя и id сайта в адресах
(`/`, `/pages`, `/pages/<адрес>`, `/media`, `/leads`, `/settings`).

- **Сайт появляется сам.** При первом запуске API на пустой базе создаёт сайт с главной страницей:
  название — `SITE_NAME` (установщик пишет его из `--site-name`), иначе домен из `SITE_URL`, иначе
  «Мой сайт». В учебном режиме (`--dev`) сайт установки — демо-сайт. Создания и удаления сайтов
  нет ни в админке, ни в API (`POST /api/sites` убран, команда `site:create` — тоже).
- **Сайт установки — правилом, без признака в базе:** это сайт, созданный первым (`created_at`, при
  равном времени — меньший `id`, `sitesRepo.installationSite`).
- **Модель данных не меняется.** `site_id` остаётся в каждой таблице, маршруты
  `/api/sites/:siteId/…` и токены на сайт — тоже ([`site_id` с первого
  дня](/averra-cms/decisions/site-id/)). Админка, рендерер и MCP узнают id из `GET /api/site` и
  ходят по ним как раньше.
- **Без лишних настроек.** Caddy отдаёт на домене сайта `/srv/sites/main/current`: ссылку `main` на
  папку сайта установки API ставит при старте, поэтому `SITE_ID` в `.env` не нужен, а
  восстановление из бэкапа `.env` не трогает. Рендереру не нужен `CMS_SITE_ID`, MCP-инструментам —
  `siteId`, командам `member:*` и `token:create` — `--site`.
- **Участники** — пользователи установки: редактор и клиент установки работают с её сайтом. Роли и
  права — прежние ([Роли и разделы](/averra-cms/admin/)).

## Почему

- **Так работает студия.** У каждого клиента своя установка на его VPS
  ([Своя установка у каждого клиента](/averra-cms/decisions/own-install/)). Выбор сайта в такой
  админке — лишний шаг на каждом входе и лишний вопрос «а какой сайт мой?».
- **Домен один.** Caddy и так отдаёт на домене установки один сайт. Список сайтов в админке обещал
  то, чего установка не умела: второй сайт без своего домена никто бы не увидел.
- **Правило вместо флага «основной».** Флаг пришлось бы держать единственным, переносить при
  удалении сайта и заводить миграцией — ради случая, который бывает только в старых базах
  разработки. Правило «созданный первым» детерминировано, ничего не хранит и в старой дев-базе
  выбирает демо-сайт. Будущий мультисайт выберет сайт по домену запроса, а не по флагу: понадобится
  свой признак — он добавит его миграцией вперёд.
- **Мультисайт — отдельный модуль.** Несколько сайтов в одной установке требуют домена у сайта,
  выбора сайта по `Host`, своих настроек Caddy и экрана сайтов. Это осознанная работа, а не режим по
  умолчанию. `site_id` в данных оставляет её дешёвой.

## Несколько сайтов в старой базе

До этого решения в базе разработки можно было завести несколько сайтов. Они не удаляются:

- админка, рендерер и команды работают с сайтом, созданным первым;
- остальные сохранены и доступны по id через API владельцу и токенам своих сайтов;
- API пишет при старте строку «В базе N сайтов…», обзор показывает владельцу заметку «В базе есть и
  другие сайты»;
- участник, у которого доступ только к другому сайту, видит «Нет доступа к сайту этой установки» и
  может выйти.

## Чем платим

- Второму сайту клиента — вторая установка (свой VPS или своя папка установки), пока нет модуля
  мультисайта.
- Сменить сайт установки на другой из той же базы можно, только удалив старшие сайты руками.
- Название сайта задаётся один раз при первом запуске: `SITE_NAME` потом его не меняет, экран
  настроек сайта появится в модуле «SEO и настройки сайта» ([дорожная
  карта](/averra-cms/roadmap/)).
