Для разработчика: почему в модели данных с самого начала несколько сайтов, хотя в установке сайт
один.

## Решение

`site_id` есть в каждой таблице с контентом — страницы, история, медиа, заявки, письма, сборки —
с первого дня, хотя в установке ровно один сайт ([Одна установка — один
сайт](/averra-cms/decisions/single-site/)). API тоже адресует сайт по id (`/api/sites/:siteId/…`),
токены выпускаются на сайт. Это задел под будущий модуль мультисайта.

## Почему

- Прикручивать несколько сайтов к модели, где их не было, очень больно: переписываются все запросы и
  права. С `site_id` модуль мультисайта — это выбор сайта по домену и экран сайтов, а не
  переписанная база.
- Права проверяются по сайту: чужой сайт для участника неотличим от несуществующего.
- Запросы фильтруют по сайту без лишних соединений, а удаление сайта каскадом чистит всё его.

## Чем платим

Лишняя колонка и индекс в каждой таблице, а id сайта — в каждом запросе API, хотя сайт один.
Админка и MCP узнают его из `GET /api/site`, людям он не виден.
