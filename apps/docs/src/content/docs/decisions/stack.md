Для разработчика: почему выбран такой стек и чего в нём сознательно нет.

## Решение

TypeScript везде. API — Hono, база — PostgreSQL через Drizzle, схемы — Zod, админка — React и Vite,
сборка сайтов — Astro, картинки — sharp, вход — Better Auth, MCP — официальный TypeScript SDK, линт —
Biome, тесты — Vitest и Playwright. Сами пишем только то, что и есть CMS.

## Почему

- **Не PHP.** Node в стеке нужна в любом случае: блоки на React, сборка на Astro. А схемы пришлось бы
  дублировать на двух языках.
- **Одна схема на всё.** Zod-схема блока проверяет данные в API, даёт типы, строит поля админки и
  JSON Schema для MCP.
- **Hono** лёгкий и даёт админке типизированный клиент API из коробки.
- **Не NestJS:** его валидация построена на DTO-классах — второй источник схем рядом с Zod, плюс
  много обвязки для проекта одного человека.
- **Криптографию сами не пишем:** хеширование паролей, сессии и лимит входа — Better Auth.

## Чем платим

Зависим от темпа чужих библиотек: TypeScript 7 пока не поддерживает `astro check`, у Better Auth
приходится закрывать и оборачивать эндпоинты, которые нам не подходят. Новые библиотеки берём
только после чтения их актуальной документации и не моложе суток.
