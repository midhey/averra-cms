Для разработчика и студии: почему на выходе статика, где и как она собирается.

## Решение

Сайт — HTML и CSS, JavaScript только там, где без него никак. «Опубликовать» собирает статику
Astro прямо на VPS клиента: отдельным процессом, по одной сборке на установку, в новую папку версии.
Потом ссылка `current` атомарно переключается на неё, и Caddy отдаёт новую версию со следующего
запроса. В версию попадают только файлы, на которые ссылается страница.

## Почему

- **Быстро и дёшево.** Статику отдаёт Caddy, API в отдаче сайта не участвует.
- **Почти нечего взламывать.** На домене сайта из API открыт только приём заявок.
- **Без простоя.** Посетитель видит либо старую версию целиком, либо новую. Упала сборка — на
  сайте прежняя.
- **Сайт самостоятелен.** Папка версии — полная статика с картинками: её можно выгрузить архивом
  и отдать любым веб-сервером (клиент не заложник).
- **Отдельный процесс** — память уходит вместе с ним, зависшую сборку убивает таймаут, а сбой не
  роняет API. Секретов API у сборщика нет.

## Чем платим

- Сборка — самое тяжёлое на VPS (около 300–350 МБ на демо-сайте), поэтому сборки идут строго по
  одной и с пределом памяти.
- Правка видна не мгновенно, а после сборки — обычно десятки секунд.
- Пять версий сайта на диске; одинаковые картинки между версиями — жёсткими ссылками, а не копиями.
- Что-то динамическое на сайте (личный кабинет, поиск) так не сделать — и мы это сознательно не
  делаем.
