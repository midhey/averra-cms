Для разработчика и студии: почему SVG и видео устроены так. Как пользоваться —
[Медиатека → SVG](/averra-cms/admin/media/#svg) и
[Редактор → Видео](/averra-cms/admin/editor/#видео), как устроено —
[Безопасность](/averra-cms/dev/security/) и [Свой блок → Видео](/averra-cms/dev/blocks/#видео).

## Решение

**SVG**

- **Признак, а не отдельная медиатека.** SVG — строка `media` с типом `image/svg+xml` и одним
  очищенным файлом `image.svg`: он и «оригинал», и единственный вариант. Выдача, удаление, проверка
  «используется», выгрузка сайта и копирование в релиз работают как с картинками.
- **Только логотип и иконка.** Логотип организации, иконка сайта (растеризуется в тот же набор
  PNG и ICO) и будущая шапка. Не в блоки, не в SEO-картинку страницы, не в картинку для соцсетей —
  это проверяет API, а админка в таких полях SVG не показывает.
- **Очистка своим allowlist поверх строгого XML-парсера `saxes`.** Файл собирается заново: только
  элементы и атрибуты из списка, значения экранированы. DOCTYPE с сущностями — отказ.
- **Вторая линия — заголовки:** `image/svg+xml`, `nosniff` и CSP `default-src 'none'; …; sandbox`
  в API и в Caddy.
- **До 256 КБ** на файл, вложенный растр — до 16 Мп вместе.

**Видео**

- **YouTube, Rutube, VK Видео** по строго разобранной ссылке; на сайт идут адреса, построенные из
  id, а не из того, что вставили.
- **До клика — только обложка и ссылка.** Обложка — своя из медиатеки или заглушка в цветах темы.
  Обложку площадки не берём ни при открытии страницы, ни при публикации.
- **Плеер по клику** — маленький скрипт ставит iframe с `sandbox` и `allow` по минимуму; YouTube —
  с `youtube-nocookie.com`. Без JavaScript ссылка открывает ролик на площадке.

## Почему

- **SVG — частый формат логотипов**, и растровый логотип в шапке размыт на ретине. Но SVG — это
  документ: в нём бывают скрипты, обработчики и ссылки наружу. Открытый по прямому адресу с домена
  сайта, такой файл исполнил бы скрипт от имени сайта. Поэтому — только очищенный и только там, где
  без него хуже.
- **Почему не библиотека очистки.** DOMPurify в Node требует jsdom — тяжёлый DOM с большой
  поверхностью. sanitize-html разбирает HTML, а SVG отдаётся как XML: два разных разбора одного
  файла — путь к обходу очистки. svgo — оптимизатор, его авторы прямо пишут, что это не средство
  безопасности. Свой allowlist на строгом XML-парсере — несколько сотен строк, в основном
  списки; его проверяет набор вредоносных образцов, а всё неизвестное выбрасывается по умолчанию.
- **Почему не в блоки.** Картинки блоков выводятся с вариантами и `srcset`, а SVG-иллюстрации часто
  несут внутри фотографию — тяжёлую и без вариантов. Соцсети SVG не показывают вовсе.
- **Почему без обложки площадки.** Картинка с `i.ytimg.com` или `vk.com` при открытии страницы —
  запрос к площадке до того, как посетитель что-то нажал: она узнаёт об IP и визите. Скачать
  обложку при публикации честно не выходит: у VK превью — только через API с токеном, у Rutube —
  через их API, а YouTube с российских VPS замедлен, и сборка сайта зависела бы от чужих серверов.
- **Почему ссылка, а не iframe сразу.** iframe площадки грузит её скрипты и ставит cookie на
  каждом открытии страницы — и тормозит её. По клику человек сам выбрал смотреть ролик.
- **Почему `padding-top`, а не `aspect-ratio`.** `aspect-ratio` нет в Safari до iOS 15, а место
  под ролик должно быть заранее у всех.

## Чем платим

- Свой код очистки нужно поддерживать: новое полезное свойство SVG придётся добавить в список
  руками, а редкий экспорт (DOCTYPE с сущностями, не UTF-8) получит отказ.
- Без своей обложки блок видео выглядит заглушкой — её стоит загрузить.
- Плеер — два клика на iOS, где браузер не даёт автозапуск со звуком, и иногда у Rutube: его
  `autoplay=true` площадка не обещает. У VK без `hash` в ссылке часть роликов во встроенном плеере
  не играет — тогда нужен адрес из кода вставки. Лицензионные ролики VK (сериалы, передачи)
  встраиваются только на сайты партнёров площадки.
- Площадка бывает недоступна из сети посетителя (YouTube в России) — тогда на месте ролика пустой
  плеер. Под ним скрипт показывает ссылку на ролик на площадке, чтобы посетитель не упёрся в
  тупик.
- Проверено вживую (22.10.2026, Chromium, сеть в России): плееры Rutube и VK Видео (без `hash`)
  работают в нашем `sandbox`, по клику сразу пошло воспроизведение (у обеих площадок — с
  рекламы), ошибок песочницы в консоли нет. YouTube из этой сети не грузится вовсе — его и VK с
  `hash` проверяют перед релизом из обычной сети ([чек-лист](/averra-cms/install/checklist/)).
- Права iframe — `allow-scripts` и `allow-same-origin`: без них плееры площадок не работают. Плеер
  при этом остаётся на своём домене и к странице сайта доступа не имеет.
