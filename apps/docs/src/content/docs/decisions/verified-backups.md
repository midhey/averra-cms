Для студии и разработчика: почему бэкапу Averra можно верить и почему восстановление не теряет
данные.

## Решение

- Бэкап — `averra.sh` на хосте: дамп базы и архив медиатеки. Удачен **только после проверки**: дамп
  восстанавливается во временную базу, число миграций и таблиц сверяется, архив читается целиком.
- Срок хранения — `BACKUP_KEEP` последних и не старше `BACKUP_KEEP` дней, локально и во внешнем
  хранилище. Внешняя копия зашифрована.
- Восстановление — **через новую базу и переименование**. Прежняя рабочая база не удаляется, пока
  восстановленная не поднялась; медиатека подменяется, пока API стоит.
- Собранные сайты не бэкапятся: API собирает их заново.

## Почему

- **Бэкап, который не восстанавливается, хуже отсутствия бэкапа:** о нём узнают в худший момент.
  Базы лендингов — мегабайты, поэтому проверяется каждый, а не выборочно.
- **Хост, а не API:** только снаружи контейнеров можно снять дамп и потом остановить API, подменить
  базу и поднять прежний образ. И бэкап идёт, даже когда API лежит.
- **Данные молча не теряются:** дамп, который не встал, рабочую базу не трогает; откат обновления
  откладывает рабочую базу под служебным именем, а не удаляет.
- **Конечный срок** — требование 152-ФЗ: удалённая заявка уходит и из бэкапов.

## Чем платим

- Бэкап дольше простого дампа, а на сервере на время проверки нужна вторая копия базы.
- Служебные базы с данными лежат до срока бэкапов и видны в «Состоянии» — их надо замечать.
- `.env` в бэкап не входит: его студия хранит отдельно, иначе зашифрованную копию не открыть.
