Для студии и разработчика. После раздела вы будете знать, почему форма в окне — это обычная страница,
что видит посетитель без JavaScript и почему появление при прокрутке не прячет контент.

## Решение

**Окно — это страница с настройкой «Окно».** Её блоки (форма заявки, свои блоки, текст) сборка кладёт
закрытым `<dialog>` в те страницы, где на неё ведёт кнопка или ссылка с «Открывать в окне». Скрипт
поведений Averra открывает окно по клику; без него — та же ссылка ведёт на страницу-окно обычным
переходом. Внешний вид окна — роли темы (ширина, фон), свой CSS окон — у владельца в теме.

**Поведения — атрибуты `data-av-*`**: появление при прокрутке, плавный `<details>`, подсказка-поворот,
рисование линии и ссылка в окно. Один маленький модуль без зависимостей подключается файлом, только
на страницах, где они есть. CSP сайта не меняется: ни строчки inline.

## Почему окно — страница

- **Без JS работает само.** Адрес ссылки — настоящая страница с той же формой: без JavaScript,
  Ctrl-кликом, «открыть в новой вкладке» и из поиска человек попадает туда же. Отдельная сущность
  «окно» потребовала бы своего адреса без JS — то есть той же страницы.
- **Одна форма.** Заявка из окна принимается как заявка со страницы-окна: те же поля, проверки по
  каналу связи, получатели уведомлений и политика.
- **Всё уже есть.** Редактор, история, публикация, свои блоки, SEO страницы — без нового экрана и без
  миграции: настройки окна — поле `window` в содержимом страницы, рядом со «скрыть шапку».

Отказались: окно по id блока формы на этой же странице (`data-av-dialog="form:…"`) — без JS ссылке
некуда вести, а форма на главной дублировала бы форму на странице записи; загрузка страницы-окна
`fetch` по клику — пауза перед окном и чужие стили и скрипты своих блоков, которых на этой странице
нет.

## Отправка из окна

Форма в окне уходит `fetch` на тот же адрес приёма с `Accept: application/json`: API уже отвечал
JSON. Успех — текст успеха формы в окне, ошибка — сообщение API в `role="alert"` над кнопкой и
текст у каждого поля с ошибкой (поле в фокусе, и на телефоне сообщение рядом с ним в экране); окно
не закрывается. Цели Метрики «URL содержит sent=» адрес не даёт, поэтому скрипт зовёт `reachGoal('lead')`
у загруженного счётчика. На сервере форма — свой источник; в dev формы ведут на API с другого порта,
поэтому `connect-src` получает адрес API так же, как `form-action`, а JSON-ответ формы читается с
любого источника (в нём нет ничего, кроме «принято» и ошибок полей).

## Доступность

`<dialog>` с `showModal()`: фон недоступен, Esc и «Закрыть» (44 px) закрывают всегда, клик мимо — по
настройке, после закрытия фокус возвращается на кнопку, прокрутка страницы заблокирована. Фокус при
открытии: на широком экране — на первое поле, если оно на виду в окне; на телефоне — на заголовок
окна (без него — на «Закрыть»): клавиатура не поднимается сразу и не уводит из виду заголовок и
описание формы. Если окно длинное и первое поле или ссылка стоят ниже видимой части, фокус тоже на
заголовке, а окно открыто сверху: иначе фокус прокрутил бы его вниз, и начала содержимого не видно.
В iOS до 15.4 (у части аудитории в России) `<dialog>` без `showModal`: окно открывается атрибутом
`open` с `role="dialog"`, затемнение — своим элементом, фокус держит своя ловушка, а остальное
содержимое страницы на время окна скрыто от диктора (`aria-hidden`, `inert`): VoiceOver свайпом за
окно не уйдёт. На телефоне окно — шторкой снизу. Там, где полоса прокрутки занимает место (Windows),
на время окна её место остаётся пустым (`scrollbar-gutter: stable`), и страница под затемнением не
сдвигается.

## Почему поведения не прячут контент

Анимация появления, сделанная в лоб (`opacity: 0` в CSS, скрипт показывает), оставила бы пустую
страницу без JS, при ошибке скрипта, в печати и у поискового робота. Здесь прячет только метка
скрипта `data-av-pending`, и скрипт ставит её лишь тому, что ниже экрана при загрузке, — и не ставит
вовсе при «уменьшить движение» и без IntersectionObserver. Появление срабатывает чуть выше нижнего
края экрана (минус 10 %), поэтому строка у самого низа страницы (копирайт подвала) этой полосы может
не достичь никогда: докрутили до упора — скрипт показывает всё, что ещё ждёт и уже в экране. CSS-приёмы (`animation-timeline: view()`,
`::details-content`) пока есть не у всех браузеров нашей аудитории (старые iOS), поэтому —
маленький скрипт поверх рабочего HTML.

## Чем платим

- Страница-окно на сайте ещё и отдельная страница: её стоит закрыть от поисковиков (noindex) и дать
  ей короткую шапку — это решает автор.
- Если шаблон своего блока ссылается в окно атрибутом, сборка кладёт на страницу все окна сайта:
  какой адрес выведет шаблон, известно только после рендера. Окон на сайте обычно одно-два.
- Свой CSS окон — один на все окна, в теме: окон немного, и вид у них общий.
- В iOS Safari до 16 `overflow: hidden` у страницы не останавливает прокрутку касанием: под окном
  фон можно прокрутить пальцем. Окно при этом остаётся на месте и работает; держать прокрутку
  фиксацией `body` (с запоминанием места) — лишний код ради уходящих версий, поэтому так.
