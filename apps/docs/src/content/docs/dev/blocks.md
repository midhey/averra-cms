Для разработчика. После страницы вы добавите новый блок так, что он появится в каталоге редактора,
в MCP и на сайте, а кривые данные в нём не пройдут нигде.

Блок — это схема и компонент. Из схемы сами получаются проверка в API, типы, поля в админке и JSON
Schema для нейронки. Настраивать блок в базе не нужно.

## Три шага

1. **Схема** — `packages/schema/src/blocks/<имя>.ts` через `defineBlock`, и две строки в
   `packages/schema/src/blocks/index.ts`: в каталог `blocks` и в союз `BlockInstance`. Тест следит,
   чтобы списки не разъехались. Порядок `blocks` — как блоки обычно стоят на странице: так их
   показывают «Добавить блок» и `list_blocks`.
2. **Компонент** — `packages/blocks/src/<имя>/<Имя>.tsx` со стилями `<Имя>.module.css` и `case` в
   `packages/blocks/src/Page.tsx`. Без `case` проект не скомпилируется: в `switch` стоит проверка
   `never`.
3. **Набросок для каталога** — строка в `sketches` в `apps/admin/src/editor/BlockSketch.tsx`:
   полосы и плашки по концепту каталога. Набор проверяется `satisfies Record<BlockType, …>`, без
   наброска админка не скомпилируется. Пометка «новый» — тип в `NEW_BLOCKS`
   (`apps/admin/src/editor/catalog.ts`); убирают её оттуда же, когда блок перестаёт быть новостью.

Больше ничего: редактор и MCP берут каталог из `blocks`, рендерер и предпросмотр — из `Page`.

```ts
// packages/schema/src/blocks/cta.ts
export const cta = defineBlock({
  type: 'cta',
  title: 'Призыв к действию',
  description: 'Заголовок, пара строк и кнопка — подтолкнуть к следующему шагу',
  category: 'sales',
  props: z.strictObject({
    title: z.string().trim().min(1).max(120).meta({ title: 'Заголовок' }),
    text: z.string().trim().max(300).optional().meta({ title: 'Текст' }),
    button: Button.meta({ title: 'Кнопка' }),
  }),
  example: { title: 'Готовы начать?', button: { label: 'Оставить заявку', href: '#contact' } },
})
```

## Правила схемы

- **`z.strictObject`** для полей: лишнее поле — ошибка, а не тихо выброшенные данные.
- **`.meta({ title })` — последним** в цепочке. Из него — подписи в админке и подсказки для MCP;
  `description` в `meta` — подсказка под полем.
- **`description`** у блока — одна фраза без точки в конце: её показывают каталог «Добавить блок»
  и `list_blocks`, по ней же ищет поиск каталога.
- **`category`** — раздел каталога из `BLOCK_CATEGORIES` (`define-block.ts`): `start` «Начало
  страницы», `about` «О компании», `sales` «Продажа», `trust` «Доверие», `contact` «Связь». Новый
  раздел — строка там же; тест следит, чтобы пустых разделов не было.
- **`example`** — заполнение, с которым блок встаёт в редактор и которое видит нейронка. Тест
  прогоняет пример через схему. Выдуманных фактов в примере нет: числа, цены, сроки — заглушки в
  квадратных скобках («[12]», «от [цена] ₽/м²»), тест ищет цифры вне скобок у новых блоков.
- **Списки** — `z.array` объектов (пункты «Преимуществ») или строк («Что входит» у тарифа): админка
  рисует пункты карточками с перестановкой; у пункта-строки одно поле с подписью из `.meta` пункта.
- **Ссылки** — `Href` или `Button` из `common.ts`: только `https://`, `http://`, `/`, `#`, `mailto:`,
  `tel:`.
- **Выбор с подписями для людей** — пометка `x-enum-titles` в `.meta()` (`{ значение: подпись }`).
  Да/нет — `z.boolean()`: админка нарисует флажок.
- **Варианты оформления** — ещё и `x-enum-sketches` (`{ значение: рисунок }` из `ENUM_SKETCHES`):
  редактор нарисует карточки с миниатюрами. Сообщение схемы о варианте называет и подпись, и
  значение: «В варианте «С картинкой» (split)…» — человек видит подпись, MCP — значение.
- **Почта и телефон** — `EmailAddress` и `PhoneNumber` из `contact.ts` (или своя строка с пометкой
  `x-input: email | tel` в `.meta()`): админка рисует однострочное поле с этим `type` и
  `inputmode` — на телефоне откроется нужная клавиатура, — и без счётчика знаков.
- **Значение по умолчанию** — `.default()` у строки: админка показывает его подсказкой
  (`placeholder`) в пустом поле, потому что пустое поле на сайте покажет именно его.
- **Связи между полями** — `superRefine` с путём до поля: ошибка встанет у него в редакторе.

## Картинка в блоке

- Поле — `Image` из `@averra/schema` (`{ mediaId, alt }`, alt обязателен). По пометке `x-widget`
  админка ставит виджет выбора из медиатеки.
- Компонент выводит её только через `Picture` из `packages/blocks/src/ui`, справочник `media`
  приходит пропсом. Свой `<img>` в блоках не пишем: потеряются форматы, `srcset` и размеры.
- API сам проверит, что картинка из медиатеки этого сайта и не SVG, и не даст удалить
  используемую. `Picture` выводит SVG-вариант простым `<img>`.
- **Логотип** — поле `Logo` (`{ mediaId }` без alt, пометки `x-widget: image` и `x-allow-svg`): в
  него можно SVG. Где SVG можно, API решает по схеме — `svgAllowedAt(content, путь)` в
  `media-svg.ts` идёт по JSON Schema блока до поля картинки. Админка по той же пометке показывает
  SVG в выборе и не просит alt: alt логотипа — соседнее поле (название клиента), его компонент
  передаёт в `Picture` сам. SEO-проверка alt смотрит в схему поля: картинку без свойства `alt`
  (`Logo`) она не проверяет.
- **Картинка необязательна, если пример без неё** — пример для каталога и MCP проходит схему без
  медиатеки. Без картинки — плашка `var(--color-surface)` с `aria-hidden` («Наши работы», «Команда»)
  или текст («Клиенты»).
- **Ссылка на снимок целиком** — `fullSizeUrl(file)` из `ui/Picture.tsx`: самый широкий вариант
  запасного формата (или SVG). Так фото галереи открывается без JavaScript.
- **Фото фоном** — `Section` с `backdrop`: фон на весь блок под отступами (так у «Первого экрана»
  в варианте `cover`). Над фото — слой `var(--color-text)` с непрозрачностью `--cover-scrim`, текст
  поверх — `var(--color-background)`: `coverScrim` в `theme.ts` считает слой так, чтобы контраст
  держал 4,5 над любым фото. Рамка фокуса на фото — тем же цветом текста.
- **Кадр** — `aspect-ratio` и `object-fit: cover` на `img` внутри `Picture` (`.photo img`). Где
  `aspect-ratio` нет (iOS до 15), фото остаются в своих пропорциях — сетка не ломается.

## Компонент

- Пропсы — `BlockComponentProps<'имя'>`: `id` (он же якорь), `data` (поля после схемы, с
  умолчаниями), `headingLevel` (1 — только у главного первого экрана), `media`, `priority`,
  `formAction`.
- Обёртка — `Section` из `ui`: id блока становится якорем.
- **Без обязательного JavaScript на сайте.** Блок — HTML и CSS. Состояния вроде «отправлено» —
  CSS (`:target`), а не скрипт. Подробнее — [JavaScript на сайте](#javascript-на-сайте).
- **Стили — CSS Modules на переменных темы** (`var(--color-accent)`, `var(--space-4)`). Конкретных
  цветов и шрифтов в блоках нет: их задаёт тема сайта (`@averra/tokens`).
- **Акцент — порогом 3.** Тема проверяет акцент на фоне и на поверхности порогом 3
  ([решение](/averra-cms/decisions/theme-contrast/)): его хватает заливкам, рамкам, значкам и
  крупному тексту (от 24 px или от 18,66 px жирным) — числа «Цифр», «+» у вопросов. Мелкий текст
  акцентом не рисуют: ему нужно 4,5, поэтому номер шага в «Как мы работаем» и звёздочка у
  обязательного поля формы — цветом текста, а акцент — полосой над шагом. Надпись на акценте —
  `--color-on-accent`. Карточки тарифов стоят на полосе цветом фона — внутри них работают пары «на
  фоне». Кнопка-рамка (`ButtonLink appearance="outline"`) — рамка акцентом, надпись цветом текста.
- **Списки без маркеров** — `role="list"` на `ul`/`ol`: Safari с `list-style: none` иначе не
  говорит диктору, что это список («Как мы работаем», тарифы, «Цифры»). Тест разметки блоков
  проверяет это у каждого блока-списка.
- **Колонки сетки — `minmax(0, 1fr)`**, и одна колонка на телефоне тоже: у `1fr` и у колонки без
  размера ширина не меньше самого длинного слова, и адрес сайта в пункте тарифа дал бы
  горизонтальную прокрутку. Переносит такие слова `overflow-wrap` у `body` в `base.css`.
- Заголовки по `headingLevel`: h1 на странице один. Его получает блок из `mainHeadingBlock`
  (`@averra/schema`, первый «Первый экран») — по тому же правилу проверки SEO в редакторе говорят,
  есть ли на странице h1. Новый блок с главным заголовком — правка там, а не только в `Page.tsx`.

## JavaScript на сайте

Сайт работает без JavaScript: посетитель со старым телефоном, медленной сетью или выключенными
скриптами видит всю страницу и отправляет форму.

- **Без фреймворков и обязательного JS.** Ни React в браузере, ни островов Astro: компонент блока
  превращается в HTML при сборке, и на этом всё.
- **Маленькие улучшения поверх рабочего HTML — можно.** Скрипт в несколько строк, который делает
  удобнее то, что уже работает без него: например, плеер видео по клику на обложку вместо ссылки на
  ролик. Без скрипта блок обязан остаться рабочим, а не пустым.
- **Новые возможности браузера — по caniuse.** Перед тем как взять новое свойство CSS или API
  браузера, сверьтесь с [caniuse.com](https://caniuse.com/) с учётом аудитории в России: у неё
  заметная доля старых iPhone, а Safari на iOS обновляется только вместе с системой. Поддержки
  меньше ~95 % — нужен запасной вариант, при котором блок выглядит проще, но работает.
- **Раскрывающееся — на `<details>` и `<summary>`.** Бургер-меню, вопросы и ответы, «Подробнее»:
  открывается и закрывается без скрипта, с клавиатуры и для экранного диктора.

Аналитика (Метрика, GA4) — исключение по решению владельца сайта, а не по выбору блока: её
подключают в разделе «SEO и аналитика», и без неё сайт работает так же.

## Cookie-уведомление

Свой скрипт сайта, который есть только у сайта со счётчиком. Как им пользуются —
[Cookie и согласие](/averra-cms/admin/cookies/), почему так —
[решение](/averra-cms/decisions/cookie-consent/).

- **Разметка** — `CookieNotice` и `LegalFooter` в `packages/blocks/src/cookie/`. `LegalFooter` —
  полоса с документами внизу страницы, пока [подвал](#подвал-сайта) не опубликован или скрыт на
  странице; опубликованный подвал выводит те же ссылки сам. Что показать,
  решает `cookieNoticeView(settings, опубликованные адреса)`: нет счётчика — уведомления нет;
  страница политики не опубликована — ссылки нет. Корень `[data-cookie-consent]` отрисован с
  `hidden`: без JS уведомления не видно. Подвал, в котором без политики осталась одна кнопка
  «Настройки cookie», тоже `hidden` (`data-legal-footer`) — его показывает скрипт. Стили —
  CSS-модуль на переменных темы сайта.
- **Логика** — `consent.ts`: чистый контроллер `createConsent(config, ports)` без DOM. Читает
  выбор из cookie `averra_consent` (`necessary`, `analytics.ym.ga`, `notice.ym` — у согласия и
  «Понятно» набор сервисов: `ym` — Метрика, `ga` — GA4). Набор не покрывает счётчики сайта сейчас
  (добавили GA4) — выбора нет, как и у старого значения без набора. Дальше решает, показать ли
  уведомление, и просит порт вставить счётчики — в режиме согласия только при выборе `analytics`
  и только один раз. В режиме уведомления ответом считаются `notice` и `analytics`: отказ
  `necessary`, данный ещё в режиме согласия, снова показывает уведомление. Отзыв после загрузки —
  порт `forgetAnalytics`: стереть cookie и ключи localStorage и sessionStorage `_ym*`, `_ga*`,
  `_gid`, `_gat*`, `_gcl*` (cookie — на хосте и родительских доменах) и перезагрузить страницу.
  Тесты — `consent.test.ts`.
- **DOM** — `consent-dom.ts` (`startCookieConsent`, экспорт `@averra/blocks/cookie-consent`): кнопки
  по `data-consent-action`, «Настройки cookie» по `data-consent-open`, номера счётчиков из
  `data-metrika` и `data-ga4` (ещё раз проверяются шаблоном). Они есть в обоих режимах: в режиме
  уведомления скрипт счётчики не грузит, а только пишет их набор в cookie. Окна — `<dialog>`:
  `showModal()`, а где его нет (iOS до 15.4) — атрибут `open` и `aria-modal="true"`; ловушка фокуса,
  Esc и возврат фокуса — свои, одни для обоих путей. Tab и Esc слушает `document`, а не окно: без
  `showModal` фон не инертен, и клик по затемнению уводит фокус на body. Открытые окна — стопкой,
  клавиши — у верхнего. «Окно по центру» при открытии фокусирует само себя (`tabindex="-1"`): первое
  Enter не уводит на политику. В таких браузерах нет и глобального `HTMLDialogElement`: окно узнаём
  по тегу, а не `instanceof`, методы `<dialog>` проверяем перед вызовом. Пока открыто окно настроек,
  у корня атрибут `data-settings-open` — уведомление под окном приглушено. Счётчики вставляются теми
  же вызовами, что в их официальных кодах (очереди `ym.a` и `dataLayer` — объекты `arguments`), без
  вебвизора. Тесты — `consent-dom.test.tsx` в happy-dom, в том числе без `HTMLDialogElement`,
  `showModal` и `close`.
- **Сборка** — `apps/renderer/src/components/CookieConsent.astro` рендерится, только когда есть
  уведомление: `<script>` в нём Astro собирает в модуль релиза (`/_astro/…`), внешних загрузок нет.
  В режиме «только уведомление» счётчики, как раньше, — в `<head>` (`analyticsHead`), в режиме
  согласия их там нет.

Проверка в браузере — `e2e/tests/cookies.spec.ts`: собранный сайт отдаётся из папки релиза, до
согласия в нём нет `script` Метрики, после «Принять все» — есть, выбор переживает перезагрузку.

## Видео

Второй свой скрипт сайта — плеер блока «Видео», только на страницах с этим блоком. Как им
пользуются — [Редактор → Видео](/averra-cms/admin/editor/#видео), почему так —
[решение](/averra-cms/decisions/svg-and-video/).

- **Разбор ссылки** — `parseVideoUrl` в `packages/schema/src/video.ts`: строго по домену, пути и
  виду id (YouTube — 11 символов, Rutube — 32 hex, VK — `owner_id`), без логина и порта в адресе.
  Схема поля — `VideoUrl`: шаблон `^https?://` (в JSON Schema — `pattern`, поэтому поле в
  редакторе однострочное) и `refine` с примером в сообщении. Ссылки на сайт строятся из
  разобранного id: `videoWatchUrl` (страница ролика; у VK — с ключом `list=ln-…` ролика с
  доступом по ссылке) и `videoEmbedUrl` (плеер с автозапуском; YouTube — `youtube-nocookie.com`, у
  Rutube `autoplay=true` площадка не гарантирует). Новая площадка — ветка в `parseVideoUrl` и обеих
  функциях, префикс плеера в `isEmbedUrl`, образцы в `video.test.ts` и строка получателя в шаблоне
  политики (`VIDEO_RECIPIENTS` в `packages/schema/src/legal.ts`).
- **Разметка** — `Video.tsx`: рамка 16 : 9 через `padding-top: 56.25%` (`aspect-ratio` нет в Safari
  до iOS 15), в ней ссылка на страницу ролика (`target="_blank"`, `rel="noopener noreferrer"`) с
  обложкой (`Picture`) или заглушкой из переменных темы. Адрес плеера — в `data-video-embed`. До
  клика на странице нет ни iframe, ни картинок площадки.
- **Скрипт** — `player-dom.ts` (`startVideoPlayers`, экспорт `@averra/blocks/video-player`): один
  слушатель на документ, клик без модификаторов заменяет ссылку iframe с `sandbox`, `allow` и
  `referrerpolicy="strict-origin-when-cross-origin"` (без Referer YouTube не играет) и переводит
  фокус в плеер. Под плеером он показывает скрытую ссылку на ролик (`data-video-fallback`): если
  площадка недоступна, посетитель не останется перед пустым плеером. Ctrl/⌘/Shift-клик и средняя
  кнопка остаются ссылкой. Права песочницы проверены вживую на Rutube и VK — см.
  [решение](/averra-cms/decisions/svg-and-video/#чем-платим). Сборка —
  `apps/renderer/src/components/VideoPlayer.astro`, рендерится только при блоке `video`.
- Тесты — `Video.test.tsx` в happy-dom: до клика нет iframe и внешних загрузок, клик ставит плеер,
  модификаторы и чужой адрес — нет. В браузере — `e2e/tests/video.spec.ts`.

## Шапка сайта

Не блок страницы, а одна шапка на сайт: компонент в `packages/blocks/src/header/`. Как ею
пользуются — [Шапка и меню](/averra-cms/admin/header/), почему так —
[решение](/averra-cms/decisions/site-header/).

- **Модель** — `Header` в `packages/schema/src/header.ts`: раскладка `layout` (`classic`, `center`,
  `double`, `minimal`), `sticky`, `condense` (только при `sticky`), `overlay`, `phone`, `button` и
  пункты `menu` — `{ label, page, block? }`, до `HEADER_MENU_MAX` (8), `logo` — id картинки.
  `headerLinkIssues(header, страницы, 'draft' | 'published')` — замечания к целям пунктов (API при
  сохранении и публикации, админка — заранее). `resolveSiteLink` — куда ссылка ведёт на собранном
  сайте: нет страницы — пункта нет, нет блока — на страницу. `readHeader` терпим к версиям.
  Страница скрывает шапку полем `hideHeader` в своём содержимом.
- **Что вывести** — `siteHeaderView(...)` в `header/view.ts`: шапка открытой страницы (ссылки
  разрешены, прозрачная — только если `overlayFits` первого блока: «Первый экран» в варианте
  `cover`; меню нет у `minimal`, телефон и адрес — из «Организации»). `null` — шапки нет. Одна
  функция для сайта (`page.astro`) и предпросмотра в админке.
- **Разметка** — `SiteHeader.tsx`: первой — «К содержимому» (`#content`, id у `main` в `Page`),
  `header[data-site-header]` с атрибутами состояния, меню двумя списками `nav aria-label="Меню
  сайта"` — строкой (с 64rem) и в `<details data-header-menu>` для телефона; виден всегда один,
  другой — `display: none`. Текущий пункт — `aria-current="page"` и подчёркивание. Логотип —
  `Picture` с `eager`: сразу, но без `fetchpriority`, первым грузится фото первого экрана.
  Прозрачная шапка на фото берёт цвет текста блока — `var(--color-background)`. Стили — только
  переменные темы.
- **Отступ якорей** — липкая шапка ставит `data-sticky-header="<раскладка>"` у `html`, и
  `scroll-padding-top` в `base.css` не даёт ей закрыть раздел, к которому перешли по якорю
  (двухстрочным `center` и `double` — больше). Высота шапки зависит от текста, поэтому сборка
  ставит ещё два признака по тем же функциям, что и шапка: `data-sticky-header-row`
  (`headerRowButton`, кнопка своей строкой) — уже 48rem отступ 12,5rem, у `double` 17rem;
  `data-sticky-header-menu-row` (`headerMenuRow`, меню своей строкой) — с 64rem 14rem, у `center`
  и `double` 16,5rem. Числа — по замеру самой высокой шапки при допустимых длинах (название сайта
  80 знаков без логотипа, подпись кнопки 40, адрес в две строки, восемь пунктов по 40): на 1024 px
  «Классика» с логотипом — 215 px, `center` без логотипа — 252 px. С 48 до 64rem кнопка уже в
  строке, и отступа по раскладке хватает: «Минимум» — 92 px, двухэтажная — 132 px. e2e
  (`header.spec`) переходит по якорю на этих длинах: кнопкой шапки без меню на 320–800 px, пунктом
  длинного меню у `classic`, `double` и `center` на 1024 и 1440 px. Признаки — без `:has()`,
  которого нет у старых iOS.
- **Узкий экран** — логотип не шире места в строке (`max-width: min(12rem, 100%)`). У шапки без
  меню `.actions` сжимается и подпись кнопки переносится (`overflow-wrap: anywhere`); у шапки с
  меню `.actions` (трубка и «Меню») не сжимается — ужимается логотип. Шапка без меню с кнопкой
  (`data-row-button`: «Минимум» или пустое меню) уже 48rem ставит кнопку своей строкой во всю
  ширину: рядом с логотипом и трубкой на 320 px место есть только короткой подписи, а на 640 px
  длинная подпись рядом с длинным названием сжималась в столбик. С 48rem кнопка в строке, но
  трубка с кнопкой не уже `min(21rem, 50%)`, с 64rem (номер виден целиком) — `min(32rem, 50%)`.
  Высота шапки при этом известна без скрипта, и прозрачной шапке отступ первого экрана задан с
  запасом на эту строку.
- **Широкий экран** — с 64rem у бренда нижняя граница ширины `min(8rem, 30%)`: меню переносится, а
  не сжимает логотип в полоску. Длинное меню (`headerMenuRow`: пункт длиннее 24 знаков или меню
  с подписью кнопки и, без логотипа, названием сайта длиннее 100) встаёт своей строкой под
  логотипом, телефоном и кнопкой (`data-menu-row`), пункты не переносятся внутри себя: в одной
  строке с логотипом восемь пунктов по 40 знаков сжимались в столбик, и липкая шапка занимала
  полэкрана. Решает сборка по длине подписей: без скрипта и без `:has()`. Прозрачной шапке с меню
  своей строкой отступ первого экрана больше — с запасом на три строки меню. У полной `center`
  меню своей строкой всегда, признак даёт ей целые пункты и отступы якорей и первого экрана, а
  боковые колонки не уже `min(17rem, 28%)` — кнопка рядом с длинным названием не сжимается.
  Собранная `center` раскладывается как `classic`: короткое меню — в строке с логотипом,
  телефоном и кнопкой, длинное (`data-menu-row`) — своей строкой под ними. Одной сеткой в строку
  колонка меню сжималась до нуля, и пункты ложились на название и телефон.
- **Скрипт** — `header-dom.ts` (`startSiteHeader`, экспорт `@averra/blocks/site-header`):
  IntersectionObserver следит за двумя метками вверху страницы. Дальняя
  `[data-header-sentinel="far"]` (7rem) ушла из окна — `data-condensed` (сборка) или `data-stuck`
  (прозрачная липкая встаёт сверху с фоном); снимает их только ближняя
  `[data-header-sentinel="top"]` (0.5rem), когда вернулись к самому верху. Зазор — гистерезис:
  липкая шапка стоит в потоке и при сборке становится ниже (у `center` и `double` — на ~50 px),
  браузер сдвигает прокрутку на эту разницу (scroll anchoring), и с одной меткой шапка мигала бы
  каждый кадр. Не делайте зазор меньше разницы высот полной и собранной шапки. Анимация —
  `data-animate` после первого состояния и только без `prefers-reduced-motion`. Esc закрывает
  меню и возвращает фокус на «Меню», выбор пункта закрывает меню. Сборка —
  `apps/renderer/src/components/SiteHeaderScript.astro`, рендерится по `headerScriptNeeded`:
  сборка, прозрачная липкая или меню (ради Esc — значит, почти на каждой странице). Без меню и
  без сборки скрипта нет.
- Тесты — `SiteHeader.test.tsx` (раскладки, `details`, `aria-current`, когда нужен скрипт),
  `header-dom.test.tsx` (наблюдатель, гистерезис, reduced motion, Esc), `header.test.ts` в схеме и
  API; в браузере — `e2e/tests/header.spec.ts`: собранный сайт на 1440 и 375 без JS и с ним,
  что шапка каждой раскладки не мигает, когда прокрутка остановилась чуть ниже метки, и что
  «Минимум» с подписью кнопки в 40 символов, телефоном и вытянутым логотипом умещается в 320 и
  375 px без прокрутки и наложений; без логотипа и с названием в 80 знаков заголовок на фото ниже
  шапки (у двухэтажной с адресом в две строки — на 320 и 375 px); восемь пунктов по 40 знаков на
  1024 и 1440 — меню своей строкой, шапка `classic` ниже 240 px, `double` и `center` — ниже
  280; собранная `center` с длинным меню и с длинным названием без логотипа (1024–1440, с JS) —
  пункты внутри меню, не на названии, телефоне и кнопке, и не выше полной; переход по якорю от
  320 до 800 px и по пункту длинного меню не прячет заголовок раздела под шапку.

## Подвал сайта

Как и шапка, не блок страницы, а один подвал на сайт: `packages/blocks/src/footer/`. Как им
пользуются — [Подвал](/averra-cms/admin/footer/), почему так —
[решение](/averra-cms/decisions/site-footer/).

- **Модель** — `Footer` в `packages/schema/src/footer.ts`: вид `layout` (`simple`, `columns`,
  `big`), фон `tone` (`surface`, `accent`), строка `about`, флажок `sections` и тексты формы
  `callback`. Реквизитов, контактов и ссылок в модели нет: они из «SEO → Организация»
  (`footerContacts`, `footerRequisites`, `socialLinks` — подпись соцсети по домену), разделы —
  пункты меню шапки. `readFooter` терпим к версиям. Страница скрывает подвал полем `hideFooter`.
- **Что вывести** — `siteFooterView(...)` в `footer/view.ts`: разделы — меню опубликованной шапки
  через `resolveSiteLink`, у `simple` их нет; форма — только у `big` и только с опубликованной
  политикой; название организации, совпадающее с названием сайта, второй раз не пишется; «©» — год
  сборки. `null` — подвала нет (не опубликован или `hideFooter`): `page.astro` выводит прежний
  `LegalFooter`, чтобы ссылки на документы остались на каждой странице.
- **Разметка** — `SiteFooter.tsx`: `footer[data-site-footer]` с `data-layout` и `data-tone`, разделы
  — `nav aria-label="Разделы сайта"`, заголовки колонок — `h2` (после `main` порядок не рвётся),
  контакты — `address`. Значок соцсети показывает короткую подпись (`aria-hidden`), а диктор слышит
  «VK — ВКонтакте»: имя ссылки содержит видимый текст. Нижняя строка — та же разметка ссылок, что у
  `LegalFooter`: «Настройки cookie» — `button[data-consent-open]` с `hidden`, показывает его
  скрипт cookie-уведомления (в предпросмотре админки — проп `preview`).
- **Форма** — обычная HTML-форма, как блок «Форма»: поля `footerFormFields` (телефон) через
  `formFieldInput`, согласие, ловушка `website`, `action` — `/api/forms/:siteId/:slug/~footer`
  (`FOOTER_FORM_ID`: `~` не бывает в id блока). Id частей формы начинаются с `~footer`, успех —
  `#~footer-sent` и `:target`, как у блока. API ищет форму не в блоках страницы, а в опубликованном
  подвале: см. [API](/averra-cms/dev/api/), «Заявки».
- **Цвета** — только роли темы. Вверху CSS-модуля палитра: переменные `--footer-bg`,
  `--footer-text`, `--footer-muted`, `--footer-focus`, `--footer-button-bg`, `--footer-button-text`,
  `--footer-line` для `surface` и `accent`; ниже цвета берутся только из них. Роли за ними — в
  `footerPalette` схемы; `footerContrast` считает пары подвала, и каждая из них — пара, которую
  тема уже проверяет (`themeChecksPair`). На акценте весь текст и фокус — «текст на акценте»
  (рамку фокуса акцентом на акценте не видно), кнопка — наоборот.
- Тесты — `SiteFooter.test.tsx` (три вида, обязательные ссылки, форма, палитра CSS против схемы:
  файл читается через `process.getBuiltinModule`, Vitest отдаёт CSS-модули пустыми),
  `footer.test.ts` в схеме (контраст во всех готовых темах и в тёмной) и в API (публикация, приём
  заявки); в браузере — `e2e/tests/footer.spec.ts`.

## Вопросы и ответы

`Faq.tsx` — `<details>` и `<summary>`, без скрипта. В `summary` только текст вопроса и значок
(`aria-hidden`): заголовок внутри роли «кнопка» диктор не услышит как заголовок. `summary` —
блоком, а не флексом: старый Safari флекс-контейнером его не делает; свой значок вместо
треугольника — `list-style: none` и `::-webkit-details-marker`. Ответ делится на абзацы
`splitParagraphs` (`text-body.ts`).

Разметка для поисковиков — `faqJsonLd` в `apps/renderer/src/lib/seo.ts`: одна FAQPage на
страницу из вопросов всех блоков `faq`, только у страницы в индексе (`isIndexable`). Как и JSON-LD
организации, JSON внутри `<script type="application/ld+json">` экранирован (`scriptJson`). Тесты —
`seo.test.ts`, в браузере — `e2e/tests/blocks.spec.ts`.

## Контакты

`Contacts.tsx` — `address` со списком `dl` («Телефон», «Почта», «Адрес», «Часы работы»). Правила
телефона и почты — `contact.ts` в схеме, общие с «SEO → Организация»: `PhoneNumber` требует хотя
бы 5 цифр, `telHref` оставляет только цифры и «+». Ссылка на карту — `mapUrl` там же: по
координатам — точка (`yandex.ru/maps/?pt=долгота,широта`, `2gis.ru/geo/долгота,широта`), иначе
поиск по адресу. Чужую карту не встраиваем: до согласия на cookie нельзя.

Разметка для поисковиков — `organizationJsonLd(site, page, media)` в рендерере: на главной и на
странице в индексе с «Контактами» (`markup: true`). Одна организация: данные «SEO» главнее, блок
дополняет пустые телефон, почту и адрес, у `LocalBusiness` — `hasMap`; `@id` один на сайт. Тесты —
`seo.test.ts`, в браузере — `e2e/tests/landing-blocks.spec.ts`.

## Форма

Поля формы описывает таблица `fieldRules` в `packages/schema/src/forms.ts`. Из неё — и HTML-атрибуты
в браузере (`formFieldInput`), и проверка заявки на сервере (`leadValuesSchema`). Атрибуты проверки
в компоненте руками не пишем. Новый тип поля — строка в `formFieldTypes` и `fieldRules` и ветка в
обеих функциях; образцы значений в `forms.test.ts` прогоняются через обе стороны. `pattern`
пишется так, чтобы компилироваться с флагом `v`, как в браузере.

Схема значения, которое потом станет вводом посетителя (вариант выбора), проверяет его по тем же
правилам, что сервер при приёме: если сервер значение не примет, редактор и MCP не должны суметь
его сохранить.

## Что ещё проверить

- Блок в редакторе: подсказка в списке слева берётся из `title`, числа `items` (слово — из
  `itemNouns` в `block-hint.ts`: «фото», «отзыва»), `plans`, `members` или `fields`, у контактов —
  телефон или адрес. Иначе — якорь. Имя пункта списка — `title`, `label`, `question`, `name` или
  `caption`.
- Блок в каталоге: раздел, набросок, поиск находит его по словам из описания.
- Блок в предпросмотре и на сайте без JS — `pnpm dev`.
- Старые страницы: если поменяли схему существующего блока, версии в истории проверяются нынешней
  схемой при возврате. Новое обязательное поле без умолчания сделает старые версии невозвратными —
  давайте умолчание.
- `pnpm check` и `pnpm e2e`.
