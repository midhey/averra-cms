Для разработчика. После страницы вы будете знать, как устроены свои блоки установки: откуда
берётся их схема, как рендерится шаблон, что проверяется при сохранении и на сайте. Как ими
пользуются — [Работа в админке → Свои блоки](/averra-cms/admin/custom-blocks/), почему так —
[решение](/averra-cms/decisions/custom-blocks/). Когда делать встроенный блок, а когда свой —
[Встроенный или свой блок](/averra-cms/dev/blocks/#встроенный-или-свой-блок).

## Модель

Свой блок — как секция Shopify: **поля + шаблон + стили**. Определение (`CustomBlockDraft` в
`packages/schema/src/custom-blocks.ts`) — ключ, название, описание, раздел каталога (`category`),
набросок «как у» встроенного (`sketch`), поля (`fields`), шаблон Liquid (`template`), CSS (`css`) и
пример данных (`example`).

- **Хранение** — таблицы `custom_blocks` (черновик `draft`, опубликованное `published`) и
  `custom_block_revisions` (версия при каждой публикации) — [Модель
  данных](/averra-cms/dev/data/). Обновление Averra их не трогает: схема меняется только миграциями.
- **Тип на странице** — `custom:<ключ>` (`customBlockType`, `isCustomBlock`). Двоеточия нет ни в
  одном встроенном типе.
- **Черновик** сохраняется, если проходит `CustomBlockDraft` (структура полей, пределы); ошибки
  шаблона, CSS и примера — замечания. **Публикация** — только без ошибок.

## Поля → Zod

`customBlockProps(fields)` строит `z.strictObject` по полям — одна функция для API (сохранение и
публикация страницы), админки (форма, проверка на лету) и MCP (JSON Schema в `list_blocks`):

| Вид | Схема |
|---|---|
| `text`, `textarea` | `z.string().trim()` с `min`/`max`; у `textarea` пометка `x-multiline` — админка рисует многострочное поле |
| `number` | `z.number()` или `z.int()` с `min`/`max` — админка рисует поле с цифровой клавиатурой |
| `boolean` | `z.boolean().default(…)` |
| `select` | `z.enum(значения).default(…)` с `x-enum-titles` |
| `link` | `Button` из `common.ts`: `{ label, href }`, `href` — `Href` |
| `image` | `Image` из `media.ts`: `{ mediaId, alt }`, alt обязателен, `x-widget: image` |
| `repeater` | `z.array(customBlockProps(поля))` с `min`/`max` (без минимума — `default([])`) |
| `group` | `customBlockProps(поля)` |

Обязательное без умолчания — как есть, с умолчанием — `.default()`, иначе `.optional()`. Подпись и
подсказка — `.meta({ title, description })`. Пределы — `CUSTOM_BLOCK_LIMITS`: 60 полей, 30 на
уровне, 3 уровня, 30 вариантов, повторитель до 50 пунктов, шаблон и CSS до 20 000 знаков каждый, пример данных — до 100 000 знаков.

## Страница со своими блоками

`PageContent` пускает свой блок как `{ id, type: custom:…, props: объект }` (`CustomBlockInstance`).
Элемент страницы — `PageBlock`: в JSON Schema это `anyOf` встроенных и своего, а разбор идёт по типу
(`custom:` — своя схема, иначе — встроенные). Простое `z.union` при ошибке в поле встроенного блока
отдало бы «не подошёл ни один вариант» без пути до поля. У `PageBlock` заменён разбор, поэтому
методы, создающие копию (`.meta`, `.optional`), у него не вызывают.

Поля своих блоков проверяет `applyCustomBlocks(content, опубликованные определения)`: страница с
умолчаниями и ошибки с путём `blocks.2.props.plans.0.title`. Её вызывают:

- API при сохранении черновика (400), публикации страницы (409, если определение с тех пор
  поменялось) и возврате версии (409) — `checkPageCustomBlocks` в
  `apps/api/src/modules/custom-blocks/service.ts`;
- админка в `validateBlocks` — ошибки встают у полей формы, как у встроенных.

## Шаблон Liquid

Движок — `@averra/blocks/custom-engine` (`packages/blocks/src/custom/`), без React: им пользуются
`Page` (сайт и предпросмотр) и API (проверка). LiquidJS настроен строго:

- **`outputEscape: 'escape'`** — весь вывод `{{ }}` экранирован. `raw`, `escape` и `escape_once`
  переопределены и экранирование не снимают. `{% echo … %}` (и `echo` внутри `{% liquid %}`) —
  тот же вывод с тем же экранированием: штатный `echo` писал мимо него, поэтому заменён. Скобки
  `{{ }}` и `{% %}` в аргументах `echo` — ошибка: они спрятали бы разметку от проверки HTML.
  `{% cycle %}` выключен (он тоже писал мимо экранирования): чередуйте через
  `{% assign odd = forloop.index | modulo: 2 %}`.
- **`capture`** собирает уже экранированный текст, и `{{ переменная }}` экранирует его ещё раз:
  `<b>` из `capture` на сайте станет видимым `&lt;b&gt;`. Разметку собирайте в самом шаблоне, а
  `capture` берите для текста.
- **Без файлов**: `templates: {}`, теги `include`, `render`, `layout`, `block` — ошибка «недоступен».
- **`strictFilters`** — неизвестный фильтр — ошибка; **`ownPropertyOnly`** — без прототипов.
- **Лимиты** (`LIQUID_LIMITS`): рендер — 200 мс, «память» LiquidJS — 2 000 000, HTML — 500 000
  знаков.
- **Переменные**: поля блока по ключам и `block` — `{ id, key }` (id — якорь на странице).
  Неизвестная переменная — ошибка со строкой (статический анализ LiquidJS).

Свои фильтры:

| Фильтр | Что делает |
|---|---|
| `image: sizes, class` | картинка медиатеки как `Picture` у встроенных: AVIF и WebP с набором ширин, запасной формат, `width`/`height` исходника, alt из поля; первый блок страницы — сразу и с `fetchpriority`, остальные — лениво |
| `image_url`, `image_width`, `image_height` | адрес самого широкого варианта, размеры исходника |
| `link` | безопасный адрес из поля «Ссылка» или строки: только `https://`, `http://`, `/`, `#`, `mailto:`, `tel:`, иначе `#` |
| `paragraphs` | абзацы `<p>` по пустой строке, перенос внутри абзаца — `<br>`; текст экранирован |
| `newline_to_br` | переносы строк — `<br>`; текст экранирован |

Ошибка шаблона — понятный текст и строка (`liquidErrorOf`): «Неизвестный фильтр «shout»», «Тег
{% if … %} не закрыт».

## HTML: две линии

1. **При сохранении** — `checkTemplateHtml`: шаблон, где Liquid заменён маской той же длины (вывод —
   `x`, теги — пробелами, строки и колонки на месте), разбирается parse5. Ошибки со строкой:
   `script`, `noscript`, `style`, `iframe`, `object`, `embed`, `form`, `base`, `link`, `meta`, SVG
   `set` и `animate…` и другие встраивания; `plaintext`, `xmp`, `listing`, `noembed`, `noframes`
   (браузер показал бы текстом всё, что после них на странице); атрибуты `on…`, `srcdoc`, `style`
   (стили — только во вкладке CSS: там они изолированы), `ping`, `form`, `formaction` и другие
   `form…` (кнопка не уйдёт в форму сайта); ссылка `javascript:` (и любая схема, кроме http(s),
   mailto, tel) в `href`, `src`, `srcset` и других; чужой адрес (`https://…`, `//хост`) в `src`,
   `srcset`, `poster`, `data` и в `href` у SVG `use`/`image`: картинки — из медиатеки (фильтр
   `image`), остальное — со своего сайта; `href` у SVG-шаблонов (`linearGradient`,
   `radialGradient`, `pattern`, `filter`, `textPath`, `mpath`) — только `#id` элемента блока
   (Firefox берёт шаблон и из внешнего документа); Liquid в значении атрибута без кавычек, Liquid на месте
   имени атрибута или элемента, в том числе приклеенный к нему (`<a{{ x }}>` — ошибка, `<a {{ x }}>`
   с пробелом — нет); `url()` в любом атрибуте, кроме `alt`, `title`, `aria-*`, `data-*`
   (`fill`, `mask`, `clip-path`, `filter`, `marker-*`, `cursor` в SVG браузер читает как CSS и грузит
   файл): допустим только `url(#id)` на элемент блока; `data-*` с именами, которыми сайт помечает
   свою разметку (`data-cookie-consent`, `data-consent-…`, `data-site-header`, `data-header-…`,
   `data-video-…`, `data-custom-block…`, `data-tone` и другие — список `isReservedDataAttribute` в
   `packages/blocks/src/custom/marker.ts`, его сверяет тест с исходниками скриптов и `base.css`):
   иначе шаблон выдал бы себя за уведомление о cookie со своим счётчиком или за обложку видео;
   `id` разметки сайта (`content`, `cookie-…`, `~footer…`); `popovertarget`, `for`, `list`,
   `headers`, `aria-labelledby`, `aria-describedby`, `aria-controls` и другие ссылки по id — только
   на id из этого же шаблона (значение из Liquid проверяет рендер); `id`, годный в имя переменной
   JS (`menu`, `ym`, `dataLayer`, `цены`), и `name` у `img` — браузер кладёт такие элементы в
   `window` и `document` (DOM clobbering): `<img name="querySelectorAll">` подменил бы метод, и
   скрипты сайта упали бы. Правило разрешающее — id с дефисом или другим знаком вне имён JS
   (`{{ block.id }}-menu`), а не список занятых имён: чужие счётчики заводят свои переменные;
   `autofocus` и `tabindex` больше 0 (фокус и порядок Tab всей страницы). Советы: `h1` (он у первого
   экрана) и `img` без alt.
2. **При рендере** — `sanitizeHtml`: вывод Liquid разбирается parse5 и собирается заново без
   запрещённых элементов, обработчиков и опасных ссылок. Это ловит то, чего не видно в шаблоне:
   текстовое поле в `href` со значением `javascript:…` или атрибут, собранный `{% if %}`. Сборка из
   дерева, а не замена по тексту: браузер разберёт ровно то, что разобрали мы. Так же убирается
   `url()` с чужим адресом из атрибута, значение которого пришло из поля (`fill="{{ color }}"`).
   Ещё при рендере убираются `id`, совпадающие с id блоков страницы (и их продолжения
   `id-…`, например поля формы): копия стояла бы раньше и перехватила бы якорь меню; свой
   `{{ block.id }}-имя` остаётся. Ссылки по id (`popovertarget`, `aria-…`) на элементы вне блока —
   тоже убираются.
3. **Скрипты сайта** (уведомление о cookie, шапка, плеер видео) ищут свою разметку только вне
   своих блоков (`closest('[data-custom-block]')`): даже подделка, прошедшая мимо
   проверки, не будет принята за настоящую.

## CSS внутри блока

`compileCustomCss(css, ключ)` — postcss, postcss-selector-parser и postcss-value-parser, не
регулярные выражения. Проверка — по **разрешающему списку**: пропускается то, что перечислено, а
не всё, кроме запрещённого. Так новая возможность браузера не проходит мимо проверки сама.

- Селектор — внутри `[data-custom-block="ключ"]` (атрибут у `<section>` блока). Он начинается с
  `:scope` (сама секция: фон на всю ширину, отступы), с элемента, класса, атрибута или `*` блока
  (к нему спереди дописывается селектор блока и пробел) или с `>`. HTML шаблона лежит в обёртке
  `[data-custom-block-root]` внутри секции, поэтому `> .a` и `:scope > .a` собираются в
  `[data-custom-block="ключ"] [data-custom-block-root] > .a` — верхние элементы шаблона, а не
  служебные обёртки секции. `~`, `+` и `||` в начале селектора или
  после `:scope` выбрали бы соседние блоки страницы — ошибка; `:scope` не в начале (`:not(:scope)`,
  `*:has(:scope)`) — тоже. Части селектора — элемент, класс, `#id`, атрибут, `*`, комбинаторы
  ` `, `>`, `+`, `~` и псевдоклассы из списка: состояния (`:hover`, `:focus-visible`, `:checked`…),
  порядок (`:nth-child()`, `:first-of-type`…), `:not()`, `:is()`, `:where()`, `:has()`,
  `:popover-open`,
  псевдоэлементы (`::before`, `::marker`, `::placeholder`…, свои у браузеров `::-webkit-…`).
  Остальное (`:host`, `::part()`, экранированное имя) — ошибка. `html`, `body`, `:root` и вложенные
  правила (`&` — нет в старом Safari) — ошибка.
- Можно `@media`, `@supports`, `@container`, `@starting-style`, `@keyframes` (имя получает префикс `ключ--`,
  `animation` переписывается); остальные @-правила (`@import`, `@font-face`, `@layer`…) — ошибка.
- Функции в значениях — из списка: `var()`, математика (`calc()`, `clamp()`, `min()`…), цвета
  (`rgb()`, `oklch()`, `color-mix()`…), градиенты, трансформации, фильтры, фигуры (`polygon()`…),
  `repeat()`, `minmax()`, `cubic-bezier()`, `counter()`; `attr()` — только в `content`. Префиксы
  браузеров (`-webkit-linear-gradient`) — как без них. Неизвестная функция — ошибка: `image()`,
  `src()`, `cross-fade()`, `element()`, `paint()` грузят файл мимо проверки.
- `url()` — только `url(media:<id картинки>)`: при сборке он становится адресом файла медиатеки
  (картинка попадает в справочник снимка и в релиз, удалить её из медиатеки нельзя). Проверяется и
  запасное значение `var(--x, url(…))`. `image-set()` — только `url(media:…)`, `type("…")` и
  плотность (`1x`, `2dppx`): строка в нём — адрес файла, а `var()` подставил бы строку из своего
  свойства, поэтому оба — ошибка. В `clip-path`, `mask`, `mask-image`, `filter`, `fill`, `stroke`,
  `marker*` можно ещё `url(#id)` — ссылку на элемент SVG блока: она ничего не грузит.
- Строка в свойствах, которые грузят картинку (`background`, `background-image`, `mask*`,
  `border-image*`, `list-style-image`, `cursor`, `shape-outside`), — ошибка. В `content`, `quotes`,
  `font-family` и своих свойствах (`--label: "Хит"`) строки можно: там они ничего не грузят.
- Обратная косая черта вне строки — в значении и в имени свойства — ошибка: браузер читает
  `\75 rl(` как `url(`, а `posit\ion` как `position`.
- Строка, оборванная неэкранированным переводом строки (LF, CR, FF), — ошибка: postcss считает её
  целой, а браузер обрывает и читает остаток как правила верхнего уровня, мимо изоляции. Проверка
  идёт до разбора. На выходе `</style` и `<!--` заменяются кодом символа, чтобы CSS не закрыл
  `<style>` страницы.
- `position: fixed` — ошибка (блок закрыл бы страницу, меню или подвал); `var()` в `position` —
  тоже: значение своей переменной (`--p: fixed`) по месту не проверить. `absolute` с выходом за
  блок не проверяется — это за автором, на телефоне видно сразу; `sticky` и `z-index`
  выше 10 — предупреждение;
- конкретный цвет (`#fff`, `rgb()`, `red`) — предупреждение: роль темы (`var(--color-text)`,
  `var(--color-accent)`) сменится вместе с темой сайта;
- ошибочные правила в сборку не попадают.

Переменные темы — те же, что у встроенных блоков: `--color-*`, `--font-heading`, `--font-body`,
`--space-*`, `--text-*`, `--radius`, `--container`.

## Рендер

- `Page` получает `customBlocks` — опубликованные определения по ключу — и рисует свой блок
  `CustomBlock`: тот же `Section`, что у встроенных (якорь, отступы, ширина), с
  `data-custom-block`; HTML шаблона — в обёртке `data-custom-block-root`.
- Картинка своего блока по умолчанию не шире блока: в `base.css` —
  `[data-custom-block] img { max-width: 100%; height: auto }`. Фильтр `image` ставит `width` и
  `height` файла (например 960), и без этого правила блок без своего CSS для картинки дал бы
  прокрутку на телефоне. CSS блока может задать размер сам — его селектор сильнее. Нет определения, данные не подходят или шаблон упал — на сайте блока нет
  (`onCustomBlockError` пишет причину в журнал сборки), в предпросмотре админки (`preview`) —
  причина на его месте.
- Снимок для рендерера несёт `customBlocks` — только опубликованные. CSS своих блоков страницы —
  `customBlocksCss` — отдельным `<style>` в `<head>` после темы, по разу на тип.
- Заголовки: h1 — у первого экрана, свой блок начинается с h2.
