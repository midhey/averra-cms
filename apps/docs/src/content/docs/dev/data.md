Для разработчика, который добавляет таблицу или колонку, пишет запрос или отвечает на вопрос «где
у нас персональные данные». После страницы вы будете знать, какая таблица за что отвечает и что
удаляется само.

Схема — `apps/api/src/db/schema.ts`, миграции — `apps/api/drizzle`. Как менять схему — в
[Соглашениях](/averra-cms/dev/conventions/#база).

`site_id` есть в каждой таблице с контентом с первого дня, хотя в установке сайт один: прикручивать
несколько сайтов потом очень больно. Удалили сайт — каскадом удаляется всё его. Сайт установки —
созданный первым (`sitesRepo.installationSite`), признака «основной» в `sites` нет: почему —
[Одна установка — один сайт](/averra-cms/decisions/single-site/).

## Таблицы

| Таблица | Что хранит | Срок хранения |
| --- | --- | --- |
| `sites` | Название; тема — `theme_published` (на сайте) и `theme_draft` (черновик экрана «Тема», пусто — как на сайте), JSON по схеме `Theme`, читает `readTheme`; шапка и меню — `header_published` (на сайте, пусто — шапки нет) и `header_draft` (черновик экрана «Шапка и подвал», пусто — как на сайте), JSON по схеме `Header`, читает `readHeader`; подвал — `footer_published` (на сайте, пусто — прежняя полоса с документами) и `footer_draft` (черновик вкладки «Подвал»), JSON по схеме `Footer`, читает `readFooter`; `theme` — проекция опубликованной темы в прежнем формате (шесть цветов, системные шрифты) для отката на версию до редактора тем, а у сайта до него — сама тема; настройки заявок: срок хранения заявок, подтверждение посетителю (`lead_recipients` устарела: адреса почты получателей заявок, её пишет модуль уведомлений для отката на прежнюю версию API); `settings` — настройки SEO (JSON по схеме `SiteSettings`: шаблон заголовка, описание, язык, адрес, индексация, иконка, коды, счётчики, организация, редиректы, cookie-уведомление `cookies`; пусто — по умолчанию, читает `readSiteSettings`) | Пока есть сайт |
| `users` | Пользователи админки, роль установки: `owner` или `member` | Пока не удалили |
| `sessions`, `accounts`, `verifications` | Таблицы Better Auth: сессии, пароли (хешем), токены сброса (хешем) | По срокам Better Auth |
| `site_members` | Роль участника на сайте: `editor` или `client` | Пока участник на сайте |
| `pages` | Адрес (`slug`), черновик (`draft`, `title`) и опубликованная версия (`published`, `published_title`). Содержимое — `PageContent`: блоки, SEO страницы (`seo`), `hideHeader` и `hideFooter` (скрыть шапку и подвал сайта на странице) | Пока есть страница |
| `page_revisions` | Снимок при каждой публикации: номер версии, заголовок, содержимое (`PageContent`: блоки, SEO страницы и `hideHeader`), кто опубликовал (пользователь или токен) и когда | Не переписывается и не чистится |
| `media` | Картинки сайта: исходное имя, тип (JPEG, PNG, WebP, AVIF или очищенный SVG одним файлом `image.svg`), размеры, вес, варианты (JSON), кто и когда загрузил. Файлы — в хранилище по ключу из id | Пока не удалили |
| `leads` | Заявки с форм: страница, блок, источник `source` (`block` — блок «Форма», `footer` — форма подвала, блок у неё `~footer`), заголовок формы, поля с подписями, их размер (`data_bytes`), согласие (текст, политика, версия страницы, время), статус `new` / `processed` | `lead_retention_days` сайта: от 7 до 1825 дней, по умолчанию 180 |
| `mail_outbox` | Очередь писем: шаблон, данные, кому, статус, попытки, аренда обработчика, последняя ошибка | Данные письма — до отправки; у окончательно не ушедшего — до удаления письма (для «Повторить»), если у шаблона нет секрета (такие шаблоны — `templatesKeepingData`); у приглашения и сброса пароля — стираются сразу; само письмо — `MAIL_RETENTION_DAYS` |
| `mail_settings` | SMTP из админки: сервер, порт, шифрование, логин, пароль (только зашифрованным), отправитель, когда прошла проверка | Пока не сменили |
| `user_invitations` | Приглашения: хеш токена, почта, сайт, роль, кто пригласил и кто принял, срок 7 дней | Закрытые — `MAIL_RETENTION_DAYS` после закрытия |
| `api_tokens` | Токены MCP: SHA-256 токена, сайт, кто выпустил, когда пользовались, отзыв | Пока не удалили |
| `notification_channels` | Каналы уведомлений: включён ли, открытые настройки (имя бота, прокси без пароля), секрет (токен бота и прокси — только зашифрованным) | Пока не сменили |
| `notification_recipients` | Получатели уведомлений: канал, адрес (почта или chat id), название чата, события; `site_id` сайта — получатели заявок, NULL — служебные | Пока не удалили |
| `notification_link_codes` | Коды привязки чата Telegram: SHA-256 кода, аудитория, кто выдал, срок 15 минут, какой чат привязан | Сутки после срока |
| `notification_outbox` | Очередь уведомлений (кроме почты): канал, адрес, событие, данные, статус, попытки, аренда, последняя ошибка | Данные — до отправки или окончательной неудачи; само сообщение — `MAIL_RETENTION_DAYS`; о заявке — вместе с ней |
| `notification_watch` | Служебные проблемы, о которых уже уведомили: ключ, событие, данные без персональных, когда появилась | Пока проблема есть |
| `site_builds` | Сборки сайта на сервере: состояние `queued` / `running` / `succeeded` / `failed`, папка версии, причина сбоя, пиковая память | Последние 20 на сайт |

## Что держит сама база

Правило, которое нельзя нарушить, проверяет база (`CHECK`, уникальный индекс), а не только код:

- у страницы опубликованное содержимое и его заголовок заполнены вместе — половинчатой публикации
  нет;
- `slug` уникален на сайте; номер версии в истории — больше нуля и уникален у страницы;
- у картинки и версии страницы автор — пользователь **или** токен, не оба;
- роли — только из списка; почта в приглашении — в нижнем регистре; у адреса на сайте одно открытое
  приглашение;
- порт и шифрование SMTP — только 465 с TLS или 587 со STARTTLS, пароль — в формате записи
  `SecretBox`; строка с `site_id` NULL (на всю установку) — одна;
- у сайта не больше одной ждущей сборки;
- данные отправленного письма стёрты, у уведомления — ещё и у окончательно не ушедшего;
- секрет канала уведомлений — в формате записи `SecretBox`; адрес в канале у аудитории — один.

## Персональные данные

- **IP посетителя не храним** нигде: он только ключ счётчика лимита в памяти.
- Заявки и уведомления о них связаны (`mail_outbox.lead_id`, `notification_outbox.lead_id`,
  `ON DELETE CASCADE`): удалили заявку — удалились и её письма и сообщения.
- Удаляет по сроку обработчик почтовой очереди (`cleanupAlso`): заявки, закрытые приглашения и
  старые письма. Отдельного планировщика нет.

Подробнее о хранении — [Персональные данные](/averra-cms/install/personal-data/).
