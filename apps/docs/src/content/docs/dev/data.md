Для разработчика, который добавляет таблицу или колонку, пишет запрос или отвечает на вопрос «где
у нас персональные данные». После страницы вы будете знать, какая таблица за что отвечает и что
удаляется само.

Схема — `apps/api/src/db/schema.ts`, миграции — `apps/api/drizzle`. Как менять схему — в
[Соглашениях](/averra-cms/dev/conventions/#база).

`site_id` есть в каждой таблице с контентом с первого дня, даже пока сайт один: прикручивать
несколько сайтов потом очень больно. Удалили сайт — каскадом удаляется всё его.

## Таблицы

| Таблица | Что хранит | Срок хранения |
| --- | --- | --- |
| `sites` | Название, тема (JSON), настройки заявок: адреса уведомлений, срок хранения заявок, подтверждение посетителю | Пока есть сайт |
| `users` | Пользователи админки, роль установки: `owner` или `member` | Пока не удалили |
| `sessions`, `accounts`, `verifications` | Таблицы Better Auth: сессии, пароли (хешем), токены сброса (хешем) | По срокам Better Auth |
| `site_members` | Роль участника на сайте: `editor` или `client` | Пока участник на сайте |
| `pages` | Адрес (`slug`), черновик (`draft`, `title`) и опубликованная версия (`published`, `published_title`) | Пока есть страница |
| `page_revisions` | Снимок при каждой публикации: номер версии, заголовок, блоки, кто опубликовал (пользователь или токен) и когда | Не переписывается и не чистится |
| `media` | Картинки сайта: исходное имя, тип, размеры, вес, варианты (JSON), кто и когда загрузил. Файлы — в хранилище по ключу из id | Пока не удалили |
| `leads` | Заявки с форм: страница, блок, заголовок формы, поля с подписями, их размер (`data_bytes`), согласие (текст, политика, версия страницы, время), статус `new` / `processed` | `lead_retention_days` сайта: от 7 до 1825 дней, по умолчанию 180 |
| `mail_outbox` | Очередь писем: шаблон, данные, кому, статус, попытки, аренда обработчика, последняя ошибка | Данные письма — до отправки; само письмо — `MAIL_RETENTION_DAYS` |
| `mail_settings` | SMTP из админки: сервер, порт, шифрование, логин, пароль (только зашифрованным), отправитель, когда прошла проверка | Пока не сменили |
| `user_invitations` | Приглашения: хеш токена, почта, сайт, роль, кто пригласил и кто принял, срок 7 дней | Закрытые — `MAIL_RETENTION_DAYS` после закрытия |
| `api_tokens` | Токены MCP: SHA-256 токена, сайт, кто выпустил, когда пользовались, отзыв | Пока не удалили |
| `site_builds` | Сборки сайта на сервере: состояние `queued` / `running` / `succeeded` / `failed`, папка версии, причина сбоя, пиковая память | Последние 20 на сайт |

## Что держит сама база

Правило, которое нельзя нарушить, проверяет база (`CHECK`, уникальный индекс), а не только код:

- у страницы опубликованное содержимое и его заголовок заполнены вместе — половинчатой публикации
  нет;
- `slug` уникален на сайте; номер версии в истории — больше нуля и уникален у страницы;
- у картинки и версии страницы автор — пользователь **или** токен, не оба;
- роли — только из списка; почта в приглашении — в нижнем регистре; у адреса на сайте одно открытое
  приглашение;
- порт и шифрование SMTP — только 465 с TLS или 587 со STARTTLS, пароль — в формате записи
  `SecretBox`; строка с `site_id` NULL (на всю установку) — одна;
- у сайта не больше одной ждущей сборки;
- данные отправленного письма стёрты.

## Персональные данные

- **IP посетителя не храним** нигде: он только ключ счётчика лимита в памяти.
- Заявки и письма о них связаны (`mail_outbox.lead_id`, `ON DELETE CASCADE`): удалили заявку —
  удалились и её письма.
- Удаляет по сроку обработчик почтовой очереди (`cleanupAlso`): заявки, закрытые приглашения и
  старые письма. Отдельного планировщика нет.

Подробнее о хранении — [Персональные данные](/averra-cms/install/personal-data/).
