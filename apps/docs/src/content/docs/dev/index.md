Для разработчика. После страницы у вас локально работают API, админка и рендерер, вы вошли
владельцем и понимаете, почему так нельзя запускать на сервере.

## Что нужно

- **pnpm 12.** Node под проект ставить не нужно: версия закреплена в `devEngines.runtime`
  (Node 24 LTS), pnpm скачает её сам и запускает на ней все скрипты, какая бы Node ни стояла
  глобально. Чтобы запустить сам pnpm, хватит любой Node ≥ 18 с corepack: `corepack pnpm …`.
- Docker и PostgreSQL не нужны: база в разработке — встроенный PGlite.

```bash
pnpm install
pnpm dev
```

| Что | Адрес |
|---|---|
| API | `http://localhost:4000/api/health` |
| Админка | `http://localhost:5173` |
| Рендерер (сайт) | `http://localhost:4321` |
| Документация (`pnpm docs:dev`, отдельно) | `http://localhost:4330/averra-cms/` |

## Первый вход

Регистрации нет. Владелец появляется одним из способов:

- **Из `.env`.** Скопируйте `apps/api/.env.example` в `apps/api/.env`. В пустой базе API при старте
  создаст владельца из `DEV_OWNER_EMAIL` / `DEV_OWNER_PASSWORD` (в примере — учебные значения) и
  демо-сайт.
- **Командой** — так же, как на сервере: `pnpm user:create --email anna@example.ru --name "Анна"`.
  Пароль команда спросит скрыто, дважды, или возьмёт из `CMS_USER_PASSWORD`.

Одна установка — один сайт ([почему](/averra-cms/decisions/single-site/)), и в разработке тоже:
демо-сайт и есть сайт установки, его id в свежей базе всегда
`d0000000-0000-4000-8000-000000000001`. Админка открывается сразу на его обзоре, без выбора сайта.
В старой базе разработки, где сайтов несколько, сайт установки — созданный первым: остальные
сохранены, но в админке не видны. API пишет об этом строку при старте, а обзор — заметку владельцу.

## Какой сайт показывает рендерер

Рендерер показывает сайт установки: снимок без id отдаёт открытый `GET /api/site/snapshot`. Как на
сервере, у него есть `robots.txt`, `sitemap.xml`, страница 404 на любой несуществующий адрес (и по
своему адресу `/404` — для этого в dev у неё отдельный маршрут) и редиректы из раздела «SEO».
`CMS_SITE_ID` (`apps/renderer/.env`, шаблон — `.env.example`) нужен, только чтобы показать другой
сайт старой базы; при публикации на сервере его ставит сборщику сам API. Для `pnpm build` нужен
запущенный API (`pnpm dev` в соседнем терминале): без него сборка рендерера остановится с понятной
ошибкой.

В `pnpm dev` рендерер собирает страницу на каждый запрос, поэтому опубликованная правка видна
после обновления страницы, без пересборки. При сборке снимок, наоборот, берётся один раз на все
маршруты (`oncePerBuild` в `apps/renderer/src/lib`): страницы, карточки `/og/*.png` и
`sitemap.xml` одной версии сайта, даже если публикация пришлась на середину сборки. Главная
открывается только по корню, `/index` — 404.
Строку Astro «getStaticPaths() ignored in dynamic page…» в логе так и задумано: маршрут статический
только при сборке.

## Учебный режим

Без своего `AUTH_SECRET` API подписывает cookie учебным секретом, который лежит в репозитории.
Поэтому так API запускается только в **учебном режиме**, и только когда выполнены все условия:

- флаг `--dev` — его ставит `pnpm dev` (и e2e), а `pnpm --filter @averra/api start` не ставит;
- `NODE_ENV` не `production`;
- `ADMIN_URL` и `API_URL`, если заданы, указывают на этот компьютер (`localhost`, `*.localhost`,
  `127.x.x.x`, `[::1]`).

Только в учебном режиме API заводит демо-сайт и владельца из `DEV_OWNER_*`, пишет письма в
файловый ящик и берёт учебный ключ шифрования SMTP. Вдобавок на учебном секрете он отвечает
только на запросы к `localhost` с этого компьютера.

Без этих условий API без `AUTH_SECRET` не стартует и объясняет почему. Учебный секрет, вписанный
руками, вне учебного режима не примет — как и его варианты. Флаг пишется ровно `--dev`: опечатка —
ошибка. **`pnpm dev` на сервере не запускайте:** прокси вроде nginx, который подменяет `Host`,
обходит проверку localhost. Для сервера — [установка](/averra-cms/install/server/) или `start` со
своими переменными. Почему так — [Учебный режим только явно](/averra-cms/decisions/dev-mode/).

Команды терминала (`pnpm user:create` и другие) сеть не слушают и работают на свежем клоне без
`AUTH_SECRET`.

## Встроенная база и команды

PGlite — один процесс. Пока запущен `pnpm dev`, команды, которым нужна база (`user:*`, `member:*`,
`token:*`), откажутся работать и попросят его остановить: API и команды держат файл-замок
`apps/api/.data/pglite.lock`. Замок от упавшего процесса снимается сам. На Windows pid быстро
переиспользуются, и замок упавшего API может достаться чужому живому процессу: тогда сообщение
покажет путь к файлу — если `pnpm dev` не запущен, удалите его.

С PostgreSQL (`DATABASE_URL`) команды работают и при запущенном API.

## Почта в разработке

Без SMTP письма не уходят наружу, а ложатся в `apps/api/.data/mail` парами файлов: `.eml`
открывается почтовым клиентом, `.json` — тема, адреса, текст и HTML. SMTP можно настроить и в
разработке, но настоящий пароль от почты под учебным ключом не вводите: страница «Почта»
предупредит.

## Публикация в разработке

Без `PUBLISH_DIR` публикация только меняет базу, а сайт показывает рендерер из API. Чтобы
проверить сборку как на сервере, задайте `PUBLISH_DIR=.data/sites` в `apps/api/.env`: сайт
соберётся в `apps/api/.data/sites/<сайт>/releases/…`, а ссылка `main` рядом будет вести на папку
сайта установки — так её отдаёт Caddy на сервере.

## Прочее

- Astro по умолчанию шлёт анонимную телеметрию. Выключить:
  `pnpm --filter @averra/renderer exec astro telemetry disable`.
- Прод-сборка API без Docker: `pnpm --filter @averra/api build`, запуск —
  `pnpm --filter @averra/api start:prod` (`node --enable-source-maps dist/server/index.js`).
