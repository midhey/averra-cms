Для студии и разработчика. После страницы вы будете знать, как разложить готовый сайт на возможности
Averra, что при переносе неизбежно теряется и как сделать перенос повторяемым скриптом. Пример —
`examples/le-english`: одностраничник репетитора с рукописным дизайном, свой Node-сервис и
мини-админка. Его
[README](https://github.com/midhey/averra-cms/blob/master/examples/le-english/README.md) —
пошаговая инструкция и таблица отличий.

## Как разложить сайт

| В исходном сайте | На Averra | Почему |
|---|---|---|
| Секция страницы со своими полями в админке | **Свой блок**: поля как в старой админке, шаблон Liquid, CSS | клиент правит те же поля, вид секции остаётся её — [Свои блоки](/averra-cms/dev/custom-blocks/) |
| Цвета, шрифты, скругления | **Тема** сайта | один источник для всех блоков; Averra проверяет контраст — [Тема сайта](/averra-cms/admin/theme/) |
| Рукописный или декоративный шрифт | **Акцентный шрифт** темы (`--font-accent`) | третий шрифт теме нужен не только этому сайту; без него подписи рисовались бы системным `cursive` |
| Шапка, меню, подвал | **Встроенные** шапка и подвал | меню ведёт на блоки страницы по id, публикация проверяет ссылки — [Шапка](/averra-cms/admin/header/) |
| Форма заявки | Встроенный блок **«Форма»** на отдельной странице | `<form>` в шаблоне своего блока запрещён: заявки принимает опубликованная страница — с защитой от спама, согласием и уведомлениями. Так же без JavaScript — [Заявки](/averra-cms/admin/leads/) |
| Политика и согласие | **Шаблон** документов Averra | реквизиты и включённые сервисы подставляются сами; текст проверяет юрист — [Cookie и согласие](/averra-cms/admin/cookies/) |
| Старые адреса | **Редиректы** в «SEO» | поисковики и закладки не теряются |
| Фото | **Медиатека** | AVIF/WebP с набором размеров |
| JavaScript-улучшения | CSS-замена или потеря | блоки работают без скриптов |

## Правила переноса

1. **Одна секция — один блок.** Поля повторяют старую схему (ключи в нижнем регистре:
   `photoCaption` → `photo_caption`; список строк — повторитель с одним полем `text`). Необязательное
   поле — обёрнуто в `{% if %}`: блок выглядит правильно и без него. Заголовки с выделенными
   словами — фильтр `accent` (`*слова*` → `<em>`).
2. **Цвета.** Всё, что есть в теме (фон, поверхность, текст, акцент, приглушённый), — роли.
   Остальное (цвет наклейки, маркер) — переменные в начале CSS блока: редактор предупредит «цвет
   задан напрямую», это совет, а не ошибка. Не выдумывайте роли ради тишины предупреждений.
3. **Скрипты — в CSS или в потерю.** Переворот карточки — скрытый флажок и `:checked`; раскрытие —
   `<details>`; анимации — только при `prefers-reduced-motion: no-preference`. Новую возможность
   CSS проверяйте по caniuse с учётом аудитории в России (старые iOS): у `color-mix()` и вложенных
   правил поддержка не полная — нужен запасной вариант под `@supports`.
4. **Мобильная раскладка — первой.** 375 px без горизонтальной прокрутки, кнопки от 44 px. Снимки
   оригинала и переноса на 1440 и 375 px — `compare/shoot.mjs`; расхождения выписывайте в README
   с причиной.
5. **Файл выгрузки — из исходников.** Блоки лежат папками (`block.json`, `template.liquid`,
   `style.css`), файл `averra.custom-blocks` собирает `build-blocks.ts` и проверяет движок: тест
   следит, чтобы файл не отстал от исходников и в нём не было ошибок.
6. **Импорт — только через API**, от имени владельца: блоки, тема, настройки, страницы, шапка и
   подвал проходят те же проверки, что в админке. Повторный запуск безопасен: настройки
   дополняются, а не затираются, кривые параметры отвергаются до первых изменений. Документы
   (политика, согласие) скрипт не публикует: это решение клиента и юриста. Поэтому и страницу с
   формой он публикует, только когда документы уже опубликованы: форма собирает персональные
   данные, и без документов её ссылки на политику и согласие вели бы на 404.

## Живой сайт клиента

Контент — не файл по умолчанию, а то, что клиент насобирал в старой админке: на сервере исходного
сайта это `data/content.json` и `public/uploads/`. Скрипт принимает оба вида записи (`{ version,
content }` и сам контент). Заявки старого сайта — персональные данные: переносите их отдельно и
только с согласия клиента.

## Чем помогает нейронка

Если владелец включил токену право на черновики блоков
([Токены](/averra-cms/mcp/tokens/)), нейронка берёт на себя рутину: читает старую вёрстку,
пишет определение блока, проверяет его (`check_custom_block`) и правит по замечаниям — а
опубликует блок человек. Инструкция «как писать свой блок» приходит вместе со списком блоков
([Инструменты](/averra-cms/mcp/tools/#свои-блоки-четыре-инструмента)).
