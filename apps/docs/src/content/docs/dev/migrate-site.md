Для студии и разработчика. После страницы вы будете знать, как разложить готовый сайт на возможности
Averra, как повторить его вид и поведение до совпадения с оригиналом, что всё-таки остаётся другим
и как сделать перенос повторяемым скриптом, который не стирает правки клиента. Пример —
`examples/le-english`: одностраничник репетитора с рукописным дизайном, свой Node-сервис и
мини-админка. Его
[README](https://github.com/midhey/averra-cms/blob/master/examples/le-english/README.md) —
пошаговая инструкция и таблица оставшихся отличий с причинами.

## Как разложить сайт

| В исходном сайте | На Averra | Почему |
|---|---|---|
| Секция страницы со своими полями в админке | **Свой блок**: поля как в старой админке, шаблон Liquid, CSS | клиент правит те же поля, вид секции остаётся её — [Свои блоки](/averra-cms/dev/custom-blocks/) |
| Цвета, шрифты, скругления | **Тема** сайта | один источник для всех блоков; Averra проверяет контраст — [Тема сайта](/averra-cms/admin/theme/) |
| Рукописный, моноширинный шрифт, фон-текстура, `theme-color`, цвет фокуса | **Акцентный и моноширинный шрифты**, **фон-картинка**, **цвет строки браузера**, **кольцо фокуса** темы | `--font-accent`, `--font-mono`, `background` (узор из медиатеки), `browserColor`, `focus` |
| Шапка и подвал со своей вёрсткой | **Свои шапка и подвал** (свой блок с местом «шапка» / «подвал») или стандартные с настройками | меню, кнопку и логотип клиент правит в «Шапке и подвале», шаблон получает их данными — [Шапка и подвал](/averra-cms/dev/custom-blocks/#шапка-и-подвал) |
| Форма заявки | Встроенный блок **«Форма»** на отдельной странице | `<form>` в шаблоне своего блока запрещён: заявки принимает опубликованная страница — с защитой от спама, согласием, проверкой контакта по каналу и уведомлениями. Так же без JavaScript — [Заявки](/averra-cms/admin/leads/) |
| Форма во всплывающем окне | Страница с формой и настройкой **«Окно»**, кнопки — с «Открывать в окне» | с JS — окно поверх страницы, без JS и Ctrl-кликом — переход на страницу — [Окна и поведения](/averra-cms/decisions/windows-behaviors/) |
| Анимации на JS: появление при прокрутке, рисование линий, плавное раскрытие | **Поведения** Averra: атрибуты `data-av-reveal`, `data-av-draw`, `data-av-hint`, `data-av-details` | один маленький скрипт Averra, `prefers-reduced-motion` и сайт без JS — уже учтены |
| Своё взаимодействие (перетаскивание, подсказки формы) | **Скрипт блока** или **скрипт сайта** — файлом, под CSP | улучшение поверх рабочего HTML — [Свой JS на сайте](/averra-cms/decisions/custom-js/) |
| Политика и согласие | **Шаблон** документов Averra | реквизиты и включённые сервисы подставляются сами; текст проверяет юрист — [Cookie и согласие](/averra-cms/admin/cookies/) |
| Старые адреса | **Редиректы** в «SEO» | поисковики и закладки не теряются |
| Фото | **Медиатека** | AVIF/WebP с набором размеров |
| `og:title`, `og:description`, `og:image:alt` | **Поля для соцсетей** в SEO страницы | превью ссылки в мессенджерах — как у оригинала |

## Правила переноса

1. **Одна секция — один блок.** Поля повторяют старую схему (ключи в нижнем регистре:
   `photoCaption` → `photo_caption`; список строк — повторитель с одним полем `text`). Необязательное
   поле — обёрнуто в `{% if %}`: блок выглядит правильно и без него. Заголовки с выделенными
   словами — фильтр `accent` (`*слова*` → `<em>`).
2. **Цвета.** Всё, что есть в теме (фон, поверхность, текст, акцент, приглушённый), — роли.
   Остальное (цвет наклейки, маркер) — переменные в начале CSS блока: редактор предупредит «цвет
   задан напрямую», это совет, а не ошибка. Не выдумывайте роли ради тишины предупреждений.
   Шрифты — тоже из темы: `var(--font-accent)`, `var(--font-mono)`, а не стек вроде
   `ui-monospace, "JetBrains Mono", …` — в Safari и на macOS `ui-monospace` есть всегда (SF Mono),
   и шрифт темы там не применится никогда.
3. **Отступы секций — свои.** Правило рамки секции Averra той же специфичности, что `:scope`, поэтому
   отступы секции оригинала пишите в `:scope[data-custom-block] { padding: … }` — иначе на телефоне
   останутся поля Averra. По той же причине абзацам, которые у оригинала переносятся обычно, верните
   `text-wrap: wrap` (у Averra по умолчанию `pretty`).
4. **Сначала без JS.** Блок работает без скриптов: переворот карточки — скрытый флажок и `:checked`,
   раскрытие — `<details>`, анимации CSS — только при `prefers-reduced-motion: no-preference`.
   Потом поверх — поведения Averra с параметрами оригинала в переменных `--av-*` (длительность,
   подъём, лесенка через `--av-reveal-delay` по `:nth-child`, наклон через `--av-reveal-from`). То,
   чего поведения не умеют, — скрипт блока: он получает корни блока и только улучшает (кнопку,
   которая без JS ничего не сделает, вставляет сам скрипт). Новую возможность CSS проверяйте по
   caniuse с учётом аудитории в России (старые iOS): у `color-mix()` и вложенных правил поддержка не
   полная — нужен запасной вариант под `@supports`.
5. **Шапка и подвал — своим видом, если настроек не хватает.** Вёрстка оригинала — в шаблоне места,
   а то, что клиент правит (меню, кнопка, логотип), — данными `site.*`; подписи, которых у
   стандартной шапки нет, — поля вида. Ссылки на документы шаблон подвала может вывести сам
   (`site.legal.*`): тогда строка документов Averra их не повторяет. Стандартная шапка с
   настройками остаётся запасной — Averra покажет её, если свой вид вывести нельзя.
6. **Форма в окне.** Страница с формой — окно (`content.window`), её кнопки — `window: true`, в
   шаблонах — `{% if button.window %} data-av-window{% endif %}`. Вид окна (бумажная карточка,
   кнопка-«таблетка») — CSS окон темы: у встроенной формы селекторы — по элементам и атрибутам
   (`input`, `select`, `button[type="submit"]`, `[data-form-box]`), классы встроенных блоков
   меняются от сборки к сборке. Поведение формы оригинала (подпись поля по выбранному каналу,
   «Спасибо, <имя>!») — скрипт сайта; без него форма та же и проверяется сервером.
7. **Мобильная раскладка — первой.** 375 px без горизонтальной прокрутки, кнопки от 44 px. Снимки
   оригинала и переноса на 1440 и 375 px по частям (секции, шапка закрыта и открыта, наведение,
   открытый вопрос, окно, служебные страницы) — `compare/shoot.mjs`, поведение действием —
   `compare/check.mjs`; оставшиеся расхождения выписывайте в README с причиной.
8. **Файл выгрузки — из исходников.** Блоки лежат папками (`block.json`, `template.liquid`,
   `style.css`, `script.js`), файл `averra.custom-blocks` собирает `build-blocks.ts` и проверяет
   движок: тест следит, чтобы файл не отстал от исходников и в нём не было ошибок.
9. **Импорт — только через API**, от имени владельца: блоки, тема, настройки, страницы, шапка,
   подвал и скрипт сайта проходят те же проверки, что в админке. Кривые параметры отвергаются до
   первых изменений. Документы (политика, согласие) скрипт не публикует: это решение клиента и
   юриста. Поэтому и страницу с формой он публикует, только когда документы уже опубликованы: форма
   собирает персональные данные, и без документов её ссылки на политику и согласие вели бы на 404.
10. **Повторный запуск: вид — от набора, контент — клиента.** Блоки, тема, вид шапки и подвала, окно
    и скрипт сайта обновляются. Страница, которую уже перенёс скрипт (её узнают по блокам
    переноса), остаётся как есть: дописывается только то, что нужно новому виду (флажок окна у
    кнопок записи, настройка «Окно», пустые поля для соцсетей). Тексты шапки и подвала тоже не
    трогаются. Флажок, который клиент снял, остаётся снятым. Чужая страница новой установки
    (демо-главная) заменяется. Вернуть контент из исходного сайта — `--reset-content`. Настройки
    сайта при повторном запуске — тоже клиента: заполняются только пустые поля, соцсети
    объединяются, а не заменяются (с `--reset-content` — снова из исходника). Свой скрипт
    интегратора (не скрипт набора) не трогается.
11. **Документы — после страниц.** Шаблон политики собирается по фактам сайта в момент создания
    (есть ли форма, какие сервисы), поэтому скрипт сначала сохраняет страницы, потом создаёт
    `/privacy` и `/consent`: иначе политика заявила бы «на сайте нет форм». При повторном запуске
    текст человека не трогается, кроме блока с фразой шаблона «нет форм заявок»: он заменяется
    свежим блоком данных из шаблона, остальные блоки, в том числе переписанный раздел про форму,
    остаются. Флаг `--rebuild-documents` заменяет черновики свежим шаблоном целиком. Черновики не
    попадают в историю версий, поэтому перед любой заменой прежний черновик сохраняется в файл
    (`~/.averra/le-english-backup/`, вне репозитория; путь в логе): если связь оборвётся между
    заменой и возвратом текста, правки юриста останутся в файле. У опубликованного документа
    заменяется только черновик, опубликованное остаётся до публикации человеком. Пока
    опубликованная политика говорит «нет форм заявок», скрипт не публикует сайт, а если слов про
    форму просто не нашлось, только предупреждает.
12. **Внешние ссылки — в новой вкладке** (`target="_blank" rel="noopener noreferrer"`): шаблон блока
    сам решает по адресу, что внешнее, а что нет. Ссылки на свои страницы — со слэшем в конце
    (`/zapis/`): без него сервер сайта сначала отвечает редиректом.

## Что остаётся другим

Перенос le-english совпадает с оригиналом по раскладке, шрифтам, бумаге, анимациям, окну записи,
меню телефона и поведению с клавиатуры. Отличия, которые остались, — следствия правил Averra, а не
недоделки: тексты документов — шаблон Averra (реквизиты и сервисы подставляются сами); на
служебных страницах есть подвал (ссылка на политику обязательна на каждой странице); у
страницы `/zapis/` без JS — встроенная форма с подписями над полями (свой CSS встроенным блокам
страницы не положен, вид бумажной карточки — только в окне); нет `FAQPage` из своего блока вопросов
(`<script>` в шаблоне запрещён). Полная таблица — в README набора.

## Живой сайт клиента

Контент — не файл по умолчанию, а то, что клиент насобирал в старой админке: на сервере исходного
сайта это `data/content.json` и `public/uploads/`. Скрипт принимает оба вида записи (`{ version,
content }` и сам контент). Заявки старого сайта — персональные данные: переносите их отдельно и
только с согласия клиента.

## Чем помогает нейронка

Если владелец включил токену право на черновики блоков
([Токены](/averra-cms/mcp/tokens/)), нейронка берёт на себя рутину: читает старую вёрстку,
пишет определение блока, проверяет его (`check_custom_block`) и правит по замечаниям — а
опубликует блок человек. Инструкция «как писать свой блок» приходит вместе со списком блоков
([Инструменты](/averra-cms/mcp/tools/#свои-блоки-четыре-инструмента)).
