Для разработчика. После страницы вы будете знать, где искать схему, почему она одна на все
приложения и как писать новую.

Zod — единственный источник правды о данных. Типы выводятся из схем (`z.infer`), руками не
дублируются. Пакет — `packages/schema` (`@averra/schema`), его импортируют API, админка, рендерер,
MCP, блоки и `deploy`.

## Что в пакете

| Файл | Что |
|---|---|
| `blocks/*`, `define-block.ts` | блоки, их каталог и союз `BlockInstance` |
| `page.ts` | страница (`PageContent`, до 50 блоков), заголовок, адрес, шаблоны, входы API страниц |
| `site.ts`, `theme.ts` | название и новый сайт; тема (цвета `#RRGGBB`, шрифты, скругления) |
| `media.ts` | картинка в блоке (`Image`), форматы и MIME-типы медиатеки |
| `forms.ts` | поля формы и правила для браузера и сервера, лимиты |
| `auth.ts` | имя, пароль, почта, роли, сброс пароля, приглашения |
| `mail.ts`, `mail-settings.ts` | адреса, тема и отправитель письма, настройки SMTP |
| `status.ts`, `publish.ts` | состояние установки, файлы `averra.sh`, сборки |
| `api-error.ts` | формат ошибок API и их описание для людей |
| `id.ts` | `Uuid()` |
| `zod-messages.ts` | русские сообщения Zod |
| `demo.ts` | демо-сайт и демо-страница |

## Правила

- **Схемы входа API** (тела запросов и параметры вроде адреса страницы) лежат здесь: ими же
  проверяют форму админки и вход инструментов MCP. Одна схема — одно сообщение об ошибке везде.
- **Русские сообщения** включает `setupZodMessages()`. Её вызывает при старте каждый процесс,
  который проверяет ввод: админка, API (`index.ts` и `createTestApi`), команды терминала (`run` в
  `cli/common.ts`), MCP, `pnpm fleet`. Новый процесс — тоже.
- **Id во входе — только `Uuid()`**, а не голый `z.uuid()`: он приводит id к строчным. Postgres
  сравнивает uuid без регистра, а код — строки, и один id в двух написаниях их разводит.
- **Адрес страницы:** новую создают только по строгой `PageSlug`, существующую ищут по мягкой
  `ExistingPageSlug` — в базе бывают адреса, созданные до строгой схемы.
- **Списки форматов и типов** (`ImageFormat`, `imageMimeTypes`) берутся отсюда, а обратные
  справочники выводятся из них — не пишите рядом свою копию.
- **Флажок из HTML-формы** — только значение отмеченного флажка (`CHECKED_VALUE`); не прислан или
  пусто — не отмечен, прочее — ошибка. Согласие на обработку персональных данных — только так.
- **Всё, что попадает в заголовки письма**, — `MailAddress`, `MailSubject`, `MailSenderName`,
  `MailLine()`: перевод строки — ошибка, а не тихая чистка. Адрес почты — шаблон
  `MAIL_ADDRESS_PATTERN`, один для письма и для формы на сайте; `z.email()` для адресов писем не
  берём — он не пускает кириллические домены.
- **Данные из базы, которые снова идут в работу** (версия из истории, письмо из очереди,
  опубликованная форма), проверяются нынешней схемой: снимок в базе старый, а схема в коде
  меняется.

## Ошибки

API отвечает в одном формате, по-русски:

```json
{ "error": { "code": "validation", "message": "Данные не прошли проверку", "issues": [{ "path": "slug", "message": "…" }] } }
```

`issues` с путём до поля — у 400 и у 409, которые можно привязать к полю: админка покажет сообщение
прямо у него, а нейронка поймёт, что исправить. Подробно — [API](/averra-cms/dev/api/).
