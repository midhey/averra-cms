Для разработчика. После страницы вы будете знать, что обязательно прогнать перед коммитом, где
писать тест на своё изменение и как не сделать тесты зависимыми друг от друга.

## Перед коммитом

| Команда | Что | Когда |
|---|---|---|
| `pnpm format` | Biome и stylelint с исправлением | всегда |
| `pnpm check` | линтер, типы, все тесты, сборка документации с проверкой ссылок | всегда |
| `pnpm e2e` | сквозные тесты в браузере | если менялись админка, API или рендерер |

`pnpm check` идёт и в CI на каждый push в master и pull request (`.github/workflows/ci.yml`, на
Linux), и перед выпуском образов. e2e в `pnpm check` не входят: он должен оставаться быстрым.

Тест пишем вместе с кодом, а не «потом».

## Юнит и интеграционные (Vitest)

- **API** тестируется через `app.request()` без запуска сервера, с PGlite в памяти:
  `createTestApi()` из `apps/api/src/testing.ts`. Медиатека — своя временная папка у каждого
  экземпляра, её удаляет `close()`. Картинки для тестов рисует sharp прямо в тесте: бинарных файлов
  в репозитории нет.
- **Тесты ходят в API, как настоящие клиенты:** `loginAs('owner' | 'editor' | 'client')` даёт
  заголовки сессии с `Origin` админки, `createToken(siteId)` — токен. Права в обход проверок не
  отключаем.
- **Лимит попыток входа общий на процесс.** Тест, который входит через HTTP, ставит себе свой
  `X-Forwarded-For`; помощники входят серверным вызовом и лимит не тратят.
- **Без общего состояния:** каждый тест создаёт свой экземпляр (фабрикой или в `beforeEach`).
  Проверка — `vitest run --sequence.shuffle` и запуск одного теста через `-t`.
- **Время — параметр** (`now`), а не `now()` базы: тесты двигают часы, а не ждут.
- **SMTP** — настоящий `smtp-server` на свободном порту с сертификатом от тестового CA
  (`src/mail/testing/`), без писем наружу.
- **Драйверы базы** расходятся в сырых запросах, типах и транзакциях. Это проверяет
  `src/db/postgres.test.ts` на настоящем node-postgres через сервер протокола Postgres поверх
  PGlite (`@electric-sql/pglite-socket`) на порту 0. Закрывать по порядку: API (пул), дождаться,
  пока сервер разберёт закрытые соединения, сервер, потом PGlite — иначе его обработчик упадёт
  после тестов.
- **Миграции** — `src/db/migrations-compat.test.ts`: только совместимые вперёд
  ([правила](/averra-cms/dev/conventions/)).

## Скрипты сервера

- `deploy/install.sh` и `deploy/averra.sh` тестируются **настоящим bash** (на Windows — Git Bash) с
  подделками внешних команд (`docker`, `ss`, `getent`, `flock`, `systemctl`…) первыми в PATH:
  подделки пишут, с чем их позвали. PATH ставится внутри bash, а не через окружение Node: Git Bash
  ставит `/usr/bin` вперёд унаследованного.
- Подделка docker (`tests/fake-docker.sh`) ведёт маленький «сервер» — базы как файлы с числом
  миграций, запущенная версия, здоровье, — и тест проверяет решения скрипта по шагам.
- Права `.env` проверяются на всех системах по вызову `chmod 600`, а на Linux — ещё и по режиму
  файла.
- `pnpm fleet` получает исполнителя команд параметром — тесты подменяют ssh.

Docker, Caddy, PostgreSQL и настоящий VPS так не проверить — для них [чек-лист живой
проверки](/averra-cms/install/checklist/).

## Сквозные тесты (Playwright)

Пакет `e2e/` гоняет сценарии в настоящем Chromium: сайты и страницы → редактор → предпросмотр →
сохранение → публикация → сайт. Браузер ставится один раз:
`pnpm --filter @averra/e2e exec playwright install chromium`.

Playwright сам поднимает свои API, админку и рендерер и гасит их в конце:

| Что | Адрес в e2e |
|---|---|
| API | `http://localhost:4100` |
| Админка | `http://localhost:5273` |
| Рендерер | `http://localhost:4421` |
| Тестовый SMTP | 127.0.0.1:2587 (только на время `smtp-settings.spec.ts`) |

- **Рядом с `pnpm dev`.** Порты, база, картинки и файловый ящик e2e свои (`e2e/.data`, стирается
  перед каждым прогоном), рендерер идёт с `astro dev --ignore-lock`. Занят порт — прогон сразу
  падает, а не идёт по чужому серверу.
- **Вход.** API e2e создаёт владельца из `e2eOwner` (`e2e/urls.ts`), проект `setup` входит один раз
  и сохраняет cookie; остальные тесты стартуют вошедшими. Тест, которому нужен вход как таковой или
  другой пользователь, берёт пустой `storageState` и свой `X-Forwarded-For`. Общую сессию «Выйти»
  не завершает.
- **Независимость.** Фикстура (`tests/fixtures.ts`) перед каждым тестом возвращает демо-сайт к
  исходному: главная — демо, других страниц нет. Свои сайты тест называет уникально. Проверка —
  `pnpm e2e --shuffle`.
- **Локаторы — по ролям и подписям** (`getByRole`, `getByLabel`), как видит человек с экранным
  диктором. Нет подписи — сначала чиним доступность. Живых областей `role="status"` бывает
  несколько — ищем статус внутри своего раздела.
- **Посетитель сайта** — свой контекст браузера без входа, с выключенным JavaScript и своим
  `X-Forwarded-For`.
- **Публикация.** API e2e запущен с `PUBLISH_DIR`, каждая публикация собирает демо-сайт настоящим
  Astro (`server-build.spec.ts`).
- **Почта.** Письма — из файлового ящика e2e (`tests/mailbox.ts`). Участника заводит приглашение, а
  не команда: команды не открывают базу, пока запущен API e2e. Тест, который меняет SMTP, удаляет
  настройки в `finally`; к тестовому SMTP API e2e подключается через `DEV_SMTP_CONNECT_PORT` и
  доверяет его CA через `NODE_EXTRA_CA_CERTS`.
- **Что админка прячет от роли** — подменой роли в ответах API (`page.route`), а сами права —
  тестами API.
- **Перетаскивание** — `dragWithMouse` (по шагам, как человек); первую стрелку после подъёма с
  клавиатуры — `firstArrow`: dnd-kit начинает слушать стрелки через тик.

Упавший тест оставляет трассу в `e2e/test-results`, отчёт — `pnpm --filter @averra/e2e exec
playwright show-report`. Строка `[API] … Command failed` в конце прогона на Windows — так
Playwright гасит сервер, это не ошибка.
