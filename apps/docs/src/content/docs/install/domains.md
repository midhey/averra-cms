Для студии. После страницы вы будете знать, что открыто на каждом домене установки, как
продлеваются сертификаты и что проверить, если сайт не открывается.

## Два домена — две роли

| Адрес | Что там |
|---|---|
| `https://<домен сайта>` | опубликованная статика сайта установки из `/srv/sites/main/current`: ссылку `main` на папку сайта ставит API при старте. Из API открыт приём заявок `/api/forms/*` и ответ на адрес без файла — редирект или страница 404 ([ниже](#адрес-без-страницы-редиректы-и-404)) |
| `https://admin.<домен сайта>` | админка (статика) и API под `/api` — один источник, поэтому cookie сессии без CORS |

Других путей API на домене сайта нет. Новый открытый путь сайта в API добавляется осознанно,
строкой в `deploy/Caddyfile`.

## Адрес без страницы: редиректы и 404

Caddy отдаёт файлы текущей версии сайта. Файла по адресу нет (404) — `handle_errors 404` передаёт
запрос в API, `GET /api/site/fallback/<путь>`:

- адрес есть в таблице [редиректов](/averra-cms/admin/seo/#редиректы) раздела «SEO» — 301 на
  «куда». Строку запроса (`?utm_source=…`) `rewrite` в Caddy сохраняет, и API переносит её в
  «куда», если у того своей нет;
- нет — 404 со страницей `404.html` текущей версии сайта (своей или стандартной, её кладёт
  сборка). Сайт ещё не собран — короткая страница «Страница не найдена» от API.

Редиректы живут в базе, а не в Caddyfile: Caddy не перечитывает конфиг, подмена версии сайта
остаётся атомарной, а таблица действует сразу после «Сохранить». Существующий файл главнее
редиректа — про него Caddy API не спрашивает. Если API не отвечает, на адресах без файла будет
502, а страницы сайта отдаются как обычно. Почему так — [SEO и настройки
сайта](/averra-cms/decisions/seo-settings/).

Такие заходы (сканеры `/wp-login.php`, старые ссылки) API не пишет в свой лог построчно: их
слишком много, и это не события API. `/favicon.ico` браузеры у сайта без иконки не просят: в
страницах стоит пустая иконка.

Проверить на сервере: `curl -I https://<домен сайта>/nope` — `404` и HTML страницы 404 сайта;
`curl -I https://<домен сайта>/<откуда>` — `301` и `location`.

## Сертификаты

Caddy выпускает и продлевает сертификаты Let's Encrypt сам: почта — из `--email` установщика
(`ACME_EMAIL`), данные — в томе `caddy_data`. Для этого DNS обоих доменов должен вести на сервер,
а порты 80 и 443 — быть открыты. HTTP перенаправляется на HTTPS.

Не выпускается сертификат — почти всегда это DNS:

- записи ещё не разошлись (от минут до суток);
- у домена есть A или AAAA на чужой адрес — Let's Encrypt проверяет каждый, IPv6 первым;
- `docker compose logs caddy` покажет ответ Let's Encrypt.

## Заголовки и кеш

На обоих доменах — HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy`. У админки ещё
`X-Frame-Options: SAMEORIGIN`: чужой сайт не покажет её в рамке.

| Что | Кеш |
|---|---|
| страницы сайта, `robots.txt`, `sitemap.xml`, иконки, `index.html` админки и её экраны (`/pages`, `/leads`…) | `no-cache`: новая версия видна сразу |
| редирект 301 и страница 404 сайта (ответ API) | `no-cache`: таблицу редиректов могут поправить |
| `/_astro/*`, шрифты темы `/_fonts/*` и картинки `/media/<uuid>/…` сайта | год, `immutable`: у них хеш или uuid в имени |
| `/assets/*` админки | год, `immutable`; нет файла — 404, а не `index.html` |

Страница сайта с адресом `media` (`/media/`) под правило картинок не попадает: оно точное.

## Сменить домен

Запустите установщик ещё раз с новым `--site-domain` (или `--admin-domain`) и прежними
остальными флагами. Он проверит DNS нового имени, запишет его в `.env` и применит. Секреты,
владелец и сайт сохранятся. Ссылки в письмах переедут сами: они ведут на `ADMIN_URL`, а его
compose собирает из `ADMIN_DOMAIN`. Домен в боковой панели админки (`SITE_URL`) compose собирает
из `SITE_DOMAIN` — он тоже обновится. Адрес отправителя писем (`MAIL_FROM` или «Адрес отправителя»
на странице «Почта») от домена установки не зависит — его меняйте сами, если нужно.

## Второй сайт и www

Одна установка — один сайт ([почему](/averra-cms/decisions/single-site/)): второму сайту клиента —
своя установка. Несколько сайтов в одной установке — будущий модуль мультисайта
([дорожная карта](/averra-cms/roadmap/)). `www.` пока добавляется строкой в Caddyfile руками; из
админки это появится позже ([дорожная карта](/averra-cms/roadmap/)). Канонический адрес для
поисковиков задаётся в разделе [«SEO»](/averra-cms/admin/seo/#основное).
