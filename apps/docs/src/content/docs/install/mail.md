Для студии после установки. После страницы письма установки — сброс пароля, приглашения,
уведомления о заявках — будут уходить и не попадать в спам.

## Какие письма шлёт Averra

- сброс пароля и приглашение участника — со ссылкой в админку;
- «Новая заявка» — на адреса уведомлений сайта, по умолчанию всем владельцам;
- «Заявка получена» — посетителю, если он оставил почту и подтверждение включено;
- «Настройки почты изменены» и «Адреса уведомлений о заявках изменены» — владельцам.

Письма уходят не прямо из запроса, а через очередь в базе: упал SMTP — действие не откатывается,
письмо уйдёт позже, с повторами ([почему](/averra-cms/decisions/outbox/)). Без почты Averra
работает, но сброс пароля и приглашения недоступны, а уведомления о заявках не уходят — админка
говорит об этом прямо.

## Где задать SMTP

**В админке — обычный путь.** Страница «Почта» → «Настройки SMTP», только владелец. Пароль SMTP
хранится в базе зашифрованным ключом `MAIL_ENCRYPTION_KEY` из `.env` — его создал установщик.
Менять пароль или провайдера можно без доступа к серверу и без перезапуска.

**В окружении** — если так удобнее студии (`SMTP_HOST` и соседние переменные, на сервере — через
`compose.override.yaml`, см. [Установку](/averra-cms/install/server/)). Окружение главнее
админки: она покажет такой SMTP только для чтения с пометкой «задано на сервере».

Порядок такой: окружение (`SMTP_HOST` или явный `MAIL_TRANSPORT`) → настройки из админки →
почта выключена.

## Настройка в админке

1. Сервер, «Порт и шифрование» (только «465 — TLS сразу» или «587 — STARTTLS»), логин, пароль
   SMTP, адрес и имя отправителя.
2. «Проверить подключение» — проходит шаги DNS, соединение, TLS, вход и отправку проверочного
   письма на указанный адрес и показывает каждый ✓ или ✗ с объяснением.
3. Ваш пароль от админки и «Сохранить». Без успешной проверки — только явной кнопкой «Сохранить
   без проверки».

После сохранения каждому владельцу уходит письмо «Настройки почты изменены» — уже по новым
настройкам, а в лог API пишется, кто и какие поля поменял (без значений).

Правила, о которые можно споткнуться:

- **Соединение только шифрованное**, сертификат сервера проверяется всегда. Выключить проверку
  нечем.
- **Пароль SMTP только на запись.** Админка показывает «задан» или «не читается». Пустое поле при
  сохранении оставляет прежний пароль — но только для того же сервера. Сменили сервер — введите
  пароль заново.
- **Проверка с сохранённым паролем** (поле пустое) работает только с сохранёнными настройками
  целиком и только на почту самого владельца. Поменяли поле — введите пароль SMTP.
- **Проверок — не больше 10 за 15 минут**, неверных паролей владельца — не больше 5 за 15 минут.
- **«Удалить настройки»** (тоже с паролем) возвращает почту к окружению или выключает её.

Почему так строго — [Пароль SMTP и повторный пароль](/averra-cms/decisions/smtp-password/).

## Ключ `MAIL_ENCRYPTION_KEY`

32 случайных байта в base64, отдельно от `AUTH_SECRET`. Установщик создаёт его сам. Храните `.env`
у студии отдельно от бэкапов: украденный бэкап без ключа не раскрывает пароль SMTP.

**Ключ потерян или сменился** — пароль SMTP в базе не расшифровать. API работает, почта
выключается с причиной «введите пароль SMTP заново». Введите пароль на странице «Почта» и
сохраните — он зашифруется новым ключом. Других данных ключ не шифрует.

Сгенерировать ключ руками:

```bash
openssl rand -base64 32
# без openssl:
node -e "console.log(require('node:crypto').randomBytes(32).toString('base64'))"
```

## Провайдер

Берите российского провайдера: в письмах о заявках персональные данные посетителей.

- **Яндекс 360 для бизнеса** — для писем студии и небольших сайтов: SMTP `smtp.yandex.ru`,
  порт 465, логин — адрес ящика, пароль — **пароль приложения**, а не пароль аккаунта. Адрес
  отправителя — тот же ящик или его алиас, иначе сервер ответит «553 Sender address rejected: not
  owned by auth user».
- **Unisender Go** и подобные транзакционные сервисы — если писем много или нужна статистика
  доставки: SMTP с логином и ключом из кабинета.

Подойдёт любой провайдер с SMTP по TLS, если домен адреса отправителя он подтвердил.

## SPF, DKIM и DMARC

Без этих записей письма уходят в спам, а домен легко подделать. Настраиваются один раз на домен
отправителя — у студии и у каждого клиента со своим доменом. Все три — TXT-записи в DNS.

1. **SPF** — кто вправе слать письма от домена. Одна запись на самом домене (`@`). Для Яндекс 360:
   `v=spf1 redirect=_spf.yandex.net`. Несколько сервисов — их `include:` в **одну** запись:
   `v=spf1 include:<первый> include:<второй> ~all`. Вторая запись `v=spf1` ломает обе.
2. **DKIM** — подпись писем ключом домена. Ключ генерирует провайдер (в Яндекс 360 — «Почта →
   DKIM-подпись»), в DNS кладётся открытая часть: запись `<селектор>._domainkey` (у Яндекса —
   `mail._domainkey`) со значением `v=DKIM1; k=rsa; p=…`. Копируйте значение целиком.
3. **DMARC** — что делать с письмами, не прошедшими проверки, и куда слать отчёты. Запись `_dmarc`:
   начните с `v=DMARC1; p=none; rua=mailto:dmarc@example.ru`, через пару недель без чужих
   отправителей в отчётах — `p=quarantine`, потом `p=reject`.

Проверка:

- записи видны в DNS: `nslookup -type=TXT example.ru`, `nslookup -type=TXT
  mail._domainkey.example.ru`, `nslookup -type=TXT _dmarc.example.ru` (или `dig TXT … +short`);
- отправьте себе проверочное письмо на Gmail или Яндекс («Проверить подключение») и откройте
  оригинал письма: в `Authentication-Results` — `spf=pass`, `dkim=pass`, `dmarc=pass`, а домен в
  `header.d=` тот же, что в `From`.

## Если письма не уходят

- **Страница «Почта»**: состояние почты, очередь писем с ошибкой последней попытки и кнопкой
  «Повторить», предпросмотр каждого шаблона.
- **Повторы**: до 8 попыток с паузой 1, 3, 9, 27… минут, не больше 6 часов — около 12 часов на всё.
  Сервер не пускает (вход, TLS, недоступен) или отказал адресу отправителя — обработчик не жжёт
  попытки писем, а выжидает до 30 минут; «Повторить» и сохранение настроек будят его сразу.
  Окончательно не уходит только письмо, которому сервер отказал в адресе получателя или в самом
  письме.
- **Письма со ссылкой** (сброс, приглашение) не повторяются после окончательной неудачи и истечения
  ссылки: человек запрашивает новую.
- **Ссылка ведёт на localhost** — на сервере не задан `ADMIN_URL`. API предупреждает в логе и на
  странице «Почта». На установке из `install.sh` этого не бывает.
- **«Состояние установки»** покажет «Письма не уходят», если письмо с ошибкой ждёт в очереди
  дольше 15 минут.

Письма живут в очереди `MAIL_RETENTION_DAYS` дней (по умолчанию 30), данные письма — только до
отправки. Подробно — [Персональные данные](/averra-cms/install/personal-data/).

## Проверка из терминала

`pnpm mail:test --to <адрес>` (на сервере — `docker compose exec api node dist/server/mail-test.js
--to <адрес>`) шлёт письмо «Проверка почты» напрямую, мимо очереди, и печатает шаги: DNS,
соединение, TLS, вход, отправка. Сломанный шаг — с объяснением и ответом сервера, пароль не
печатается. Команда проверяет **только SMTP из окружения**: базу она не открывает. SMTP из админки
проверяет кнопка «Проверить подключение» — шаги там те же.
