Для студии и клиента, который отвечает за персональные данные посетителей. После страницы вы
будете знать, что хранит установка, сколько и что указать в политике обработки персональных
данных.

Клиент — оператор персональных данных своих посетителей. Averra помогает выполнить требования, но
политику обработки, договор с хостингом и прочие документы клиент готовит сам.

## Что хранится

| Данные | Где | Сколько |
|---|---|---|
| Заявки с форм: поля, согласие (текст, ссылка на политику, версия страницы, время) | база | срок сайта: по умолчанию 180 дней, от 7 до 1825 |
| Письма о заявках и других событиях | очередь писем в базе | `MAIL_RETENTION_DAYS`, по умолчанию 30 дней. Данные письма (у письма о заявке — поля посетителя) — до отправки; у письма, которое так и не ушло, — до удаления по `MAIL_RETENTION_DAYS`, чтобы его можно было повторить. Приглашение и сброс пароля свои данные теряют сразу, как только окончательно не ушли |
| Закрытые приглашения (адрес человека) | база | `MAIL_RETENTION_DAYS` после закрытия |
| Пользователи админки (имя, почта) | база | пока пользователь есть |
| Бэкапы | `/opt/averra/backups` и внешнее хранилище | `BACKUP_KEEP` дней, по умолчанию 7 |

**IP посетителей не хранится.** Для лимитов он живёт только в памяти процесса и забывается через
окно лимита. В базу и в лог не пишется.

## Удаление

- Заявки старше срока сайта удаляются автоматически, раз в час. Срок — «Настройки сайта» →
  «Заявки».
- Заявку можно удалить руками в разделе «Заявки» (например, по просьбе посетителя). Вместе с ней
  удаляются и письма о ней, в том числе неотправленные.
- Из бэкапов удалённая заявка уходит не позже чем через `BACKUP_KEEP` дней плюс сутки до
  следующего бэкапа.

**Обещание про бэкапы держится, если:**

- сервер включён и таймер бэкапов работает;
- внешнее хранилище даёт удалять — сбой чистки виден в «Состоянии установки»;
- обновление не брошено оборванным — его бэкап `pre-update` и отложенная база хранятся, пока
  `averra.sh update` его не доведёт;
- рабочая база на месте — после неудачного отката служебные базы не удаляются, пока человек не
  вернёт рабочую.

Служебные базы с копиями данных (`averra_rolled_back_…`, `averra_failed_restore_…`) удаляются по
тому же сроку, а пока лежат — видны в «Состоянии установки». `averra_before_restore` — рабочие
данные, по сроку не удаляется: её разбирают руками.

## Что написать в политике клиента

Срок хранения заявок — **срок сайта + `BACKUP_KEEP` дней** (по умолчанию 180 + 7). Место хранения —
сервер клиента; для клиентов из России сервер и внешнее хранилище бэкапов — в России (например,
Yandex Object Storage, регион `ru-central1`). Копия во внешнем хранилище зашифрована ключом,
которого у хранилища нет.

## Согласие

Форма заявки не отправляется без согласия на обработку персональных данных. Засчитывается только
отмеченный флажок, а ссылка на политику — обязательное поле блока: форму без неё не сохранить и не
опубликовать. Подробно — [Заявки](/averra-cms/admin/leads/).

## Кто видит заявки

Владелец и клиент сайта. Редактор и нейронка (токен MCP) — никогда. Полная выгрузка данных сайта
(в ней заявки) — тоже только владельцу и клиенту. Обращайтесь с выгрузкой как с заявками.

## Письма

- Провайдер почты — российский: в письмах о заявках поля посетителя.
- Подтверждение посетителю — фиксированный текст без его данных, не чаще раза в сутки на ящик.
- Сменились получатели уведомлений (адрес почты, чат Telegram) — об этом узнают все владельцы
  и прежние получатели: заявки нельзя молча перенаправить.

## Telegram

- Уведомление о заявке в Telegram несёт её поля, а Telegram — иностранный сервис: это
  трансграничная передача персональных данных. Решает клиент как оператор: впишите Telegram
  в политику конфиденциальности и уведомление Роскомнадзора — или оставьте в Telegram только
  служебные события, а заявки — почтой.
- Данные сообщения в очереди стираются, как только оно ушло или окончательно не ушло; уведомления
  о заявке удаляются вместе с ней. Что уже пришло в чат, Averra удалить не может — это решают
  участники чата.
- В базе — только chat id и название чата; токен бота — зашифрованным.
