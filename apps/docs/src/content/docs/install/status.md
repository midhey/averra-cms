Для студии и владельца установки. После страницы вы будете знать, где увидеть, что с установкой
не так, и что делать с каждой проблемой.

## Где смотреть

- **В админке** — экран «Состояние» (только владелец, пункт в блоке «Установка» боковой панели).
  Кнопка «Проверить снова» собирает его заново.
- **На сервере** — `sudo /opt/averra/averra.sh status` (или `--json`). Работает и когда API лежит:
  тогда скрипт скажет «API не отвечает» и покажет бэкапы и обновление из своих файлов, а у
  внешней базы — оборванное или неудачное восстановление и страховочные дампы
  (`"restore"`, `"restoreLast"`, `"keptDumps"` в `--json`).
- **Все установки студии** — [`pnpm fleet status`](/averra-cms/install/fleet/).

## Что показывает

- версию (её видно и в боковой панели админки);
- базу: своя или внешняя (`--external-db`), отвечает ли, сколько миграций, какие служебные базы
  или страховочные дампы внешней базы с копиями данных лежат на сервере. У внешней базы
  `averra.sh status` без API тоже проверяет, отвечает ли она (`"database":"external","dbUp":…` в
  `--json`), и итог последнего восстановления внешней базы;
- последний бэкап и последний удачный: когда, проверен ли, ушла ли копия во внешнее хранилище;
- последнее обновление: с какой версии на какую и чем кончилось;
- раздел «Обновление»: установленная и доступная версии, заметки к релизу, когда сервер последний
  раз проверял новые версии, кнопка «Обновить до …», ход обновления по шагам и итог
  ([Обновить из админки](/averra-cms/install/updates/#обновить-из-админки));
- публикацию: последнюю сборку и сколько сайтов с упавшей сборкой;
- почту: включена ли, сколько писем не ушло за неделю, сколько ждёт и сколько с ошибкой;
- место на диске;
- **проблемы** — список того, на что смотреть, от самого срочного.

Адресов, путей, логинов и секретов в состоянии нет, версии нет в открытых маршрутах.

## Проблемы и что делать

| Проблема | Что делать |
|---|---|
| База не отвечает | `docker compose ps`, `docker compose logs postgres` |
| Внешняя база не отвечает | сервер базы у провайдера, доступ с IP сервера и сеть; `averra.sh status` проверит соединение |
| Удачных бэкапов ещё не было | `averra.sh backup`; проверить таймер `systemctl list-timers averra-backup.timer` |
| Последний удачный бэкап — больше 48 часов назад | таймер не работает или бэкапы падают: `journalctl -u averra-backup` |
| Последний бэкап не удался | причина — в тексте проблемы; повторить `averra.sh backup` |
| Копия не выгрузилась во внешнее хранилище | проверить `BACKUP_S3_*` в `.env` и права ключа |
| Старые копии во внешнем хранилище не удалились | ключу нужно право на удаление: иначе нарушается срок хранения |
| Файл состояния бэкапов или обновления не читается | файл битый или записан более новым `averra.sh`: обновите установку |
| Обновление не прошло проверку — вернулась прежняя версия | см. `/opt/averra/update.log`, почему новая версия не встала |
| Откат не удался | нужен человек на сервере: подсказка — в выводе `averra.sh update` и `update.log` |
| Данные после отката сохранены в базе `averra_rolled_back_…` | перенести нужное (заявки); база удалится со старыми бэкапами |
| Обновление не закончилось за час | повторить `averra.sh update --version <та же>` — доведёт или откатит |
| На сервере служебные базы с копиями данных | с временем в имени удалятся сами; `averra_before_restore` разобрать и удалить руками |
| Данные после отката сохранены в страховочном дампе `rolled-back-…` | внешняя база: перенести нужное из дампа; удалится со старыми бэкапами |
| Восстановление базы не закончилось | внешняя база: восстановление оборвалось — `averra.sh status` на сервере скажет, на каком шаге; вернуть прежнюю базу — `averra.sh restore-dump <страховочный дамп>`, оставить как есть — `averra.sh restore-dump --dismiss` ([Бэкапы](/averra-cms/install/backups/#внешняя-база)). Страховочный дамп уже удалён сроком хранения — так и написано: прежнюю базу вернёт только бэкап |
| Восстановление базы не удалось | внешняя база: причина — в тексте проблемы и выводе `averra.sh restore`; база прежняя, если не сказано иное. Проблема видна неделю |
| В папке бэкапов страховочные дампы `before-restore-…` | восстановление внешней базы прервалось или не удалось: если база не та — `averra.sh restore-dump <файл>` ([Бэкапы](/averra-cms/install/backups/#внешняя-база)); иначе удалятся сами |
| Почта выключена | задать SMTP на странице «Почта» ([Почта](/averra-cms/install/mail/)) |
| Письма не уходят | письмо с ошибкой ждёт дольше 15 минут: проверить настройки на странице «Почта» |
| Писем не ушло за неделю | открыть очередь на странице «Почта»: причина у каждого письма |
| Сайтов с упавшей сборкой | «Настройки сайта» → «Сайт на сервере»: причина и «Собрать заново» |
| Мало места | меньше 1 ГБ или 10 % свободно: почистить диск, уменьшить `BACKUP_KEEP` или расширить диск |

Проблема с откатом обновления показывается неделю, дальше это история.

## Раздел «Обновление»

| Что видно | Что делать |
|---|---|
| «работает только на сервере, установленном install.sh» | хостовой части нет (разработка или сервер без `install.sh`): обновлять по SSH. На сервере — `averra.sh install-units` |
| «выключено на сервере (ADMIN_UPDATE=off)» | так решила студия: обновление — по SSH |
| «заявки из админки некому забирать» | нет systemd или path-юнит заявок выключен или упал: `systemctl status averra-update-request.path`, `averra.sh install-units` (на сервере с systemd) или обновление по SSH |
| «требует шага на сервере» | ломающий релиз (BREAKING CHANGES у новой или пропущенной версии, или установка отстала больше чем на 30 релизов): студия делает шаг и обновляет по SSH |
| «закончилось неудачным откатом» | нужен человек на сервере (`averra.sh status`, `update.log`); дальше — обновление по SSH |
| «уже не прошло и откатилось» | обновление до этой версии уже откатилось: студия смотрит `update.log`, устраняет причину и обновляет по SSH; из админки — со следующей версией |
| «Проверка новых версий выключена на сервере» | `UPDATE_SOURCE=off` в `.env`: так решила студия |
| «у API нет папки заявок» | `averra.sh install-units` (создаст `/opt/averra/requests` с владельцем uid 1000) или обновление по SSH |
| «Проверка новых версий не удалась» | нет сети или источник недоступен; «образы версии … в реестре не найдены или реестр не ответил» — релиз вышел минуты назад, его сборка (`release.yml`) упала или нет связи с ghcr.io. Повторить — `averra.sh check-update` |
| «Сервер отклонил заявку» | причина — в тексте и в `update.log`; обычно за время между проверкой и нажатием вышла другая версия — обновите страницу |
| «Заявка отправлена» дольше минуты, через 10 минут — «Заявка не дошла до сервера» | служба заявок не работает (новая заявка заменит старую): `systemctl status averra-update-request.path`, `journalctl -u averra-update-request` |


## Проверка новых версий по кнопке

«Проверить снова» заодно запрашивает источник релизов через сервер. Пока `release-check.json` не
получил время новее заявки, показывается «Проверяю новые версии…» и состояние опрашивается.
Через пять минут без ответа экран предлагает повторить позже или обратиться к студии.
Проверки — не чаще раза в пять минут; при недоступной папке заявок или без новой службы systemd
кнопка обновляет только сведения и поясняет, что версии проверяются раз в сутки.
Подробнее — [Обновления](/averra-cms/install/updates/#проверить-новые-версии-сейчас).
