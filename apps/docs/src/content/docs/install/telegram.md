Для студии после установки. После страницы уведомления о заявках и служебные — бэкап, диск,
сборка, почта — будут приходить в Telegram.

## Создать бота

1. В Telegram откройте [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Имя — как его увидят в чате, например «Ремонт: заявки». Логин — латиницей и на `bot`, например
   `remont_leads_bot`.
3. BotFather пришлёт токен вида `123456789:AA…`. Это пароль бота: кто его знает, читает и пишет от
   имени бота. Не пересылайте его в чатах и не храните в заметках.

Один бот — одна установка: Averra забирает обновления бота, пока человек привязывает чат, и второй
потребитель (другая установка, webhook) ему помешает.

## Подключить

«Уведомления» → «Каналы» → Telegram: токен, прокси (если нужен), свой пароль от админки →
«Подключить бота». Averra проверит токен (`getMe`) и сохранит его зашифрованным ключом
`MAIL_ENCRYPTION_KEY` — тем же, что пароль SMTP. Без ключа бота не сохранить: экран скажет, как
его задать ([Почта](/averra-cms/install/mail/)).

Дальше — привязать чаты ссылкой «Привязать чат Telegram» ([Уведомления](/averra-cms/admin/notifications/)).
Чтобы бот писал в группу, добавьте его туда по кнопке «Добавить в группу» — так он получит и код.

## Если у бота был webhook

Averra не держит входящего адреса для Telegram: обновления она забирает сама (`getUpdates`) и только
пока жив код привязки. Если у бота настроен webhook, Telegram отвечает 409: под ссылкой привязки
вместо «Ждём «Старт»» появится «Бот сейчас не получает «Старт»» с причиной. Снимите webhook
командой `deleteWebhook` на сервере. Токен — скрытым вводом в переменную, а не аргументом: так он
не останется в истории shell и в списке процессов:

```sh
read -rs TOKEN   # вставьте токен и нажмите Enter — на экране его не видно
curl -s -K - <<< "url = https://api.telegram.org/bot$TOKEN/deleteWebhook"
unset TOKEN
```

С российского VPS `api.telegram.org` напрямую часто недоступен — тогда через тот же прокси, что
в канале. Адрес прокси с паролем — тоже скрытым вводом. Для SOCKS пишите `socks5h://` вместо
`socks5://`: так имя `api.telegram.org` разрешает прокси, а не сервер:

```sh
read -rs TOKEN   # токен бота
read -rs PROXY   # прокси: socks5h://логин:пароль@host:1080 или http://логин:пароль@host:3128
curl -s -K - <<< "url = https://api.telegram.org/bot$TOKEN/deleteWebhook
proxy = $PROXY"
unset TOKEN PROXY
```

`curl -K -` берёт адрес и прокси из ввода, а не из аргументов команды. Ответ `{"ok":true,…}` —
webhook снят; через несколько секунд экран привязки снова ждёт «Старт».

## Telegram недоступен с VPS

С российских VPS `api.telegram.org` часто недоступен напрямую. Признак — «Не удалось подключиться
к Telegram» при подключении бота или на «Проверить». Варианты:

- **Прокси** в настройках канала: `socks5://логин:пароль@host:1080`, `http://host:3128` или
  `https://host:443`. Пароль прокси хранится вместе с токеном зашифрованным, на экране — адрес без
  пароля. HTTP-прокси должен уметь `CONNECT` (туннель к `api.telegram.org:443`).
  Спецсимволы в логине и пароле — %-кодами, как в любом URL: `#` → `%23`, `?` → `%3F`,
  `@` → `%40`, `/` → `%2F`, `%` → `%25`, `\` → `%5C`, пробел → `%20`, двоеточие в логине →
  `%3A`. Пароль `pa#ss?1` пишется `socks5://user:pa%23ss%3F1@host:1080`. Без кодов адрес не
  примется: экран скажет об этом у поля прокси. Если в адресе есть «@», логин перед ним
  обязателен, а хост IPv6 пишется в квадратных скобках: `socks5://[2001:db8::1]:1080`. В тексте
  ошибок подключения адреса прокси нет — его видит и клиент у ссылки привязки.
- **Свой адрес Bot API** — переменная `TELEGRAM_API_URL` в окружении API: [локальный сервер Bot
  API](https://github.com/tdlib/telegram-bot-api) или зеркало
  ([Переменные окружения](/averra-cms/dev/env/)). Адрес в интернете — только `https://`. Свой
  сервер Bot API на той же машине или контейнером в сети docker обычно слушает `http://` — такой
  адрес тоже подходит: `http://127.0.0.1:8081`, `http://telegram-bot-api:8081` (имя сервиса без
  точки). Токен уходит на этот адрес — ставьте только свой сервер.

Пока Telegram недоступен, сообщения ждут в очереди и не тратят попыток: канал выжидает с растущей
паузой до 30 минут и пробует снова. Заявки при этом принимаются как обычно.

## Персональные данные

В уведомление о заявке уходят её поля. Telegram — иностранный сервис: решите с клиентом, слать ли
туда заявки или только служебные события ([Персональные данные](/averra-cms/install/personal-data/)).
