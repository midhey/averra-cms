Для студии. Шаблон переносит сайт в новую установку на VPS клиента. Каждая установка по-прежнему
обслуживает один сайт; пользователи, доступы и настройки сервера у клиента свои.

## Сделать шаблон

Владелец или администратор сайта открывает **Настройки сайта → Выгрузка → Скачать шаблон сайта**.
Через терминал, со встроенной базой при остановленном API:

```bash
pnpm site:template --out client-template.zip
```

На сервере, из папки установки:

```bash
docker compose exec api node dist/server/site-template.js --out /tmp/client-template.zip
docker compose cp api:/tmp/client-template.zip ./client-template.zip
```

Относительные пути pnpm-команд считаются от `apps/api`; для выгрузки в другую папку укажите полный путь.
Существующий файл команда не перезаписывает. Архив ZIP содержит `template.json`: формат
`averra-site-template`, `formatVersion: 1`, `averraVersion` и оригиналы используемых картинок.
Предел — 256 МБ на архив и распакованные данные, 16 МБ на JSON.

Переносятся:

- Страницы: опубликованная версия и заголовок; у неопубликованной — черновик. Несохранённые
  и неопубликованные изменения опубликованной страницы не переносятся.
- Тема, шапка, подвал, свои блоки, скрипт сайта, политика и согласие, свои тексты писем сайта.
- SEO без домена, canonical, кодов подтверждения, счётчиков и организации. Картинки — только
  те, на которые ссылаются переносимые страницы, оформление, SEO и свои блоки.

Заявки, получатели уведомлений, пользователи, токены, SMTP и история версий в шаблон не входят.
Настройки организации исключаются; известные реквизиты в текстах заменяются заглушками,
блоки «Контакты» получают пустые контакты и заглушку адреса. Имена исходных файлов не переносятся.
Скрипты, CSS и Liquid не переписываются: при известных реквизитах организации в коде выгрузка
отказывает и просит убрать их. Перед передачей просмотрите произвольные тексты, код своих блоков,
скрипты и сами изображения:
сведения, вписанные туда вручную, невозможно надёжно распознать автоматически.

## Поднять клиента

Скопируйте архив на VPS вместе с [файлами установщика](/averra-cms/install/server/). На новом VPS:

```bash
sudo bash install.sh --site-domain client.ru --email studio@example.com --version 0.4.0 --template ./client-template.zip
```

`--template` работает только в новой папке установки, где ещё нет `.env`. Установщик проверяет
читаемость и размер архива, запускает API, создаёт владельца, передаёт архив через stdin и
собирает сайт. В `--dry-run` файл проверяется, импорт не выполняется; `--env-only` с шаблоном
несовместим. Для повторного запуска установщика уберите `--template`.

В уже подготовленную пустую установку можно импортировать отдельно:

```bash
docker compose exec -T api node dist/server/site-import-template.js --file - < client-template.zip
```

Локально: `pnpm site:import-template --file client-template.zip`. `--file -` читает stdin.
Со встроенной базой остановите API; на сервере PostgreSQL позволяет команде работать рядом с API.
Для серверной сборки API должен отвечать локально на своём порту; при заданном `PUBLISH_DIR`
команда ждёт сборку и сообщает о её неудаче. После ошибки сборки контент уже импортирован:
исправьте причину и нажмите «Собрать заново» в админке.

Импорт разрешён только с нетронутой пустой неопубликованной главной и без своих блоков. Даже
пустая опубликованная страница защищена от замены. Флага `--force` нет. Повреждённый архив,
неизвестная версия формата, лишние файлы и неверные схемы отвергаются. Картинки получают новые ID
и проходят обычные проверки медиатеки: размер, тип по содержимому, ограничения пикселей и очистку
SVG. Данные записываются транзакцией; при отказе новые файлы удаляются.

Уже заполненные на целевой установке организация, адрес сайта и настройки, отсутствующие в шаблоне,
сохраняются. Новые публикации получают свою начальную историю без истории исходной установки.

Все страницы сохраняются черновиками; опубликованные в шаблоне сразу публикуются с новой историей.
Новый сайт скрыт от поисковиков до запуска, независимо от индексации исходного сайта.

## Заполнить данные клиента

На **Обзоре** появляется «Что заполнить»: организация и реквизиты, документы, SMTP, получатели
заявок, домен. Пункты вычисляются из данных и исчезают после заполнения. Домен из `SITE_URL`,
который задаёт установщик, тоже учитывается. SMTP настраивает владелец установки.

В документах `privacy` и `consent` импорт добавляет заметку: подставьте свои данные, проверьте
текст, удалите заметку и опубликуйте. После подготовки откройте индексацию в SEO и пройдите
[чек-лист запуска](/averra-cms/install/checklist/).
