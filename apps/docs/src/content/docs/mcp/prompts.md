Для студии и заказчика. MCP-сервер Averra предлагает пять готовых сценариев (prompts) на русском.
Вы выбираете сценарий и задаёте пожелания, нейронка получает последовательность работы с
[инструментами](/averra-cms/mcp/tools/). Выбор prompt сам по себе ничего не меняет: инструменты
вызывает нейронка, с обычными правами токена.

Во всех сценариях **только черновики, публикует человек после предпросмотра**, даже если токену
разрешена публикация страниц. Аудит вообще ничего не сохраняет. Это инструкции для ИИ, а не
новые ограничения API: для дополнительного ограничения выдайте токен без публикации и удаления.

## Как студия запускает сценарий

1. Подключите MCP по странице [Подключение](/averra-cms/mcp/setup/). Для установки заказчика
   укажите адрес её админки как CMS_API_URL; сайт выбирается по токену.
2. Выберите сценарий и заполните аргументы из таблицы ниже. Укажите адрес страницы, аудиторию,
   факты, которые нужно сохранить, и желаемый результат. Не передавайте заявки и персональные данные.
3. Прочитайте отчёт: что сохранено, какие проверки не прошли, чего не хватило для завершения.
4. Проверьте черновики в админке, согласуйте с заказчиком и опубликуйте вручную.

### Claude Code

Файл `.mcp.json` лежит **в корне вашего локального клона Averra**, рядом с `package.json`, а не на
VPS. Он исключён из git; фрагмент с токеном копируется из «Установка → Доступ для ИИ».
После подключения откройте новую сессию в этой папке и проверьте сервер `averra` через `/mcp`.

Наберите `/`, найдите `/averra:rewrite_page (MCP)` или другой сценарий Averra. Работает и полное
имя `/mcp__averra__rewrite_page`. Аргументы передаются в порядке из таблицы, через пробел;
Claude Code делит их по пробелам, поэтому для короткого вызова используйте одно слово на аргумент:

```text
/mcp__averra__rewrite_page index спокойнее
/mcp__averra__new_landing_section index FAQ-перед-contacts
/mcp__averra__refresh_design крупнее-заголовки
/mcp__averra__audit_site
/mcp__averra__mail_texts дружелюбно
```

Развёрнутый бриф можно заранее написать отдельным сообщением в том же диалоге, а в аргументе
сослаться на него словом «по-брифу». Имена команд и правила аргументов описаны в
[документации Claude Code](https://code.claude.com/docs/en/mcp#use-mcp-prompts-as-commands).

### Claude Desktop

Claude Desktop использует свой `claude_desktop_config.json`, а не проектный `.mcp.json`.
Откройте **Settings → Developer → Edit Config** и перенесите запись `averra` из mcpServers
своего `.mcp.json` в mcpServers этого файла, сохранив остальные серверы. Замените command и пути
в args на абсолютные пути вашего клона: рабочая папка Desktop может отличаться от корня проекта.
Сохраните env с адресом API и токеном; запускайте тот же Node и тот же MCP-сервер, что в
[настройке подключения](/averra-cms/mcp/setup/).

Путь конфигурации на Windows — `%APPDATA%\Claude\claude_desktop_config.json`, на macOS —
`~/Library/Application Support/Claude/claude_desktop_config.json`. Полностью перезапустите Desktop.
Эти шаги описаны в [официальной инструкции MCP](https://modelcontextprotocol.io/docs/develop/connect-local-servers).

В новом чате откройте меню `+` рядом с полем сообщения, найдите сценарии сервера `averra`,
выберите нужный и заполните поля аргументов. Названия пунктов меню зависят от версии клиента.
Если ваша версия показывает только инструменты, используйте Claude Code для выбора готового
prompt; обычное сообщение из примеров ниже тоже позволяет поручить работу через инструменты,
но само по себе не загружает серверный сценарий.

## Сценарии и аргументы

Все аргументы — непустые строки: пробелы по краям убираются. page — до 200 символов,
goal и request — до 4000, tone — до 2000. Аудит аргументов не принимает.
page — slug или название уже существующей страницы; главная — index. По названию нейронка ищет
страницу в списке. Если совпадение неоднозначно или страницы нет, сценарий не сохраняет изменения.

| Prompt | Аргументы по порядку | Результат |
|---|---|---|
| `rewrite_page` | page — страница; goal — цель, аудитория и тон | Читает черновик и каталог, переписывает тексты блоков, сохраняет полный черновик, проверяет seoChecks и возвращает список изменений |
| `new_landing_section` | page — страница; request — что добавить и где | Выбирает стандартный или опубликованный свой блок, вставляет в черновик; без указания места добавляет в конец и сообщает об этом |
| `refresh_design` | request — что изменить | Читает актуальные черновики темы, шапки и подвала, сохраняет только затронутые части, исправляет ошибки контраста темы из ответа |
| `audit_site` | нет | Проходит все страницы с пагинацией, проверяет заголовки, h1, якоря, alt и даты документов; возвращает только отчёт |
| `mail_texts` | tone — тон писем | Читает шаблоны сайта, переписывает тексты с сохранением обязательных блоков и переменных, проверяет на примерных данных и сохраняет черновики |

Черновики сохраняются целиком. Сценарии требуют читать актуальную версию и сохранять остальные
блоки, id, ссылки и настройки; перед записью нейронка перечитывает черновик. Это не блокировка
совместного редактирования: на время работы лучше не править те же части сайта одновременно.

Если нужен новый свой блок, нейронка читает правила, сохраняет определение черновиком и проверяет
его. Нужны права на черновики своих блоков. Пока человек не опубликовал определение в админке,
вставка в страницу откладывается. Отчёт должен прямо сказать, какой шаг ещё не выполнен.

Аудит отделяет опубликованную версию от черновиков, игнорирует скрытые блоки при проверке h1
и якорей. Видимый заголовок длиннее 80 символов отмечается как редакторская рекомендация;
для SEO используются советы каталога и seoChecks. Старая дата сама по себе не доказывает,
что документ устарел: явно истёкшие сроки и вопросы для человека приводятся отдельно.
Недоступные определения своих блоков, внешние документы и итоговая вёрстка попадают в список
непроверенного. Это аудит доступного содержимого, а не полный обход сайта браузером.

## Как клиент может сформулировать задачу

- «На главной перепиши тексты для семей с детьми: спокойно, без канцелярита. Цены и условия
  оставь. Только черновик, в конце перечисли изменения и замечания по SEO» — rewrite_page.
- «На странице services добавь FAQ перед contacts, используй эти четыре вопроса и ответа.
  Остальные разделы сохрани» — new_landing_section.
- «Сделай заголовки крупнее и подвал спокойнее, сохрани логотип и пункты меню.
  Проверь контраст, подготовь черновики» — refresh_design.
- «Проверь страницы: заголовки, h1, якоря, alt картинок и сроки в документах.
  Ничего не меняй, пришли отчёт с местами проблем» — audit_site.
- «Перепиши письма сайта дружелюбно и кратко, сохрани обязательные блоки.
  Проверь пример и сохрани только черновики» — mail_texts.

Студия выбирает соответствующий prompt и передаёт этот текст в его аргументе либо как бриф
в диалоге. Для нового раздела приложите факты и тексты: сценарий не должен придумывать отзывы,
цены или обязательства компании.

## Права и проверка человеком

Черновики страниц доступны обычному токену. Для оформления нужно отдельное право
«Черновики темы, шапки и подвала» (designDraft), для определений своих блоков — право на их
черновики. При отказе нейронка сообщает, что не сделано; расширяет права владелец в
[настройках токена](/averra-cms/mcp/tokens/). Черновики писем сайта доступны токену без данных
заявок; служебные письма установки ему закрыты.

Нейронка не читает заявки, персональные данные, адреса получателей и секреты; не отправляет
письма и не выпускает ссылки предпросмотра. Предпросмотр письма использует только примерные
данные. Сохранение темы проверяет контраст основных пар, но сочетания поверх фотографий,
свои блоки и состояния элементов нужно дополнительно посмотреть вручную, в том числе на телефоне.

Владелец или администратор сайта может открыть **Обзор → Предпросмотр для заказчика** и создать
[ссылку на черновики](/averra-cms/admin/preview/). MCP лишь напоминает об этой возможности.
Ссылка не публикует сайт; её передаёт заказчику человек. После согласования тему публикует
владелец, шапку и подвал — владелец или администратор сайта (при изменении вида — только
владелец), страницы — человек с правом публикации, письма — в «Уведомления → Письма».
