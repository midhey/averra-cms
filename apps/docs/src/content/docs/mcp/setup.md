Для разработчика и студии. После страницы нейронка в Claude Code (или другом MCP-клиенте) будет
видеть сайт и сможет собирать его страницы.

MCP-сервер Averra — процесс на вашей машине, клиент API по stdio. Он ходит в API по адресу
`CMS_API_URL` с токеном `CMS_API_TOKEN`: в локальный `pnpm dev` или в установку клиента.

## Локально, с `pnpm dev`

1. Запустите `pnpm dev`, войдите в админку владельцем и откройте **Установка → Доступ для ИИ**.
2. Выпустите токен: имя и права, по умолчанию «только черновики»
   ([Токены](/averra-cms/mcp/tokens/)). Токен показывается один раз.
3. Нажмите «Скопировать фрагмент .mcp.json» и сохраните его в `.mcp.json` в корне репозитория (он
   в `.gitignore`). В нём уже адрес установки и токен. На Windows поправьте `command` на
   `node_modules/.bin/node.exe`. Если на macOS или Linux файла `node_modules/.bin/node` нет,
   укажите в `command` путь, который выведет `pnpm exec node -p process.execPath`.
4. Откройте новую сессию Claude Code в папке репозитория и разрешите сервер `averra`. Был запущен —
   перезапустите: токен читается при старте.

Без админки: остановите `pnpm dev` (команде нужна база, а встроенная база не выдерживает два
процесса) и выпустите токен командой `pnpm token:create --name mcp`. Строку `CMS_API_TOKEN=…` из
вывода положите в `apps/mcp/.env` (образец — `apps/mcp/.env.example`), а `.mcp.example.json`
скопируйте в `.mcp.json`.

`.mcp.json` запускает сервер на Node, закреплённой в проекте: её кладёт в `node_modules/.bin`
`pnpm install`. stdout сервера занят протоколом MCP, поэтому сервер запускается напрямую через
Node, а не через `pnpm run`: pnpm печатает в stdout свои строки.

## С установкой клиента

MCP-сервер можно направить в API установки — админка и API живут на одном адресе:

1. Выпустите токен в админке установки (Установка → Доступ для ИИ) и скопируйте фрагмент
   `.mcp.json`: адрес в нём — адрес этой админки, например `https://admin.example.ru`.
2. Сохраните фрагмент в `.mcp.json` своего клона репозитория Averra.
3. Перезапустите MCP-сервер.

По SSH — та же команда в контейнере: `docker compose exec api node dist/server/token-create.js
--name mcp` в `/opt/averra`, а `CMS_API_URL` и `CMS_API_TOKEN` — в `apps/mcp/.env` на своей
машине.

Публикация через MCP на установке собирает сайт на сервере, как публикация из админки.

## Переменные

| Переменная | Что задаёт |
|---|---|
| `CMS_API_TOKEN` | токен API. Без него сервер стартует, `list_blocks` работает, а остальные инструменты отвечают, как получить токен |
| `CMS_API_URL` | адрес API, по умолчанию `http://localhost:4000` |

Где их задать: `env` сервера `averra` в `.mcp.json` (так делает фрагмент из админки) или файл
`apps/mcp/.env` — сервер ищет его рядом с пакетом, а не в текущей папке. Если переменная есть в
обоих, главнее `.mcp.json`.

## Проверка

Попросите нейронку вызвать `list_sites` или `get_page`: в ответе — сайт токена и его главная.
Ошибки по-русски объясняют, что не так:

- «Нужен токен API…» — `CMS_API_TOKEN` пуст;
- «API не принял токен: он отозван или неверный» — выпустите новый;
- «Публиковать этому токену не разрешено…» — токен «только черновики»: публикуйте в админке или
  включите токену право «Публикация страниц»;
- «API не отвечает» — API не запущен или `CMS_API_URL` не тот.
