Для студии. После страницы вы выпустите токен для нейронки, будете знать его права и отзовёте его,
когда он больше не нужен.

## Права

Токен API — это **редактор на сайте установки**: читать сайт, страницы, историю и медиатеку, править
черновики, создавать, публиковать и удалять страницы, загружать картинки, «Собрать заново».

Отдельное право — **«черновики своих блоков»**, по умолчанию выключено: с ним нейронка читает
определения своих блоков с черновиками, создаёт блок, сохраняет черновик и проверяет шаблон
([Свои блоки через MCP](/averra-cms/mcp/tools/#свои-блоки-четыре-инструмента)). Публиковать,
удалять и откатывать блоки токен не может и с правом: это делает человек в админке. Право
включает владелец командой, оно действует сразу, токен перевыпускать не нужно.

Чего токену нельзя никогда — заявок и полной выгрузки данных сайта: это персональные данные
посетителей. Запрет — отдельная проверка, её не снимет изменение таблицы ролей. Ещё нельзя: другие
сайты, создание сайтов, приглашения, почта, состояние установки, «Скачать сайт архивом».

## Выпустить, посмотреть, отозвать

| Команда | Что делает |
|---|---|
| `pnpm token:create --name <имя> [--by <почта владельца>] [--blocks-draft]` | выпускает токен на сайт установки и показывает его один раз; `--blocks-draft` сразу даёт право на черновики своих блоков |
| `pnpm token:list` | токены: сайт, кто выпустил, когда пользовались, отозван ли, есть ли право на черновики блоков — без самих токенов |
| `pnpm token:grant --id <id> --blocks-draft on\|off` | включает или выключает право на черновики своих блоков |
| `pnpm token:revoke --id <id>` | отзывает токен |

`--by` нужен, только если владельцев несколько. `--site <id>` — только для старой базы
разработки, где сайтов несколько. id токена — в выводе `token:create` и `token:list`.

На сервере — те же команды в контейнере API: `docker compose exec api node
dist/server/token-create.js …` (`token-list.js`, `token-grant.js`, `token-revoke.js`). С PostgreSQL они работают при
запущенном API. Локально со встроенной базой сначала остановите `pnpm dev`.

Экрана токенов в админке пока нет — он в [дорожной карте](/averra-cms/roadmap/).

## Как хранится

В базе — только SHA-256 токена. Сам токен показывается один раз и больше нигде не появляется: ни в
базе, ни в логах. Поэтому потерянный токен не восстановить — выпустите новый и отзовите старый.
Подробно — [Токены и ссылки только хешем](/averra-cms/decisions/hashed-tokens/).

Токен передаётся заголовком `Authorization: Bearer <токен>`. Отозванный или неверный — 401, и MCP
скажет «API не принял токен».

## Советы

- Один токен — одна программа: так видно в `token:list`, кто когда пользовался, и отзыв не задевает
  остальных.
- Храните токен в `apps/mcp/.env` (он в `.gitignore`), не в `.mcp.json` и не в чате с нейронкой.
- Закончили работу с сайтом клиента — отзовите токен.
