Для владельца установки (студии). После страницы вы выпустите токен для нейронки в админке,
выберете ему права и отзовёте его, когда он больше не нужен.

## Права

Любой токен работает только с сайтом установки и всегда может: читать сайт, страницы, историю,
тему, шапку и медиатеку, создавать страницы и сохранять их черновики, загружать картинки.

Остальное — отдельные права. Новый токен по умолчанию — **«только черновики»**:

| Право | По умолчанию | Что открывает |
|---|---|---|
| Черновики своих блоков | включено | читать черновики своих блоков, создавать блок, сохранять черновик, проверять шаблон ([через MCP](/averra-cms/mcp/tools/#свои-блоки-четыре-инструмента)) |
| Публикация страниц | выключено | `publish_page` и «Собрать заново» |
| Удаление страниц и картинок | выключено | удалить страницу или картинку медиатеки |

Без права API отвечает 403 и говорит, где его включить, — нейронка передаст это вам. С «только
черновики» нейронка собирает страницу, а публикуете вы в админке, посмотрев результат.

Чего токену нельзя никогда, с любыми правами:

- заявок и полной выгрузки данных сайта — это персональные данные посетителей;
- опубликовать, удалить или откатить свой блок — это код на страницах, его читает человек;
- менять тему, шапку, меню и подвал, SEO, почту и уведомления, обновлять установку;
- выпускать, менять и отзывать токены — иначе программа выдала бы себе права.

Эти запреты — отдельные проверки в API (`tokenDenied` и `personalData` в `auth/access.ts`), их не
снимет изменение таблицы ролей: даже если редактору когда-нибудь откроют SEO, токену оно останется
закрытым. Права меняются сразу: перевыпускать токен и перезапускать MCP не нужно.

Токены, выпущенные до версии с правами, сохранили то, что умели: публикацию и удаление. Право на
черновики своих блоков у них — как было. Посмотрите их в списке и снимите лишнее.

## В админке

**Установка → Доступ для ИИ** — только у владельца. Администратору сайта и редактору раздела нет,
API отвечает им 403.

1. **Новый токен:** имя (чья это программа: «Claude Code Алексея») и права. Нажмите «Выпустить
   токен».
2. Откроется окно с токеном. **Он показывается один раз**: после «Готово» его не увидит никто,
   даже вы. «Скопировать фрагмент .mcp.json» копирует готовую настройку MCP-сервера с адресом
   установки и токеном:

   ```json
   {
     "mcpServers": {
       "averra": {
         "command": "node_modules/.bin/node",
         "args": ["apps/mcp/node_modules/tsx/dist/cli.mjs", "apps/mcp/src/index.ts"],
         "env": {
           "CMS_API_URL": "https://admin.example.ru",
           "CMS_API_TOKEN": "cms_…"
         }
       }
     }
   }
   ```

   Положите его в `.mcp.json` в корне репозитория Averra (файл в `.gitignore`). Есть свой
   `.mcp.json` — перенесите только сервер `averra`. Адрес — тот, где открыта админка: API живёт
   на том же адресе. Как запустить сервер — [Подключение](/averra-cms/mcp/setup/).
3. **Токены:** имя и кто выпустил, права («Только черновики» — отдельной пометкой), когда выпущен,
   когда им пользовались последний раз, состояние.
4. **«Права»** — окно с теми же флажками. «Сохранить права» активна, только если что-то поменяли.
5. **«Отозвать»** — с подтверждением в окне. Программа с токеном теряет доступ на следующем же
   запросе, MCP скажет «API не принял токен». Вернуть отозванный токен нельзя — только выпустить
   новый. Отозванный остаётся в списке с пометкой «Отозван».

## Командой

Те же действия есть в терминале API — для скриптов и установки без браузера. Значения по
умолчанию — как в админке.

| Команда | Что делает |
|---|---|
| `pnpm token:create --name <имя> [--publish] [--delete] [--no-blocks-draft] [--by <почта владельца>]` | выпускает токен «только черновики»; флаги добавляют публикацию и удаление или снимают черновики своих блоков. Показывает токен один раз |
| `pnpm token:list` | токены: сайт, кто выпустил, права, когда пользовались, отозван ли — без самих токенов |
| `pnpm token:grant --id <id> [--blocks-draft on\|off] [--publish on\|off] [--delete on\|off]` | меняет названные права, остальные не трогает; отозванному токену откажет, как админка (нужен новый токен) |
| `pnpm token:revoke --id <id>` | отзывает токен |

Прежний флаг `token:create --blocks-draft` принимается: право и так включено. `--by` нужен, только
если владельцев несколько. `--site <id>` — только для старой базы разработки, где сайтов
несколько. id токена — в выводе `token:create` и `token:list`.

На сервере — те же команды в контейнере API: `docker compose exec api node
dist/server/token-create.js …` (`token-list.js`, `token-grant.js`, `token-revoke.js`). С
PostgreSQL они работают при запущенном API. Локально со встроенной базой сначала остановите
`pnpm dev`.

## Как хранится

В базе — только SHA-256 токена. Сам токен приходит один раз — в ответе на выпуск — и больше нигде
не появляется: ни в базе, ни в списке, ни в логах. Потерянный токен не восстановить — выпустите
новый и отзовите старый. Подробно — [Токены и ссылки только
хешем](/averra-cms/decisions/hashed-tokens/), почему права такие —
[Права токена MCP](/averra-cms/decisions/token-rights/).

Токен передаётся заголовком `Authorization: Bearer <токен>`. Отозванный или неверный — 401, и MCP
скажет «API не принял токен».

## Советы

- Один токен — одна программа: в списке видно, кто когда пользовался, и отзыв не задевает
  остальных.
- Начинайте с «только черновики». Публикацию включайте, когда доверяете результату нейронки без
  просмотра.
- Храните токен в `.mcp.json` или `apps/mcp/.env` (оба в `.gitignore`), не в чате с нейронкой и не
  в репозитории.
- Закончили работу с сайтом клиента — отзовите токен.
