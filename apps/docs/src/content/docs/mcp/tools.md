Для разработчика и того, кто пишет промпты для нейронки. После страницы вы будете знать, что
принимает и отдаёт каждый инструмент и по каким правилам нейронка собирает страницу.

## `list_blocks`

Каталог блоков. Вызывается перед сборкой страницы. Работает и без токена.

Отдаёт `rules` — правила сборки страницы — и `blocks`: у каждого блока `type`, `title`,
`description`, `category` (раздел каталога: «Начало страницы», «О компании», «Продажа», «Доверие»,
«Связь»), `props` (JSON Schema полей, сгенерированная из той же Zod-схемы, что в API) и `example`.
Блоки идут в том порядке, в каком обычно стоят на лендинге. После встроенных — свои блоки сайта
токена (`custom: true`, `type` — `custom:<ключ>`): только опубликованные, схема `props` строится из
их определения так же, как в API. Ставятся на страницу так же — `{ id, type: "custom:tariffs",
props }`. Сами определения своих блоков токен меняет только черновиком и только с правом на
черновики (`save_custom_block_draft`, ниже); публикует определение владелец в админке
([почему](/averra-cms/decisions/custom-blocks/)). Без токена или на установке до своих блоков —
только встроенные.

Главные правила из каталога:

- страница — `{ blocks: [...] }`, не больше 50 блоков;
- у любого блока необязательный `hidden` рядом с `id`, `type`, `props`: `true` скрывает блок,
  `false` или отсутствие показывает. Скрытый блок сохраняет содержимое и порядок, но не выводится
  в предпросмотре, на сайте и в меню по якорям;
- у каждого блока уникальный `id` (латиница, цифры, `_`, `-`) — он же якорь для ссылок `#id`;
- главный заголовок страницы получает первый видимый `hero` или свой блок с `<h1>` в шаблоне —
  начинайте страницу с него;
- ссылки — только `https://`, `http://`, `/`, `#`, `mailto:` и `tel:`;
- лишних полей нет — только поля из схем;
- картинка — `{ mediaId, alt }` из медиатеки этого сайта, alt обязателен; SVG — только для логотипа,
  иконки и логотипов клиентов (`clients`, поле `logo` — `{ mediaId }` без alt), в остальные
  картинки блоков его не поставить;
- видео (`video`) — `url` ролика YouTube, Rutube или VK Видео (другие адреса не пройдут),
  заголовок обязателен, обложка `cover` — своя из медиатеки;
- форма заявки: уникальные ключи полей (`website` и `consent` заняты), у выбора — варианты,
  `policyUrl` обязателен, `consentUrl` (текст согласия, `/consent`) — нет. Способ связи: у
  вариантов select — необязательный `contact` (`telegram`, `vk`, `phone`, `email`), у поля text —
  `contactBy` с ключом этого select; тогда контакт проверяется по выбранному способу, а не
  принимается любым. `contactBy` без такого select форма не сохранит;
- текст (`text`): пустая строка — новый абзац, «- » — пункт списка, «## » — подзаголовок, HTML
  не работает;
- не выдумывать факты: числа, цены, сроки и гарантии — из брифа, иначе заглушка в квадратных
  скобках, как в `example` («[12]», «от [цена] ₽/м²»);
- `text-image` — текст с той же разметкой и необязательная картинка слева или справа; `stats` —
  2–4 факта `{ value, label }`; `steps` — 3–6 шагов; `pricing` — 2–4 тарифа, `featured` — не больше
  чем у одного; `faq` — 1–20 вопросов, они же уходят в разметку FAQPage;
- `gallery` — 1–24 фото с подписями; `reviews` — 1–12 отзывов, только настоящие из брифа;
  `clients` — 2–24 клиента `{ name, logo }`; `team` — 1–24 человека `{ name, role, photo }`;
  `contacts` — телефон, почта, адрес, часы, карта (`mapService`, `coordinates`), хотя бы одно из
  телефона, почты и адреса; `markup: true` добавляет разметку организации из «SEO → Организация»;
- SEO страницы — необязательное `seo: { title, description, shareTitle, shareDescription, image,
  imageAlt, canonical, noindex }` рядом с `blocks`: SEO-заголовок целиком, описание, заголовок и
  описание для соцсетей, картинка `{ mediaId }` и что на ней, canonical, noindex. Пустое берётся у
  сайта; диапазоны длин — в правилах;
- окно — необязательное `window: { title, width, surface, closeOnBackdrop }`: страница открывается
  окном поверх других по кнопке с `window: true` (у `button` «Первого экрана», «Призыва», «Тарифов»,
  «Текста с картинкой»); без JS — переход на неё. У главной и 404 окна не бывает: API ответит 400.
  «Появление при прокрутке» — `reveal: "up" | "fade"` у карточных блоков, плавный FAQ —
  `smooth: true`;
- страница с адресом `404` — служебная: её показывают на адресах, где страницы нет;
- `save_draft` сохраняет черновик, на сайт он попадает после `publish_page`.

## `list_sites`

Сайт, на который выпущен токен: id и название. Вызывать его не обязательно: сайт у установки один,
и остальные инструменты без `siteId` работают на сайте токена (его отдаёт `GET /api/site`).

## `list_pages`

Список страниц сайта токена без содержимого блоков. Право `site.read`, как у `get_page`.

Вход: необязательные `siteId`, `q` (поиск по заголовку или адресу без учёта регистра, до 200
символов), `state`, `limit` (1–100, по умолчанию 20) и `offset` (0–2147483647, по умолчанию 0).
`state`:

- `draft` — страницу ещё не публиковали;
- `published` — у страницы есть опубликованная версия, в том числе с более новым черновиком;
- `unpublished` — есть неопубликованные изменения, включая новые черновики.

Ответ: `{ items, total, limit, offset }`. У элемента — `slug`, `title`, `state`,
`hasUnpublishedChanges`, `updatedAt`, `publishedAt` (или `null`). Состояние элемента — `draft`,
`unpublished` (опубликована, но черновик отличается) или `published` (всё опубликовано).
`total` — число после фильтров, до пагинации. Главная идёт первой, остальные по адресу.
Для следующей порции увеличьте `offset` на `limit`; при изменении списка между запросами
страницы могут смещаться. Содержимое страницы получают через `get_page`. Данные авторов,
контакты организации и заявки в список не входят.

## `upload_image`

Загружает картинку в медиатеку сайта токена. Право `media.upload` есть у любого токена,
отдельно выдавать его не нужно. Ровно один источник:

- `path` — путь к локальному обычному файлу на машине MCP-сервера; относительный путь считается
  от рабочей папки процесса. Симлинк допустим, если ведёт на обычный файл;
- `data` вместе с `fileName` — обычный base64 с заполнением `=`, без пробелов и префикса `data:`;
  имя должно содержать расширение.

Форматы: `.jpg`, `.jpeg`, `.png`, `.webp`, `.avif`, `.svg` (регистр не важен). Предел MCP —
10 МиБ на файл, для SVG — 256 КиБ (`MAX_SVG_BYTES`). Размер локального файла проверяется по
`stat` до чтения, длина base64 — до декодирования. Base64 занимает не более
`4 × ceil(лимит в байтах / 3)` символов; точный размер проверяется с учётом `=`.
Чтение файла ограничено и при его росте. Тип по содержимому, размеры и безопасность SVG
окончательно проверяет API. Лимит установки `MEDIA_MAX_BYTES` может быть ниже: отказ API
(в том числе 413) инструмент передаёт по-русски.

URL не принимается: это исключает серверные запросы к произвольным адресам (SSRF) и
автоматическое скачивание чужого контента. Скачайте разрешённый файл самостоятельно и передайте
`path`. Загрузка идёт тем же multipart-маршрутом `POST /api/sites/:siteId/media`, что в админке,
с токеном MCP.

Ответ: `mediaId`, `width`, `height`, `mimeType`, `usage` (как ссылаться). В обычной картинке блока —
`{ mediaId, alt }`, в логотипе — `{ mediaId }`. SVG подходит только для логотипов и иконки,
в обычные картинки блоков и SEO-картинку страницы его поставить нельзя. Медиатека не хранит
общий alt: описание задаётся в каждом блоке, до 200 символов. Для полей темы и SEO используйте
полученный `mediaId` в формате соответствующего поля; настройки меняет человек в админке.

## `get_page`

Вход: `slug` (по умолчанию `index` — главная) и необязательный `siteId`. Отдаёт страницу с
черновиком и опубликованной версией — как `GET /api/sites/:siteId/pages/:slug` — и `seoChecks`:
советы по SEO черновика, те же, что в панели «SEO» редактора (`level` — `warning` или `problem`,
`title`, `advice`). Публиковать они не мешают. Черновик, который эта версия MCP не знает целиком
(например, после отката с более новой версии), страницу не ломает: советы считаются по тому, что
понятно, а не разобрать и этого — страница приходит без `seoChecks`. Так же без советов, но без
ошибки, отвечает установка старее MCP, у которой `GET /api/sites/:siteId` ещё не отдаёт `seo`,
и API, не ответивший на этот запрос: советы — добавка к странице, а не её часть. Если на странице
есть свои блоки, MCP читает их опубликованные определения: свой блок с `<h1>` в шаблоне — главный
заголовок, и совета «нет h1» нет. Определения не прочитались — совет считается по встроенным блокам.

## `save_draft`

Временно скрыть блок: получите страницу через `get_page`, задайте нужному блоку `hidden: true`
рядом с `props` и сохраните всю страницу. Для возврата задайте `hidden: false` или уберите поле.
Изменение появится на сайте после `publish_page` и сохранится в истории; удалять блок не нужно.

Вход: `slug`, `title` (заголовок страницы), `content` — `{ blocks: [...], seo?, hideHeader?,
shortHeader?, hideFooter?, window? }` — и необязательный `siteId`. `hideHeader: true` скрывает шапку сайта
на этой странице (промо), `shortHeader: true` делает её короткой — логотип и «← На главную» (для
«Спасибо», документов, 404), `hideFooter: true` скрывает подвал (ссылки на документы остаются).
Сохраняет черновик **целиком**: блоки, которых нет в `content`, исчезнут из черновика, `seo`,
`hideHeader`, `shortHeader`, `hideFooter` и `window` — тоже, если их не передать (шапка и подвал
на промо-странице после публикации вернутся, страница-окно станет обычной страницей).
Поэтому правка одного блока — это `get_page`, правка и `save_draft` всей страницы со всеми её
полями.

Нет страницы с таким адресом — создаст её. Опубликованная версия не меняется. В ответе —
`seoChecks` по сохранённому черновику, как у `get_page`. Нет советов — черновик всё равно
сохранён: ошибкой `save_draft` отвечает, только если не сохранил.

## `publish_page`

Вход: `slug` и необязательный `siteId`. Публикует черновик — он заменит то, что на сайте, и попадёт в историю с
автором-токеном. На установке после этого собирается сайт.

Нужно право токена «Публикация страниц». У токена «только черновики» (новый по умолчанию) —
403 «Публиковать этому токену не разрешено…»: черновик сохранён, публикует человек в админке.

## `get_theme`

Вход: необязательный `siteId`. Отдаёт актуальный черновик `draft` и опубликованную тему
`published` (она же `theme`) — цвета
(`background`, `surface`, `text`, `muted`, `accent`, `onAccent`, `border`), шрифты (id) и
скругления; `fonts` — названия шрифтов заголовков и текста («Lora», «Golos Text»);
`unpublishedDraft` — есть ли на экране «Тема» неопубликованный черновик. Тема от более новой версии
Averra читается без ошибки: незнакомое — значения по умолчанию.

Правку начинайте с `draft`: в нём могут быть ещё не опубликованные правки человека.
Сохранение — `save_theme_draft`, публикация и возврат из истории — только в админке
([почему](/averra-cms/decisions/token-rights/)).

## `get_header`

Вход: необязательный `siteId`. Отдаёт опубликованную шапку `published` (также `header`),
её черновик `draft` и подвал: `header` —
раскладка (`layout` и `layoutTitle`), липкая, сборка, прозрачная, телефон, логотип (`brand`,
`logo`, `logoMark`, `logoText`), вид (`look`), кнопка и пункты `menu` — `{ label, mobileLabel,
page, block, url, href, newTab }` (`url` — внешняя ссылка, `href` — адрес на сайте, `newTab` —
откроется ли в новой вкладке); `null` и `note` — шапку ещё не публиковали. `draft` — черновик с
экрана «Шапка и подвал» по схеме `Header`, без вычисленных `layoutTitle` и `href`,
`unpublishedDraft` — отличается ли он от сайта. `footer` и `footerDraft`
— подвал на сайте (`null` — не публиковали) и черновик: вид, фон, свой текст, ссылка на согласие,
логотип; `unpublishedFooterDraft`. У шапки и подвала есть `custom` — свой вид (`{ key, props }`:
ключ своего блока с местом и тексты его полей) или `null` — стандартный. Нужен, чтобы правкой
страниц не ломать меню: пункт ведёт на блок по его id.

Перед правкой читайте `draft`, затем сохраняйте его целиком через `save_header_draft`.
Контакты организации и данные людей не возвращаются.

## `get_footer`

Вход: необязательный `siteId`. Ответ — `{ draft, published, unpublished }`: актуальный черновик,
опубликованный подвал (`null`, если его ещё нет) и наличие неопубликованных изменений.
Контакты организации в ответ не входят. Перед правкой читайте `draft`.

## Черновики темы, шапки и подвала

| Инструмент | Вход | Схема содержимого из `@averra/schema` |
|---|---|---|
| `save_theme_draft` | `{ theme, siteId? }` | `ThemeInput`, включая проверку контраста |
| `save_header_draft` | `{ header, siteId? }` | `Header`: шапка вместе с меню |
| `save_footer_draft` | `{ footer, siteId? }` | `Footer` |

Нужно право токена **«Черновики темы, шапки и подвала»** (`designDraft`). Владелец включает его
в **Установка → Доступ для ИИ** или командой `pnpm token:grant --id <id> --design-draft on`.
Новые токены получают его по умолчанию; старым владелец выдаёт сам.

Сначала получите актуальный `draft` через соответствующий `get_*`: сохранение заменяет черновик
целиком, включая меню у шапки. Токен с правом может менять и вид шапки и подвала. Ответ —
`{ draft, published, unpublished }`, без контактов организации, заявок и email людей.
Опубликованное не меняется. **На сайт изменения уходят только после публикации человеком в
админке. Снимает с сайта и возвращает из истории (`site_revisions`) тоже только человек.**

Проверки — те же, что у `PUT` в API: схемы, контраст, картинки своего сайта, существующие цели
меню и поля своих видов. Ошибки 400/409 возвращаются по-русски с путями полей
(`colors.accent`, `menu.0.page`, `custom.key`); 403 без права содержит подсказку и
`--design-draft on`. Исправьте названные поля и сохраните снова.

## Свои блоки: четыре инструмента

Нейронка может не только ставить готовые свои блоки на страницы (`list_blocks` показывает их с
JSON Schema полей, `save_draft` принимает `custom:<ключ>`), но и **предложить новый блок —
черновиком определения**. Это отдельное право токена «Черновики своих блоков»: у нового токена
включено, меняет его владелец в админке (Установка → Доступ для ИИ) или командой `pnpm token:grant
--id <id токена> --blocks-draft on|off` ([Токены](/averra-cms/mcp/tokens/)).
Без права `list_custom_blocks` показывает только опубликованное, остальные три отвечают 403 с
подсказкой, как право включить.

**Публикует определение только человек**: «Свои блоки» → блок → «Опубликовать». Токен не может
опубликовать, удалить, откатить версию, выгрузить или загрузить файл блоков — даже с правом.
Публикуется тот черновик, который человек видел на экране: если нейронка сохранила новый, пока
экран был открыт, публикация откажет, и человек сначала прочитает свежий.
Блок, который есть только черновиком, на страницу не встанет: страницу проверяют по опубликованным
определениям.

### `list_custom_blocks`

Без входа. Отдаёт `blocks` — для каждого `key`, `state` (опубликован, черновик новее,
только черновик), `definition` (поля, шаблон, CSS, пример; черновик, если он есть) — и `rules`:
инструкцию, как писать свой блок. Вызывать перед `save_custom_block_draft`.

Правила в `rules` — те же, что проверяет движок, плюс требования сайта: порядок работы (тема →
черновик → проверка → человек публикует); поля и их пределы; шаблон Liquid и фильтры (`image`,
`link`, `paragraphs`, `newline_to_br`, `accent`); **шаблон без JavaScript**; **готовые поведения** — атрибуты `data-av-reveal`, `data-av-details`, `data-av-hint`,
`data-av-draw` и ссылка в окно `data-av-window` вместо своего скрипта; **скрипт блока** —
только улучшение (см. ниже); **доступность** (заголовки по
порядку — у блока h2, внутри h3; настоящие ссылки и кнопки; alt у картинок; видимый фокус);
**переменные темы** вместо цветов и шрифтов; **телефон 375 px** без горизонтальной прокрутки;
пример без выдуманных фактов — заглушки в квадратных скобках.

### `get_custom_block`

Вход: `key`. Черновик и опубликованная версия одного блока, замечания к черновику (`problems`) и
страницы, где блок стоит. Нужно право на черновики.

### `save_custom_block_draft`

Вход: `definition` — определение целиком (`CustomBlockDraft`: ключ, название, описание, раздел,
поля, шаблон, CSS, скрипт `script` — необязательно, пример). Сохраняет **черновик**, а если ключа нет — сначала создаёт блок.
Черновик заменяется **целиком**, а истории черновиков нет: правки, которые человек сделал в админке
и не опубликовал, при сохранении токеном пропадают, и наоборот, «Сохранить» в админке затирает
черновик токена. Поэтому нейронка перед сохранением читает актуальный черновик
(`list_custom_blocks`), а владельцу стоит договориться, кто сейчас правит блок; публикацию от гонки
защищает отдельная сверка (409). В ответе при повторном сохранении есть `note`: если нейронка не
читала черновик перед сохранением, в нём могли быть правки человека, и об этом стоит предупредить.
Опубликованное не меняется.
Ошибки шаблона, CSS и примера сохранению не мешают (код пишут по
частям) и возвращаются в `problems`; структура полей, которую API не примет, — ошибка 400 с путём.

Свою шапку или подвал нейронка предлагает так же — определением с `placement: "header"` или
`"footer"` (у блока страницы — `"block"`, по умолчанию; место задаётся при создании и не меняется).
Шаблон места получает данные сайта `site` и `page` — меню, кнопку, логотип, «Организацию», ссылки
на документы; список и пример — [Свои блоки → Шапка и
подвал](/averra-cms/dev/custom-blocks/#шапка-и-подвал). Выбрать свой вид в шапке токен не может:
это делает владелец в «Шапка и подвал». В `list_blocks` такие блоки не попадают — на страницу их
не ставят.

### `check_custom_block`

Вход: `key` (проверить сохранённый черновик) **или** `definition` (проверить, не сохраняя), и
необязательные `data` — свои данные блока вместо примера (длинные тексты, пустые необязательные
поля). Ответ: `verdict`, `problems` — часть (`template`, `css`, `script`, `example`, `fields`), уровень
(`error` не даёт опубликовать, `warning` — совет), строка и понятный текст, `html` — какой HTML
выйдет на сайте (картинки из медиатеки рисуются, как на сайте; своя шапка и подвал — на образце
данных сайта: меню из трёх пунктов, кнопка, «Организация», у подвала — со строкой документов
Averra) и `css`. Нейронка исправляет
блок по этим замечаниям сама. Ничего не сохраняет и не публикует. Почему так —
[решение](/averra-cms/decisions/custom-blocks/).

## Как писать скрипт своего блока

Инструкция для нейронки — та же, что в `rules`. Подробно — [Свои блоки → Скрипт
блока](/averra-cms/admin/custom-blocks/#скрипт-блока), почему так — [Свой JS на
сайте](/averra-cms/decisions/custom-js/).

1. **Сначала блок без скрипта.** Шаблон и CSS дают полный рабочий вид: текст виден, ссылки ведут,
   формы отправляются. Начальное состояние в CSS — финальное.
2. **Скрипт только добавляет.** Ставит класс или `data-`атрибут (`block.classList.add('will-reveal')`),
   и уже по нему CSS прячет или анимирует. Нет скрипта или он упал — всё видно.
3. **Только свои экземпляры.** `blocks` — корни этого блока на странице; элементы ищите внутри:
   `for (const block of blocks) block.querySelectorAll('.card')`, не по всему `document`.
4. **Тело async-функции.** Можно `await`, нельзя `import`/`export`. Нельзя `eval`, `new Function`,
   строку в `setTimeout`, `document.write`, внешние загрузки — их запрещает CSP сайта.
5. **Уважайте `prefers-reduced-motion`**: при `reduce` — без анимаций.
6. **Проверьте**: `check_custom_block` покажет ошибку разбора (часть `script`) и советы. Опубликует
   человек; он же увидит скрипт в действии в изолированном предпросмотре.

## Скрипт сайта: два инструмента

Скрипт на всех страницах и домены, которые ему нужны (виджет чата, CRM-форма), — то же право
«Черновики своих блоков». Публикует только человек: «Скрипт сайта» → «Опубликовать».

### `get_site_script`

Без входа. Черновик и опубликованная версия (`{ script, origins }`), есть ли неопубликованные правки
и замечания к черновику.

### `save_site_script_draft`

Вход: `script` — `{ script, origins }`. `script` — тело async-функции, выполняется на каждой странице
после загрузки; `origins` — домены `https://хост` или `https://*.хост` без пути, они попадут в CSP
сайта (скрипты, стили, картинки, шрифты, фреймы, запросы). Черновик заменяется целиком — сначала
прочитайте его (`get_site_script`). Метрику и GA4 в домены добавлять не нужно.

## Ошибки

Ошибки API приходят нейронке по-русски, с путём до поля, — так же, как их видит админка:

- 400 — вход не прошёл схему: что и где не так;
- 401 — токен не принят;
- 403 — действие не разрешено токену: запрещено всегда или нужно право, которое включает владелец
  (в сообщении сказано, какое);
- 404 — нет сайта или страницы (или сайт не этого токена);
- 409 — запрос верный, но спорит с базой: например, картинки нет в медиатеке сайта.


## Письма сайта

- `list_mail_templates` — два шаблона сайта токена (`lead-new`, `lead-received`): переменные и
  блоки с подписями и обязательностью, стандартный текст, черновик и публикация с авторами.
- `save_mail_template_draft` — `template`, `subject`, `preheader`, `body`. Заменяет черновик
  целиком: перед правкой прочитайте актуальный. Публикует человек в админке, «Уведомления» →
  «Письма»; ИИ не публикует и не сбрасывает текст.
- `preview_mail_template` — те же поля; возвращает `{ subject, html, text }` только на примерных
  данных шаблона, с названием сайта. Ничего не сохраняет, реальных данных заявок не получает.

Формат текста и обязательные блоки — [Письма](/averra-cms/admin/notifications/#письма).
Служебные шаблоны установки токену полностью недоступны.
