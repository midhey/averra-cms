Для студии и разработчика, которые хотят понимать систему целиком. После страницы вы будете знать,
какие части есть в Averra, кто с кем разговаривает и где что хранится.

## Части системы

```
                         сервер клиента (VPS)
                ┌──────────────────────────────────────────────────────┐
 посетитель ──► │ Caddy, домен сайта ── статика сайта (current)        │
                │        │ /api/forms/*            ▲                   │
                │        ▼                         │ сборка Astro      │
 клиент,    ──► │ Caddy, admin.домен ── /api/* ──► API ──► PostgreSQL  │
 студия         │        │                          ├──► медиатека     │
                │        └─ админка (статика)       └──► SMTP          │
 нейронка   ──► │ (MCP: тот же /api/*, токен Bearer)                   │
                └──────────────────────────────────────────────────────┘
```

| Часть | Что делает | Где в коде |
|---|---|---|
| **API** | данные, права, проверка схемами, медиатека, очередь писем, приём заявок, сборка сайта | `apps/api` (Hono, Drizzle) |
| **Админка** | экраны для людей: обзор сайта, редактор, медиатека, заявки, почта, состояние | `apps/admin` (React, Vite) |
| **Рендерер** | собирает сайт из JSON в HTML и CSS | `apps/renderer` (Astro) |
| **MCP-сервер** | инструменты для нейронки поверх того же API | `apps/mcp` |
| **Схемы** | блоки, страница, тема, поля форм, входы API | `packages/schema` (Zod) |
| **Блоки** | React-компоненты блоков: одни и те же в предпросмотре и на сайте | `packages/blocks` |
| **Установка** | Dockerfile, Compose, Caddy, установщик и `averra.sh` | `deploy` |

## Путь страницы

1. Человек в админке (или нейронка через MCP) правит черновик. API проверяет его схемами блоков
   и сохраняет. Сайт при этом не меняется.
2. «Опубликовать» копирует черновик в опубликованную версию и в той же транзакции пишет снимок в
   историю.
3. API ставит сборку сайта в очередь. Сборки идут по одной на установку, отдельным процессом с
   пределом памяти и таймаутом.
4. Рендерер (Astro) берёт у API снимок опубликованных страниц и настроек SEO и собирает статику в
   новую папку версии: страницы с мета-тегами, `robots.txt`, `sitemap.xml`, `404.html`, иконки. Туда
   же копируются картинки, на которые ссылаются страницы и настройки.
5. Ссылка `current` атомарно переключается на новую папку. Caddy со следующего запроса отдаёт
   новую версию — без простоя и перезапуска. Упала сборка — на сайте остаётся прежняя версия.

Подробнее для пользователя — [Публикация и история](/averra-cms/admin/publishing/).

## Форма на сайте

Форма — обычная HTML-форма. Она отправляет заявку на свой же домен (`/api/forms/…`), Caddy
передаёт этот путь в API. API проверяет заявку по опубликованной версии формы, сохраняет её и
ставит письма в очередь в одной транзакции, а посетителя возвращает на страницу с якорем
«Спасибо» и параметром `sent` — по нему считает цель аналитика. Подробно — [Заявки](/averra-cms/admin/leads/) и [Форма без
JavaScript](/averra-cms/decisions/no-js-form/).

## Где живут данные

Всё — на сервере клиента:

- **PostgreSQL** — сайты, страницы с черновиками и историей, пользователи, заявки, очередь писем,
  настройки SMTP (пароль — только зашифрованным);
- **том медиатеки** — оригиналы картинок и их варианты;
- **том сайтов** — собранные версии сайта. Это производные данные: при восстановлении API собирает
  их заново;
- **`/opt/averra/.env`** — секреты установки, права 600.

Бэкап снимает базу и медиатеку. Подробно — [Бэкапы и
восстановление](/averra-cms/install/backups/).

## В разработке

На машине разработчика всё то же, но проще: база — встроенный PGlite (настоящий Postgres в WASM),
картинки — в папке, письма — в файловом ящике, а рендерер показывает сайт прямо из API без
сборки. Как запустить — [Запуск](/averra-cms/dev/).
