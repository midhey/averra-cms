Для всех, кто решает, как что-то сделать в Averra: студии, разработчика, проверяющего. После
страницы вы сможете сверить любую новую идею с правилами системы.

1. **Одна схема — много потребителей.** Блок описан один раз: схема Zod и компонент. Из схемы
   получаются проверка в API, типы TypeScript, поля в админке и описание для нейронки. Кривой блок
   не пройдёт нигде.
2. **Контент — данные, а не HTML.** Страница — JSON со списком блоков и их полей. HTML в базе не
   хранится, его собирает рендерер.
3. **В git — код и схемы, в базе — то, что меняет человек.** Блоки, их варианты и тема по умолчанию
   живут в коде. Страницы, картинки, заявки и настройки сайта — в базе установки.
4. **Явное вместо глобального.** Никаких глобальных хуков по строковым именам и общего состояния.
   Данные приходят в компоненты пропсами, зависимости в API — через `createApp(deps)`.
5. **На выходе статика.** HTML и CSS без обязательного JavaScript: сайт целиком работает и без
   скриптов, даже форма заявки. Маленькие улучшения поверх рабочего HTML — можно (например, плеер
   видео по клику вместо ссылки на ролик); правила — [JavaScript на
   сайте](/averra-cms/dev/blocks/#javascript-на-сайте). Сайт быстрый, хостинг дешёвый, взламывать
   почти нечего.
6. **Стили только через токены.** Блок не знает конкретных цветов и шрифтов, только роли темы:
   «акцент», «фон», «текст». Поменяли фирменный цвет — поменялся весь сайт.
7. **Нейронка — такой же клиент API, как админка.** Те же схемы, те же права, те же проверки.
   Особых путей для нейронки нет, а персональные данные ей закрыты.
8. **Клиент не заложник.** Сайт выгружается статическим архивом, который отдаст любой веб-сервер,
   а все данные сайта — архивом с описанием формата.

## Что из этого следует

- Новый блок — это схема и компонент, а не настройка в базе. Как его добавить — [Свой
  блок](/averra-cms/dev/blocks/).
- Всё, что приходит снаружи (API, форма на сайте, MCP), проверяется схемой. Обойти её нельзя ни
  человеку, ни программе.
- Если для фичи нужен скрипт на сайте, сначала ищем способ без него. Пример — [форма без
  JavaScript](/averra-cms/decisions/no-js-form/).
