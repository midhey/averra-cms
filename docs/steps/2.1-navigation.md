# Шаг 2.1. Навигация по сайтам и страницам

## Цель

Админка перестаёт быть «одной страницей первого сайта». В ней три экрана со своими адресами: список сайтов → страницы сайта → редактор страницы. Из админки можно создать сайт, создать и удалить страницу, видеть, какие страницы опубликованы и где есть неопубликованные правки. Уйти из редактора с несохранёнными правками можно только после подтверждения. Обновление вкладки оставляет человека на том же экране.

## Решения и почему

1. **TanStack Router, маршруты в коде (code-based).** Типизированные параметры (`$siteId`, `$slug`) и `Link`/`navigate`, которые не скомпилируются с опечаткой в пути. Генератор файловых маршрутов не нужен: экранов три, дерево видно целиком в одном файле `src/router.tsx`. Маршруты плоские, дети корня: `/`, `/sites/$siteId`, `/sites/$siteId/pages/$slug`. Вложенность не нужна: у редактора своя полноэкранная вёрстка, общий у экранов только корень.
2. **TanStack Query для загрузки, кеша и мутаций.** Ключи — от общего к частному: `['sites']`, `['sites', id]`, `['sites', id, 'pages']`, `['sites', id, 'pages', slug]`. После мутации сбрасываем префикс, и всё зависимое перезагружается само. Опции запросов (`queryOptions`) лежат в одном файле `src/queries.ts`, ими пользуются и загрузчики маршрутов, и компоненты.
3. **Загрузчики маршрутов кладут данные в кеш Query** (`queryClient` в контексте роутера). Экран рисуется уже с данными, без мигания «Загружаю…» внутри экрана. Списки берут данные через `useSuspenseQuery` и обновляются после мутаций. **Редактор грузит страницу через `fetchQuery`, всегда свежую:** состояние редактора берётся из данных один раз при открытии, и если показать устаревший кеш (например, черновик поменяли через MCP), следующее сохранение затрёт чужие правки.
4. **Ошибки загрузки — на экран ошибки маршрута** с текстом от API («Сайт не найден», «Страница не найдена») и ссылкой «К списку сайтов». Неизвестный адрес админки — свой экран «Такой страницы нет».
5. **Уход из редактора.** `useBlocker` роутера с `window.confirm`, включён только пока есть несохранённые правки (`disabled: !dirty`). Свой `beforeunload` уже есть и остаётся, поэтому у блокировщика `enableBeforeUnload: false`: иначе он по умолчанию вешает предупреждение о закрытии вкладки даже без правок. `confirm` — как при удалении блока: одинаковое поведение, клавиатура и экранный диктор работают из коробки.
6. **Схемы входа API — в `@averra/schema`**, ими же проверяет форму админка: `SiteName`, `NewSite`, `PageSlug`, `NewPage`, `PageTemplate`. Одна схема — одно сообщение об ошибке и в браузере, и в ответе API.
7. **Адрес страницы (`PageSlug`)** — латиница в нижнем регистре и цифры, дефис только между ними (`uslugi`, `o-nas`, `price-2026`), до 64 символов. Раньше маршрут пускал и `-`, `--a`, `a-`; это ни к чему, а адрес сайта из них выходит кривой. Та же схема проверяет параметр `:slug` во всех маршрутах страницы и в MCP. Риск: страница с таким кривым адресом, созданная раньше через `PUT`, станет недоступна по API. Сам сайт создавала только демо-сид с `index`, через MCP адреса такого вида маловероятны; осознанно принимаем.
8. **Главная страница `index`.** Её нельзя удалить: API отвечает 409, у главной в списке нет кнопки «Удалить». **Новый сайт создаётся сразу с главной** (пустой черновик, заголовок = название сайта, не опубликована): иначе у сайта нет корня, а запрет удалять главную теряет смысл. Сайт и главная создаются в одной транзакции.
9. **Шаблон новой страницы:** `empty` — без блоков, `hero` — один блок «Первый экран» с примером из каталога (`hero.example`, id `hero`). Содержимое строит функция `pageTemplateContent` в `@averra/schema` и прогоняет через `PageContent`, так шаблон не может разойтись со схемой.
10. **Создание не публикует.** Новая страница — только черновик, на сайт попадает после «Опубликовать», как и любая правка.
11. **«Есть неопубликованные изменения» считает база:** `published IS NULL OR draft IS DISTINCT FROM published OR title IS DISTINCT FROM published_title`. Сравнение `jsonb` в Postgres смысловое (порядок ключей не важен), поэтому повторное сохранение того же содержимого флаг не поднимает. В список идут `slug`, `title`, `publishedAt`, `updatedAt`, `hasUnpublishedChanges`; главная первой, остальные по адресу.
12. **Ошибки — единый формат `ApiError`.** Занятый адрес — 409 `conflict` с `issues: [{ path: 'slug', … }]`: админка разносит `issues` по полям одинаково и для 400 проверки, и для 409, сообщение «Такой адрес уже есть» встаёт под полем «Адрес». Удаление главной — 409 `conflict` «Главную страницу удалить нельзя». Нет сайта или страницы — 404 `not_found`.
13. **Коды ответов:** `POST` → 201 с созданным, `DELETE` → 204 без тела. Вставка страницы — `ON CONFLICT DO NOTHING` по уникальному индексу `(site_id, slug)`: две одновременные попытки не дадут 500, вторая получит 409.
14. **`PUT /pages/:slug` по-прежнему создаёт страницу, если её нет.** Так работает `save_draft` в MCP, ломать его в этом шаге не нужно. Адрес проверяется той же `PageSlug`.
15. **Рендерер собирает один сайт** (`CMS_SITE_ID` или первый). Новый сайт из e2e рендерер не покажет, пока у рендерера нет выбора сайта (это модуль 9, выкладка по доменам). Поэтому e2e проверяет рендерер на новой странице демо-сайта, а полный путь «новый сайт → страница → публикация» — по снимку сайта в API, который и читает рендерер.
16. **Хлебные крошки** — `nav` с подписью «Навигация по разделам»: «Сайты / <сайт> / <страница>», текущий пункт с `aria-current="page"`. В редакторе крошки стоят в верхней панели вместо названия сайта.
17. **Формы создания** проверяются схемой при отправке, а после первой попытки — при каждом вводе. Ошибка поля связана с ним через `aria-describedby` и `aria-invalid`, общая ошибка (сеть, 500) — в `role="alert"`. После создания сайта открывается его список страниц, после создания страницы — её редактор.

## Критерии готовности

1. `pnpm check` зелёный; `pnpm e2e` зелёный; `pnpm e2e --shuffle --repeat-each 2` зелёный.
2. Админка: `/` — список сайтов; клик по сайту → `/sites/<id>` со списком страниц; клик по странице → `/sites/<id>/pages/<slug>` с редактором. В каждом экране есть хлебные крошки назад. Обновление вкладки (F5) на любом экране показывает тот же экран.
3. В списке страниц видны заголовок, адрес, состояние («Опубликована», «Есть неопубликованные изменения», «Не опубликована») и дата публикации.
4. «Новый сайт» с названием создаёт сайт с темой по умолчанию и пустой неопубликованной главной и открывает его страницы. Пустое название — ошибка у поля, запрос не уходит.
5. «Новая страница»: неправильный адрес — ошибка у поля «Адрес» (схема та же, что в API); занятый — «Такой адрес уже есть» под полем (ответ API 409). После создания открывается редактор; шаблон «С первым экраном» даёт блок «Первый экран» с примером.
6. Удаление страницы спрашивает подтверждение; отмена ничего не удаляет; у главной кнопки удаления нет, а API на `DELETE …/pages/index` отвечает 409 в формате `ApiError`.
7. Уход из редактора по ссылке или кнопкой «Назад» браузера с несохранёнными правками спрашивает подтверждение; отмена оставляет в редакторе с правками; без правок вопроса нет.
8. Новая страница после публикации открывается в рендерере по `/<slug>`.
9. API: все четыре новых маршрута проверяют вход схемами; 400/404/409 в формате `ApiError`; тесты на каждый случай.
10. Ни один e2e не зависит от другого: страницы и сайты, которые создают тесты, не мешают соседям.

## Тесты

### Юнит (`packages/schema`, `apps/admin`)
- `PageSlug`: принимает `index`, `o-nas`, `price-2026`; отклоняет пустой, заглавные, кириллицу, пробел, `_`, ведущий/хвостовой/двойной дефис, длиннее 64.
- `NewPage`: шаблон по умолчанию `empty`; лишнее поле — ошибка. `pageTemplateContent`: оба шаблона проходят `PageContent`; `hero` — один блок `hero` с примером.
- `SiteName`/`NewSite`: обрезает пробелы, пустое и слишком длинное — ошибка.
- `forms/field-errors`: ошибки Zod по путям (первое сообщение на поле), `issues` из ответа API, вложенные пути.
- `pages-format`: подпись состояния для трёх случаев, дата публикации по-русски.
- `errors`: `ApiRequestError` из ответа в формате `ApiError` и из ответа без него.

### Интеграционные (`apps/api`, `routes.test.ts`, PGlite в памяти)
- `GET /sites/:id/pages`: демо-главная опубликована без изменений; сохранённый другой черновик → флаг поднят; публикация → флаг снят; повторное сохранение того же содержимого флаг не поднимает; правка только заголовка поднимает флаг; главная первой; 404 нет сайта; 400 кривой id.
- `POST /sites`: 201, тема по умолчанию, сайт в `GET /sites`, у него неопубликованная пустая главная с заголовком = название; пробелы по краям названия обрезаны; 400 на пустое название и лишнее поле.
- `POST /sites/:id/pages`: 201 пустая и с `hero`; страница не опубликована и не попадает в снимок; 409 на занятый адрес с `issues[0].path = 'slug'`; тот же адрес на другом сайте можно; 400 на кривой адрес и пустой заголовок; 404 нет сайта.
- `DELETE /sites/:id/pages/:slug`: 204, страница пропадает из списка, `GET` даёт 404, опубликованная пропадает из снимка; 409 на `index`; 404 нет страницы; 404 нет сайта.
- Параметр `:slug` с кривым адресом → 400.

### e2e (`e2e/tests/navigation.spec.ts`)
- Путь по экранам: список сайтов → сайт → редактор главной и назад по хлебным крошкам; F5 на каждом экране оставляет на месте.
- Новый сайт → новая страница с первым экраном → правка заголовка → публикация: в списке страниц «Опубликована» с датой, в снимке API (то, что берёт рендерер) — новый заголовок.
- Новая страница демо-сайта → наполнить → опубликовать → рендерер открывает её по `/<slug>` с нужными `<title>` и `h1`.
- Ошибки формы: неправильный адрес — ошибка у поля, запрос не уходит; занятый адрес — «Такой адрес уже есть».
- Удаление страницы: отмена в диалоге ничего не удаляет, подтверждение удаляет; у главной нет кнопки удаления; API отвечает 409 на удаление главной.
- Несохранённые правки: уход по крошкам спрашивает подтверждение, отмена оставляет правку на месте, согласие уводит; без правок ухода без вопроса; кнопка «Назад» браузера тоже спрашивает.
- Существующие тесты редактора и публикации идут через новый адрес редактора и не меняют смысла.

## Итог

Сделано всё из плана. Админка открывается списком сайтов, у трёх экранов свои адреса (`/`, `/sites/<id>`, `/sites/<id>/pages/<slug>`), назад ведут хлебные крошки, F5 оставляет на месте. Сайт и страница создаются из админки, страница удаляется с подтверждением, главная — нет. В списке страниц видны заголовок, адрес, состояние и дата публикации. Уход из редактора с несохранёнными правками (ссылка, «Назад» браузера, закрытие вкладки) спрашивает подтверждение.

Проверки: `pnpm check` зелёный (схемы — 40 тестов, API — 33, админка — 30, MCP — 4); `pnpm e2e` зелёный — 20 тестов, из них 9 новых в `navigation.spec.ts`; `pnpm e2e --shuffle --repeat-each 2` зелёный (40). После прогонов порты 4100, 5273, 4421 свободны. Отдельно проверено: `vite build` админки собирается; `astro build` рендерера против временного API собирает статикой только опубликованные страницы (черновик в сборку не попал). `apps/api/.data` не открывался.

Зависимости: `@tanstack/react-router` ^1.170.42 (вышел 10.10.2026) и `@tanstack/react-query` ^5.104.1 (2.10.2026), только в `apps/admin`. Скриптов установки у них нет, исключения `minimumReleaseAge` не понадобились.

### Отклонения от плана

1. **Рендерер в dev не видел страниц, опубликованных после его запуска — исправлено.** e2e «новая страница открывается в рендерере» упал с 404: Astro в dev запоминает результат `getStaticPaths` до правки файла маршрута, поэтому новая страница появлялась только после перезапуска `pnpm dev`, а удалённая продолжала открываться. Маршрут страниц переехал из `src/pages/[...slug].astro` в `src/routes/page.astro` и подключается в `astro.config.mjs` через `injectRoute` с `prerender: command !== 'dev'`: при сборке он статический, как раньше, в dev — рендер по запросу. Файловым маршрутом так нельзя: `prerender` в файле обязан быть константой. Неопубликованный адрес в dev теперь отдаёт 404 (раньше бросал ошибку → 500). e2e проверяют оба направления: черновик по своему адресу — 404, после публикации — страница, после удаления — снова 404.
2. **Интеграционные тесты новых маршрутов — в отдельном файле** `apps/api/src/modules/sites/pages.test.ts`, а не в `routes.test.ts`: каждый тест заводит свой сайт и не зависит от демо-сайта, который правят старые тесты. Список проверок — как в плане, плюс «список только своего сайта», «новый сайт не встаёт перед демо» (рендерер без `CMS_SITE_ID` берёт первый) и 404 в едином формате на повторное удаление.
3. **`PageSlug`: пустой и слишком длинный адрес дают одну ошибку** (`abort` у `min`/`max`), иначе к «Поле не может быть пустым» добавлялось ещё и «не та латиница».
4. **409 всегда с `issues`** (у удаления главной — пустой список): формат ответа один, админке не нужно проверять, есть ли поле.
5. **Сверх плана:** e2e на экраны ошибок (несуществующий сайт, страница, адрес админки), на создание пустой страницы и на форму нового сайта; юнит-тесты `errors.ts` (разбор ответа API, тело не в формате API). MCP берёт из `@averra/schema` и `PageTitle`, а не только `PageSlug`.
6. **Фикстура e2e** теперь отдаёт тесту демо-сайт (`demoSite`) и перед каждым тестом удаляет с демо-сайта все страницы, кроме главной. `editor.open()` открывает редактор по прямому адресу.

### Что осталось на потом

- Рендерер собирает один сайт (`CMS_SITE_ID` или первый). Новый сайт из админки на рендерере не посмотреть, пока нет выбора сайта при сборке и выкладки по доменам (модуль 9). e2e проверяют новый сайт по снимку в API — ровно тем данным, из которых рендерер собирает страницы.
- Удалить или переименовать сайт пока нельзя; сайты, созданные e2e, копятся в `e2e/.data` до следующего прогона.
- Адрес страницы не предлагается по заголовку (транслитерация) — вводится руками с подсказкой.
- Страница, созданная раньше через `PUT` с адресом, который новая `PageSlug` не пускает (`a-`, `--a`), станет недоступна по API. Демо-сид создаёт только `index`, так что на практике это может коснуться лишь страниц, заведённых через MCP с таким адресом.
