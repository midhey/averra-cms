# Шаг 3.10. Новый интерфейс: редактор страницы

## Цель

Переделать редактор страницы (`/sites/:siteId/pages/:slug`) по утверждённому концепту `Editor.dc.html` на основе шагов 3.8 (`@averra/ui` — foundation frontend-kit `f904954` и тема Averra, компоненты `apps/admin/src/ui`) и 3.9 (оболочка и экраны). Редактор умеет всё, что умел, права те же, доступность не хуже, на 375 px нет горизонтальной прокрутки страницы. Старые `.module.css` редактора и его полей удаляются: после шага в админке нет ни одного `.css`.

Источники: концепт (раскладка, иерархия, отступы, цвета, тексты — эскиз, не код) и правила frontend-kit (`AGENTS.md`, `docs/style-system.md`, `docs/tokens.md`, `docs/llm.md`): токены primitives → semantic, сырые цвета только в токенах и темах, стили берут семантические роли, публичный Sass API без глубоких импортов, видимый `:focus-visible`, `disabled` и `reduced-motion`.

## Решения и почему

### 1. Раскладка: своя полноэкранная, без боковой панели

Как в концепте и как решено в 3.9, редактор остаётся вне `_app`: верхняя полоса и рабочая область на всю высоту окна (`100dvh`). Колонки прокручиваются каждая сама, страница целиком — нет: блоки, предпросмотр и поля видны одновременно.

- **Верхняя полоса** (`<header>`, внутри — область «Страница»): ссылка-иконка «Назад к сайту» (обзор сайта), название сайта мелко, заголовок страницы, плашка состояния; переключатель ширины предпросмотра; «История», «Сохранить», «Опубликовать» (только тем, кто может публиковать).
- **Заголовок страницы** — поле прямо в полосе, на месте текста заголовка в концепте: выглядит как текст, рамка появляется при наведении и фокусе. Подпись «Заголовок страницы» есть у поля (видна только диктору: рядом и так понятно, что это заголовок). Отдельной панели «Страница» не заводим — заголовок правят часто, и он должен быть под рукой. Ошибка заголовка и ошибки страницы целиком — строкой под полосой, связаны с полем через `aria-describedby`, как раньше.
- **Состояние** — одна живая область `role="status"` в виде плашки `StatusPill`: пока нет итога действия, она говорит, что с черновиком (решение 2); после действия — итог («Черновик сохранён», «Опубликовано…», «Версия N возвращена…»), он держится до следующей правки, как раньше. Ошибка действия — `InlineAlert` с `role="alert"` под полосой.
- **Кнопки** — `Button` из `ui`: «История» (`aria-expanded`, `aria-controls`; на узком экране, уже 64rem, — `IconButton` с подписью для диктора, см. «Мелочи после приёмки», 3.10-6), «Сохранить» (было «Сохранить черновик» — подпись концепта; недоступна без правок или с ошибками), «Опубликовать» — главная. Пока идёт действие, нажатая кнопка в состоянии `loading`.

### 2. Состояние черновика словами

Сейчас полоса говорит только «Всё сохранено / Есть несохранённые изменения». Концепт различает ещё и публикацию. API уже отдаёт страницу целиком (`published`, `publishedTitle`, `publishedAt`), поэтому состояние считается на клиенте чистой функцией `draftState` (`editor/draft-state.ts`, с тестом):

| Условие | Плашка | Тон |
|---|---|---|
| есть несохранённые правки | Есть несохранённые правки | warning |
| сохранено, страницу ни разу не публиковали | Черновик сохранён · не опубликован | warning |
| сохранено, опубликованная версия отстаёт | Сохранено · правки не опубликованы | warning |
| сохранено и опубликовано то же самое | Опубликовано | success |

Сохранённое и опубликованное сравниваются по смыслу: JSON с упорядоченными ключами (`stableJson`), а не текстом, — порядок ключей в ответе API и в редакторе бывает разный. После сохранения, публикации и возврата версии редактор берёт страницу из ответа API (PUT и publish отдают строку страницы), а не угадывает.

### 3. Три колонки, на узком экране — вкладки

- **Слева — «Блоки страницы»** (ориентир `navigation`, как раньше): заголовок «Блоки» и счётчик «3 из 50» (`PAGE_MAX_BLOCKS` из `@averra/schema` вместо числа в схеме). Пункт — ручка перетаскивания `DragHandle`, кнопка выбора (тип блока жирным, под ним подсказка содержимого), стрелки «Поднять/Опустить блок» и «Удалить блок» — `IconButton`. Выбранный — белая карточка в синей рамке (`aria-current="true"` у кнопки выбора: выбор виден не только цветом — ещё и рамкой и подложкой). Блок с ошибкой — плашка «Ошибка». Стрелки и удаление — только у выбранного пункта: список чистый, как в концепте, и у каждого блока нет лишних остановок Tab; переставить любой блок можно и ручкой. На узком экране они у каждого пункта (см. «Мелочи после приёмки», 3.10-6). Перетаскивание мышью и с клавиатуры, объявления диктору, стрелки и вопрос перед удалением — как раньше (`SortableList`, `useMoveButtons`).
- **Подсказка содержимого** — чистая функция `blockHint` (`editor/block-hint.ts`, с тестом): заголовок блока; без заголовка — число пунктов («4 пункта», «3 поля формы»); иначе якорь `#id`.
- **«+ Добавить блок»** — кнопка во всю ширину с пунктирной рамкой; открывает `Dialog` «Добавить блок» с каталогом: у каждого блока название, описание и пример (заголовок из примера). Выбор — кнопка-карточка: блок встаёт после выбранного, окно закрывается, новый блок выбран. Описания — новое обязательное поле `description` в `defineBlock` (`@averra/schema`): его видит и MCP в `list_blocks`. На пределе 50 блоков кнопка недоступна (`aria-disabled`, остаётся в порядке Tab), рядом сказано почему.
- **В центре — «Предпросмотр»**: серая подложка (`--color-surface-inset`), белая рамка выбранной ширины со скруглением и тенью. Телефон 375, планшет 768, десктоп 1280 px; шире колонки — ужимается масштабом, как раньше. Выбранный блок подсвечен рамкой цвета акцента; клик по блоку в предпросмотре выбирает его (решение 5).
- **Справа — «Поля блока»** (`complementary`): «Блок» мелко и название блока h2, якорь `#id` моноширинным, поля (решение 4). Без выбранного блока — `EmptyState` «Выберите блок». При открытой истории здесь панель истории (решение 6).
- **Узкий экран (< 64rem, `ui.breakpoint-down(medium)`)**: колонки становятся вкладками «Блоки / Предпросмотр / Поля» (третья — «История», пока она открыта). Вкладки — шаблон WAI-ARIA: `TabList` выносится из `Tabs` (`ui/Tabs.tsx`), чтобы у каждой колонки была своя панель (`role="tabpanel"`, `aria-labelledby`). Невыбранные панели скрыты атрибутом `hidden`, но не размонтируются: iframe предпросмотра и состояние форм живут. Выбор блока в списке на узком экране открывает «Поля». Переключатель ширины на узком экране — над предпросмотром во вкладке, а не в полосе. Узкий или широкий экран — `useMediaQuery` (`ui/use-media-query.ts`, `useSyncExternalStore` поверх `matchMedia`, с тестом): ARIA-роли вкладок нужны только там, где вкладки есть.

### 4. Поля (`SchemaForm`) на компонентах `ui`

Форма по-прежнему строится по JSON Schema блока, правила — те же. Меняется вид и разметка:

- **Строка** — `TextInput` / `TextArea` с `Field`: подпись (« · необязательно» у необязательных), подсказка из `description`, ошибка (`aria-invalid`, `aria-describedby`), счётчик «49 из 120 символов» для `maxLength ≤ 300`. Строка с шаблоном (ссылки, `Href`) — моноширинным (`mono`), без счётчика.
- **Перечисление**:
  - с пометкой `x-enum-sketches` (варианты оформления, сейчас — вариант первого экрана) — `SegmentedControl` вид «карточки» с миниатюрами `LayoutThumbnail` (по центру, слева, с картинкой);
  - короткое (до 4 вариантов) — `SegmentedControl` «сегменты» (число колонок);
  - длинное — `Select` (тип поля формы).

  Подписи вариантов — `x-enum-titles`. У первого экрана появляются подписи «По центру», «Слева», «С картинкой» и миниатюры; тексты ошибок схемы называют вариант по подписи («В варианте «С картинкой» (split) нужна картинка…»), чтобы человек видел то же слово, что на карточке, а MCP — значение.
- **Да/нет** — `Checkbox` с подсказкой.
- **Объект** (кнопка, необязательный блок полей) — `fieldset` с `legend`; необязательный — флажок «Показывать». Если все поля объекта однострочные (текст кнопки и ссылка), они встают в две колонки, как в концепте, и переносятся в одну на узкой панели (`auto-fit`).
- **Список пунктов** — сортируемые карточки: шапка карточки с ручкой, номером и именем пункта, стрелками и «Удалить пункт» (`IconButton`), ниже поля. «+ Добавить пункт» — `Button` с иконкой. Ключи пунктов, объявления и перестановка — как раньше (`useItemKeys`, `SortableList`).
- **Картинка** (`ImageField`) — карточка: превью 64×48, имя файла, «2400 × 1600 · AVIF, WebP» (`mediaFormats` из вариантов), «Заменить» (или «Выбрать картинку», если не выбрана) и «Убрать картинку»; описание (alt) обязательно — `TextInput` с подсказкой, ошибкой и счётчиком. Медиатека открывается в `Dialog` из `ui` (было своё `<dialog>`).

### 5. Подсветка и выбор блока в предпросмотре — только в админке

Блоки на сайте работают без JavaScript, и опубликованный сайт ничего не знает о редакторе — в `@averra/blocks` ничего не меняем. Надёжная опора уже есть: `Page` рисует каждый блок корневым `<section id={block.id}>` прямо внутри `<main>`, а id блока на странице уникален (это проверяет схема).

- **Подсветка** — отдельный `<style>` в iframe предпросмотра, его текст строит чистая функция `previewSelectionCss` (`editor/preview-selection.ts`, с тестом): рамка `outline` внутрь блока `main > section[id="…"]` и лёгкая рамка при наведении у остальных. Цвета — не сырые: значения ролей `--color-action` и `--color-border-strong` редактор читает из своего документа (`getComputedStyle`) и передаёт в iframe переменными. Глобальный слой админки в iframe по-прежнему не попадает (решение 3 шага 3.8). Толщина делится на масштаб предпросмотра, чтобы ужатый «десктоп» не терял рамку. Id в селектор попадает, только если проходит `BlockId` (латиница, цифры, `_`, `-`) — экранировать нечего.
- **Клик по блоку** — обработчик кликов в документе iframe (тот же, что не даёт уйти по ссылкам): ближайший `main > section[id]`, если такой блок есть в черновике, становится выбранным. Пока в предпросмотре версия из истории, клик ничего не выбирает (у версии другие блоки). Это удобство для мыши; с клавиатуры блок выбирают в списке слева.
- **Выбор из списка прокручивает предпросмотр** к блоку, если тот не виден (без плавности при `prefers-reduced-motion`).

### 6. История — панель на месте полей

Как и раньше, «История» заменяет колонку полей (на узком экране — вкладку «История»): `aside` «История публикаций» с h2. Версии — кнопки-карточки с `aria-pressed` (номер, «сейчас на сайте» — плашка, когда и кто, заголовок), внизу липкая полоса «Вернуть в черновик» (главная) и «Показать черновик». Подпись над предпросмотром о показанной версии — `InlineAlert` в живой области. Вопрос перед возвратом с несохранёнными правками, возврат фокуса на версию, «выбор блока закрывает историю» — как раньше. Диалог не берём: версию смотрят в предпросмотре рядом, а окно закрыло бы его.

### 7. Уход с несохранёнными правками

Без изменений: `beforeunload` при закрытии вкладки и `useBlocker` с `window.confirm` при уходе по ссылке внутри админки, в том числе по новой «Назад к сайту» (раньше — крошки).

### 8. Что удаляется

`editor/BlockList.module.css`, `Editor.module.css`, `History.module.css`, `Inspector.module.css`, `Preview.module.css`, `forms/SchemaForm.module.css`, `media/ImageField.module.css` — вместо них `.module.scss` на токенах. `ui/Breadcrumbs.tsx` и его стиль — ими пользовался только редактор, теперь у него «Назад к сайту». Закрытый список старых `.css` в `check-tokens.test.ts` исчезает: тест требует, чтобы в админке не было ни одного `.css`, и проверяет токенами все стили без исключений.

## Критерии готовности

1. Редактор по концепту: верхняя полоса (назад, сайт и страница, состояние, ширина предпросмотра, История, Сохранить, Опубликовать), три колонки, выбранный блок выделен в списке и подсвечен в предпросмотре.
2. Состояние в полосе: «Есть несохранённые правки» / «Черновик сохранён · не опубликован» / «Сохранено · правки не опубликованы» / «Опубликовано» — по данным API, после сохранения и публикации меняется.
3. «+ Добавить блок» открывает окно с каталогом (название, описание, пример); блок встаёт после выбранного и выбран.
4. Клик по блоку в предпросмотре выбирает его; на опубликованном сайте нет ни строки JS и ничего нового в разметке блоков.
5. Поля: подпись, подсказка, ошибка, счётчик; вариант первого экрана — карточки с миниатюрами; число колонок — сегменты; ссылки моноширинным; картинка — карточка с превью, размерами и форматами, «Заменить», обязательный alt; пункты — сортируемые карточки.
6. История — панель на месте полей; предупреждение об уходе с несохранёнными правками работает (в том числе по «Назад к сайту»).
7. На 375 px: вкладки «Блоки / Предпросмотр / Поля», всё работает, горизонтальной прокрутки страницы нет.
8. Доступность: настоящие `button`/`a`/`input`+`label`, `aria-label` у кнопок-иконок, текст 4,5:1 (роли темы), клавиатура и порядок фокуса, выбор виден не только цветом.
9. В админке нет ни одного `.css`; проверка токенов идёт по всем стилям без исключений.
10. Функциональность и права прежние: клиенту нет «Опубликовать»; перетаскивание, стрелки, удаление с вопросом, история и возврат, картинки, формы.
11. `pnpm check` и `pnpm e2e` зелёные, сценариев e2e не меньше.
12. Скриншоты 1440 и 375 px сняты, сравнены с концептом, расхождения — в «Итоге».

Горизонтальной прокрутки нет ни на одной ширине.

Совпадает с концептом: полоса `#FBFAF8` с квадратной «назад», название сайта 12 px и заголовок 16 px, плашка состояния с точкой, дорожка «Телефон / Планшет / Десктоп» по центру, «История», «Сохранить» и чёрная «Опубликовать»; слева «БЛОКИ» капителью и «3 из 50», выбранный блок — белая карточка в синей рамке, пунктирная «+ Добавить блок»; в центре серая подложка и белая рамка с тенью, выбранный блок обведён синим; справа «Блок» и название, карточки вариантов с миниатюрами и галочкой, поля с подсказкой и счётчиком («45 из 120 символов»), «Текст кнопки» и «Ссылка» в ряд, ссылка моноширинным, карточка картинки с превью, размерами и «Заменить».

Расхождения с концептом:
- **Стрелки и «Удалить блок»** — строкой под подсказкой у выбранного блока; в концепте у блоков только ручка. Без них пропала бы перестановка кнопками (с клавиатуры без режима перетаскивания) и удаление. На широком экране у невыбранных их нет, как в концепте: сначала пробовал показывать при наведении поверх конца подсказки, но такая накладка перехватывала щелчки по самой кнопке выбора (это поймал e2e). На узком экране (уже 64rem) они у каждого блока: там список — отдельная вкладка, и уходить с неё ради перестановки неудобно (3.10-6).
- **Заголовок страницы** — поле в полосе, выглядит как текст; подпись у него только для диктора. В концепте это просто текст, но заголовок страницы правится, а отдельной панели «Страница» в концепте нет.
- **Плашка** после сохранения сразу говорит, что с черновиком («Сохранено · правки не опубликованы»), а после публикации — итог «Опубликовано. Обнови сайт, чтобы увидеть»; в концепте один пример — «Черновик сохранён · не опубликован», он есть для страницы, которую не публиковали.
- **Полоса на узком экране** (уже 64rem): состояние — точкой и текстом, а не плашкой, «История» — иконкой; на телефоне (уже 40rem) название сайта спрятано. В концепте узкой полосы нет.
- **Ширина «Десктоп»** — 1280 px с ужатием под колонку (как было), в концепте рамка 960 px. «Планшет» — 768 px, в концепте 720.
- **Вариантов первого экрана три** («По центру», «Слева», «С картинкой»), в концепте два — в схеме их три.
- **Счётчик символов** — у всех коротких полей, не только у заголовка; приписки «станет h1 страницы» нет — подсказка поля берётся из схемы («Главная мысль страницы»).
- **«Описание картинки (alt)»** — подпись из схемы, в концепте «Что на картинке (alt)». Подсказка под полем — «Что на картинке — коротко, как сказали бы вслух».
- **Форматы под картинкой** перечислены все, что нарезаны («AVIF, WebP, JPEG»), в концепте — «AVIF, WebP».
- **История** — панель на месте полей, а не отдельный экран: в концепте её нет.
- **На 375 px** — вкладки; в концепте колонки просто переносятся друг под друга. Предпросмотр на телефоне начинается с ширины «Телефон».

### Отклонения от плана

- Интеграционного теста «Назад к сайту с несохранёнными правками» в `editor.spec.ts` нет: это уже проверяет `navigation.spec.ts` («уход из редактора с несохранёнными правками спрашивает подтверждение»), теперь по «Назад к сайту».
- «Сохранить» и «Опубликовать» недоступны через `aria-disabled`, а не `disabled`: после сохранения фокус остаётся на кнопке (e2e это проверяет). Правило записано в CONVENTIONS.
- Итог сохранения — сама плашка состояния, отдельного «Черновик сохранён» больше нет: оно скрывало, опубликованы ли правки.
- Добавлены тесты `forms/SchemaForm.test.tsx` и `editor/Editor.test.tsx` (полоса, каталог, вкладки) вместо отдельных тестов каждого компонента; `ui/use-media-query.test.tsx` — файлом `.tsx`.
- Колонка полей при выборе другого блока прокручивается к началу.
- Обработчик щелчков в iframe больше не полагается на `instanceof Element`: элементы iframe из другого окна, проверка ссылок шла через `closest`.

### Что не проверено

- Экранный диктор вживую не запускался: роли, имена, вкладки и фокус проверены Testing Library и Playwright.
- Режим принудительных цветов у поля заголовка — правило есть, в браузере не прогонялось. Выбранный блок и версия истории проверяются e2e (см. «Мелочи после приёмки»).
- `field-sizing: content` у поля заголовка работает в Chromium; в Firefox и Safari поле просто шире текста, плашка встаёт дальше.
