# Шаг 3.8. Основа интерфейса: frontend-kit и компоненты

## Цель

Подготовить основу для редизайна админки по утверждённому концепту (обзор сайта, редактор, заявки): стили на Sass по правилам frontend-kit владельца, тему Averra на токенах, свои шрифты и набор базовых компонентов. Экраны на этой основе собираются в шагах 3.9 и 3.10; здесь их не переделываем, только подключаем основу так, чтобы ничего не сломалось.

Источники: концепт (`Main.dc.html`, `Editor.dc.html`, `Leads.dc.html` — эскиз с инлайн-стилями: берём раскладку, иерархию, отступы, цвета и тексты) и frontend-kit (`git@github.com:midhey/frontend-kit.git`, коммит `f904954`: `AGENTS.md`, `docs/style-system.md`, `docs/tokens.md`, `docs/llm.md`, `src/styles`).

## Решения и почему

### 1. `@averra/ui` — перенос foundation кита как есть, чистый Sass

Новый пакет `packages/ui` без React и без знаний о продукте. В `src/foundation/` — папка `foundation` кита с той же раскладкой файлов (`config`, `tools`, `tokens`, `base`, `utilities`, `_index.scss`, `preset.scss`): так изменения кита переносятся сравнением папок, а не переписыванием. Не переносим пайплайны шрифтов и картинок, WordPress, пресеты React/Vue и демо: шрифты приходят из npm (решение 4), картинок в админке нет, пресеты и демо — не про нас.

Публичный вход — `exports` пакета с условием `sass` (его понимают и Vite, и наш тест):
- `@averra/ui` — Sass API (`config`, `rem`, `em`, `fluid`, `focus-ring`, `reduced-motion`, `breakpoint`), CSS не выводит;
- `@averra/ui/preset` — токены, сброс, базовые правила, утилиты (`.visually-hidden`, `.skip-link`, `.container`);
- `@averra/ui/themes/averra` — тема Averra.

Глубоких импортов нет: других путей в `exports` нет, Vite и тест их не найдут.

Что изменено в foundation по сравнению с китом (и почему) — в README пакета; коротко: новые семантические роли (решение 2), шкала размеров текста, моноширинный шрифт, `body` берёт размер и высоту строки из токенов. Цвета, правила `:focus-visible`, `disabled`, `reduced-motion` — как в ките.

### 2. Токены: primitives → semantic → (component), тема — другой набор значений

Слои как в ките: в `tokens/_primitives.scss` сырые значения (палитра, шкала отступов, размеров текста, радиусы, тени, время), в `tokens/_semantic.scss` роли (фон, поверхность, текст, граница, действие, фокус, статусы), которые ссылаются на primitives. Стили компонентов берут только семантические custom properties; палитру (`--palette-*`) напрямую — нет, это проверяет тест (решение 6).

Добавленные роли — с минимальными именами по роли, значения по умолчанию в foundation на палитре кита, а Averra переопределяет их в теме:
- поверхности: `--color-surface-sidebar` (боковая панель и верхняя полоса), `--color-surface-inset` (подложка предпросмотра, дорожка переключателей), `--color-surface-accent` (выбранный вариант);
- текст: `--color-text-placeholder`;
- границы: `--color-border-strong` (граница полей ввода — 3:1 к фону, WCAG 1.4.11; в концепте `#D6D4CC` даёт 1,4:1, поле на белом почти не видно), `--color-border-subtle` (разделители строк таблицы);
- главное действие: `--color-primary`, `--color-primary-hover`, `--color-primary-text` — в концепте главная кнопка почти чёрная, а синий акцент (`--color-action`) — у ссылок, выбранного, счётчиков и кольца фокуса. Так и делаем: один синий акцент, а «главная кнопка» — отдельная роль, и тема может сделать её синей одной строкой;
- статусы: к `success`/`warning`/`danger` кита (`-surface`, `-text`) — `info` и `neutral` и роль `-indicator` (точка статуса);
- размеры: `--font-size-small|caption|body|lead|title|headline|display`, `--font-weight-*`, `--line-height-body|tight`, `--radius-control|card|inner|item|pill`, `--shadow-raised|overlay`, `--size-control|control-small|sidebar`, `--space-page-inline|page-block|card`.

Тема Averra (`src/themes/_averra.scss`) по концепту: тёплый светлый фон `#F4F3EF`, белые поверхности, почти чёрный текст `#1A1B1E`, синий акцент `#2B44C7`, Golos Text и JetBrains Mono. Своя палитра темы (`--palette-sand-*`, `--palette-ink-*`, …) объявлена в ней же, роли ссылаются на неё. Тёмная тема — ещё один блок `[data-theme="dark"]` с теми же ролями и без правок компонентов; сама тёмная тема не делается.

Статусы различимы не только цветом: у плашки всегда есть текст, а точки статуса различаются по светлоте (L* через ≥ 8 единиц) — тест считает это по значениям темы.

### 3. Глобальные стили админки не попадают в предпросмотр

Предпросмотр копирует все `<style>` админки в iframe: в них стили блоков (CSS-модули). Сброс кита (`button { border: 0 }`, `ul { padding: 0 }`, `img { display: block }`, `:disabled { opacity }`) и токены `:root` (`--color-background`, `--color-text`, `--space-*` — те же имена, что у темы сайта) в iframe изменили бы вид лендинга относительно опубликованного. Поэтому глобальный слой (preset, тема, шрифты, базовые правила админки) собирается в `src/styles/global.scss`, подключается через `?inline` и ставится отдельным `<style data-admin-global>` первым в `<head>`; предпросмотр копирует всё, кроме него (`previewStyleNodes` в `src/styles/global-style.ts`, с тестом). CSS-модули компонентов админки в iframe попадают, как и раньше, — они на классах и лендинг не задевают.

### 4. Шрифты — `@fontsource`, свои `@font-face`

Golos Text (400, 500, 600, 700) и JetBrains Mono (400) из npm-пакетов `@fontsource/golos-text` и `@fontsource/jetbrains-mono` (OFL). Vite кладёт файлы в сборку админки с хешем в имени — шрифты раздаются со своего сервера, Google Fonts нет. Пайплайн кита (TTF → WOFF2) не берём: нужны исходники в репозитории и нативные зависимости со скриптами установки, а готовые подмножества уже есть в пакетах.

Готовые CSS Fontsource по подмножествам (`cyrillic-400.css`, `latin-400.css`) не годятся: в них нет `unicode-range`, и два `@font-face` с одинаковым начертанием перекрывают друг друга (кириллица ушла бы в запасной шрифт). Полные (`400.css`) тянут ещё `cyrillic-ext` и `latin-ext`. Поэтому `@font-face` пишем сами в `src/styles/_fonts.scss`: только WOFF2, только кириллица и латиница, `unicode-range` — как у Fontsource, `font-display: swap`.

### 5. Админка — на Sass, CSS-модули `.module.scss`

`sass` (Dart Sass) — как в ките; Vite подключает его сам. Новый код — `.module.scss` с `@use "@averra/ui" as ui;` и только семантическими токенами. Старые `.module.css` экранов остаются до шагов 3.9–3.10 закрытым списком исключений в проверке токенов: новый `.css` в админке проверку не пройдёт. `app.css` переезжает в `styles/global.scss` на токенах.

### 6. Проверки в `pnpm check`

- **Токены** (`packages/ui/tools/check-tokens.ts`, перенос `check-tokens` кита на TypeScript): разбор SCSS через `postcss-scss`, сырые цвета (HEX, функции цвета `rgb()`, `hsl()`, `hwb()`, `lab()`, `lch()`, `oklab()`, `oklch()`, `color()` и именованные цвета вроде `white`) запрещены вне `packages/ui/src/foundation/tokens/` и `packages/ui/src/themes/`; дополнительно — `--palette-*` и примитивы формы и текста (`--radius-small|medium|round`, `--shadow-small|surface`, `--type-*`) вне них же: тема переопределяет роли, а не примитивы; системные цвета (`Highlight`, `CanvasText`, устаревшие `WindowText`…) — только внутри `@media (forced-colors: active)`, иначе нарушение вида `system`. Тест `packages/ui/src/check-tokens.test.ts` проверяет сам механизм на образцах (как `tokens.test.mjs` кита) и прогоняет его по `packages/ui/src` и всем стилям `apps/admin/src`. Старые `.module.css` админки — закрытый список, лишняя строка в нём (файл удалили) — тоже ошибка.
- **Сборка стилей** (`packages/ui/src/styles.test.ts`): каждый `.scss` админки и пакета компилируется Dart Sass (ошибка Sass ловится до `vite build`); каждая `var(--…)` в стилях админки и пакета объявлена в токенах или теме (опечатка в имени токена — ошибка, а не тихий `unset`).
- **Тема** (`packages/ui/src/theme.test.ts`): контраст пар «текст/фон» темы Averra ≥ 4,5:1 (основной, приглушённый, плейсхолдер, ссылки, текст на главной кнопке и акценте, текст статусов на их поверхностях), граница полей ≥ 3:1 к фону и поверхности, точки статусов различаются по светлоте.
- **Линт SCSS** — stylelint с конфигом кита (`stylelint-config-standard-scss` и правила `scss/at-use-no-unnamespaced`, `scss/load-no-partial-leading-underscore`, `scss/no-global-function-names`). Biome SCSS не разбирает, а самописная проверка не заменит стандартный набор правил (опечатки в свойствах, неизвестные единицы, дубли, порядок). Отличие от кита одно: в CSS-модулях классы в `camelCase` (`styles.navLink`), в пакете — kebab-case и BEM, как в ките. `:global` в модулях разрешён. Запускается в `pnpm lint` (входит в `pnpm check`) только по `*.scss`: старые `.css` уйдут в 3.9–3.10.

### 7. Компоненты — `apps/admin/src/ui`

React-компоненты на токенах и CSS-модулях. Правила: настоящие `button`/`a`/`input` + `label`; у кнопок по умолчанию `type="button"`; кнопка-иконка без подписи не компилируется; иконки — один набор inline-SVG с обводкой `currentColor` (`aria-hidden`, `focusable="false"`); видимое кольцо фокуса от кита; `disabled` и `prefers-reduced-motion` учтены (спиннер не крутится, переходы выключены).

- `Icon` — набор иконок концепта (обзор, страницы, медиатека, заявки, настройки, стрелки, поиск, ручка перетаскивания, плюс, закрыть, меню, внешняя ссылка, галочка, предупреждение, корзина, скачать, история, выход).
- `Button` — `primary | secondary | ghost | danger`, `medium | small`, `loading` (кнопка остаётся в фокусе, `aria-busy`, `aria-disabled`, нажатие не срабатывает, спиннер), иконка слева. `buttonClassName()` — тот же вид для ссылок роутера («Новая страница», «Ответить письмом»).
- `IconButton` — `label` обязателен по типам и становится `aria-label` и `title`.
- `Field` и поля `TextInput`, `TextArea`, `Select` — подпись, подсказка, ошибка (`aria-describedby`, `aria-invalid`), счётчик «49 из 120 символов». Счётчик не ставит `maxLength`: вставленный длинный текст не обрезается молча, а превышение видно и его ловит схема. Моноширинный вариант для адресов, неизменяемая приставка («/»).
- `Checkbox` — нативный флажок с подписью, подсказкой и ошибкой.
- `SegmentedControl` — группа нативных радиокнопок в `fieldset` с `legend`: стрелки и Tab работают как у браузера. Вид «сегменты» (ширина предпросмотра) и «карточки с миниатюрами» (вариант блока, как в концепте).
- `Tabs` — шаблон WAI-ARIA: `tablist`/`tab`/`tabpanel`, перемещаемый `tabIndex`, стрелки, Home, End, счётчик в подписи вкладки («Новые · 3»).
- `StatusPill` — тона `success | warning | danger | info | neutral`, вид «плашка» и «точка с текстом»; готовые подписи концепта (новая, опубликована, черновик, есть правки, ошибка, обработана) — в витрине.
- `Card`, `PageHeader` (заголовок `h1`, строка сведений, действия, ссылка «назад»), `EmptyState`, `InlineAlert` (ошибка — `role="alert"`).
- `DataTable` — колонки описываются данными, `th scope="col"`, подпись таблицы, обёртка с горизонтальной прокруткой — область с `tabIndex=0` и подписью (прокручивается с клавиатуры), пустое состояние.
- `Dialog` — нативный `<dialog>` с `showModal()` (по CONVENTIONS): заголовок связан с окном, Esc и кнопка «Закрыть» зовут `onClose`, фокус возвращает браузер.
- `AppShell` — раскладка концепта: боковая панель 264 px и содержимое; на узком экране (< 64rem) — верхняя полоса с названием и кнопкой «Меню» (`aria-expanded`, `aria-controls`), меню закрывается по Esc (фокус на кнопку) и по переходу по ссылке. Ссылка «Перейти к содержимому». Части панели: `SidebarSection`, `NavList`, `navLinkClassName`, `NavLinkContent` (иконка, подпись, счётчик), `SidebarUser`. Экран внутри по-прежнему рисует свой `<main>`.

Существующие `TextField`, `AppHeader`, `Breadcrumbs`, `SortableList` остаются: экраны переходят на новые компоненты в 3.9–3.10.

### 8. Витрина `/dev/ui` — только в разработке

Маршрут регистрируется только при `import.meta.env.DEV`, компонент грузится лениво: в `vite build` его нет (тест `apps/admin/src/dev/production-build.test.ts` в `pnpm check` собирает админку во временную папку и ищет адрес и тексты витрины). Экран без входа (данных API не берёт) и без старой шапки. Витрина сама собрана в `AppShell`: в боковой панели — разделы витрины, в содержимом — все компоненты во всех состояниях (варианты, размеры, загрузка, `disabled`, ошибки полей, счётчик, пустая таблица, окно). По ней проверяющий и экраны 3.9–3.10 смотрят состояния.

## Критерии готовности

1. `@averra/ui` — чистый Sass, без React; публичный вход только через `exports`; README пакета говорит, откуда foundation (frontend-kit `f904954`), что изменено и почему, как синхронизировать.
2. Тема Averra на семантических ролях; сырые цвета (HEX, функции цвета, именованные цвета) только в `foundation/tokens` и `themes`; стили админки не берут `--palette-*` и примитивы радиусов, теней и шкалы текста; тёмная тема — только другой набор значений.
3. Шрифты Golos Text и JetBrains Mono грузятся с адреса админки (в сети нет запросов к `fonts.googleapis.com`/`fonts.gstatic.com`), только кириллица и латиница, только нужные начертания.
4. `pnpm check` включает stylelint по `*.scss`, проверку токенов, компиляцию всех `.scss`, проверку `var(--…)`, контраст темы.
5. Компоненты из решения 7 есть, с тестами на поведение и доступность; витрина `/dev/ui` открывается в разработке и отсутствует в сборке.
6. Предпросмотр редактора не получает глобальных стилей админки (тест на `previewStyleNodes`, e2e редактора зелёные).
7. Экраны работают как раньше: e2e без правок сценариев зелёные; на 375 px нет горизонтальной прокрутки страницы на витрине и на старых экранах, кроме редактора: он шире телефона и до шага (сетка `260px 1fr 360px` в `Editor.module.css`), переделывается в 3.10.
8. Скриншоты 1440 и 375 px витрины и старых экранов сняты и сравнены с концептом, расхождения описаны в «Итоге».

### e2e

### Major: проверка «шрифты свои» ничего не проверяла

**Что нашли.** `document.fonts.check('600 14px "Golos Text"')` отвечает `true` и тогда, когда `@font-face` для семейства нет вовсе, а `body.fontFamily` берётся из токена темы. Без `@use "fonts"` в `global.scss` или со сломанными путями к `@fontsource` ни один тест не падал.

**Что сделано.** `dev-ui.spec.ts` после `document.fonts.ready` берёт начертания со статусом `loaded` и требует среди них Golos Text 400 и 600 и JetBrains Mono 400. Кроме того, тест собирает ответы на `*.woff2`: хотя бы один должен прийти, и все — с адреса админки. Без `@font-face` загруженных начертаний нет, и тест падает; при сломанном пути Vite не соберёт стиль.

### Второй круг проверки

Проверяющий не принял шаг из-за одного major: исправление 3 первого круга (выбор в `SegmentedControl` в режиме принудительных цветов) не работало. Нашлось и шесть мелочей. Исправлено всё.

#### Major: принудительные цвета в `SegmentedControl` не применялись

**Что нашли.** Правило `@media (forced-colors: active) { .option:has(.input:checked) { … } }` имело специфичность 0,3,0, а обычные правила выбранного варианта — `.segments .option:has(.input:checked)` и `.cards .option:has(.input:checked)` — 0,4,0. Поэтому системная заливка не применялась. У сегментов оставались цвета темы. У карточки срабатывал только `color: HighlightText`, а фон оставался `--color-surface-accent`. В светлой системной палитре подпись выбранной карточки выходила белой на почти белом, около 1,05:1. Режим тогда проверялся только чтением CSS, в браузере его никто не запускал. Пункт 3 первого круга и CONVENTIONS описывали поведение, которого не было.

**Что сделано.**
- Медиазапрос перенесён внутрь блока выбранного состояния каждого вида. Специфичность теперь та же, а правило стоит ниже по тексту.
- Сегменты: заливка `Highlight`, текст `HighlightText`, `forced-color-adjust: none`. Кольцо фокуса в этом режиме — `CanvasText`, иначе оно осталось бы цветом темы.
- Карточки системной парой больше не заливаются: миниатюра внутри осталась бы в цветах темы. Фон и подпись отдаются браузеру (`Canvas`/`CanvasText`, читаемая пара в любой палитре). Выбор показывают рамка и галочка цвета `Highlight`.
- CONVENTIONS дополнен: куда класть правило для этого режима и когда заливать, а когда только обводить.

**Тест.** e2e «принудительные цвета (light|dark): выбранный вариант и вкладка видны» в `dev-ui.spec.ts`. Он включает `page.emulateMedia({ forcedColors: 'active', colorScheme })`, выбирает карточку «С картинкой» и читает вычисленные стили. Системные цвета берутся с пробного элемента. Проверяется:
- у выбранного сегмента фон `Highlight`, текст `HighlightText`, контраст подписи не ниже 4,5:1;
- у выбранной карточки контраст подписи не ниже 4,5:1, рамка и галочка (`::after`) — `Highlight`, у невыбранной рамка другая;
- у выбранной вкладки нижняя рамка `Highlight`, у невыбранной — `Canvas`.

Проверено, что тест ловит поломку: с выключенными правилами режима оба варианта падают на фоне сегмента.

#### Мелочи

1. **Нестабильный тест API.** «Удачная сборка пишет в журнал релиз и пик памяти» (`apps/api/src/publish/queue.test.ts`) при холодном старте полного `pnpm check` не укладывался в общие 30 с. Это первый тест файла, и он платит за PGlite, миграции и вход. Отдельно файл проходит примерно за 14 с. Тесту дан свой таймаут 90 с, причина записана в комментарии. Сам тест этот шаг не трогал. Если начнут тормозить и соседние тесты, лучше прогревать `setup()` в `beforeAll`.
2. **`sass` в рабочем образе.** Это необязательный peer `vite`. Раз он есть в рабочей области, pnpm подставляет его во все варианты vite, в том числе у `astro` и `@astrojs/react` рендерера. Поэтому `pnpm install --prod --filter "@averra/renderer..."` в Dockerfile тянет `sass`, `immutable` и готовые бинарники `@parcel/watcher`. Его скрипты установки выключены в `allowBuilds`. Решено оставить и задокументировать (комментарий в `deploy/Dockerfile`):
   - `dedupePeerDependents: false` или правило peer-зависимостей поменяли бы разрешение vite во всей рабочей области ради нескольких мегабайт;
   - сайт Sass не использует, и в рантайме API он не загружается.

Если объявление не лежит внутри `@media (forced-colors: active)` на любой глубине вложенности Sass, это нарушение вида `system`. Тест «системные цвета — только внутри @media (forced-colors: active)»:
   - вне медиазапроса и в `forced-colors: none` — нарушение;
   - внутри медиазапроса, в том числе вложенного в `&:hover`, — нет;
   - `field-label`, `marker`, `ui.mark` — не цвета.

   Из теста «похожее на цвет, но не цвет» убран `outline: … Highlight`. Нарушений по репозиторию нет.
5. **Размеры мимо токенов.**

   - Число на витрине — `--font-size-headline` (22 px вместо 20).

Комментарий объясняет: миниатюра — рисунок блока в масштабе, её скругления не форма интерфейса. `--radius-inner` (6 px) на квадрате 22 px сделал бы его почти кругом.
