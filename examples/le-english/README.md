# Vallex English на Averra

Пример переноса самописного сайта на Averra: одностраничник репетитора английского
(`le-english`, свой Node-сервис, мини-админка, стили по блокам) становится сайтом на Averra —
одиннадцатью своими блоками (восемь секций главной, «Ой!» для 404, свои шапка и подвал), темой,
окном записи с формой, поведениями и скриптами улучшений, политикой и согласием. Здесь же — скрипт, который ставит всё на установку
через API и при повторном запуске обновляет вид, не стирая правки клиента.

Общий разбор переноса и его правила — гайд
[«Перенос самописного сайта на Averra»](https://midhey.github.io/averra-cms/dev/migrate-site/).

Папка называется `examples/le-english`: `examples/` — готовые наборы для студии, а имя совпадает
с именем исходного проекта, чтобы по нему находить, откуда набор взят.

## Что внутри

| Что | Файл |
|---|---|
| Исходники блоков: `block.json` (ключ, поля, пример), `template.liquid`, `style.css`, `script.js` (если есть) | `blocks/<ключ>/` |
| Файл выгрузки блоков (`averra.custom-blocks`, версия 1) — его грузит «Свои блоки» → «Загрузить из файла» | `le-english.blocks.json` |
| Сборка файла выгрузки из исходников, проверка шаблонов, CSS и скриптов | `build-blocks.ts` |
| Скрипт импорта: фото, блоки, тема, настройки, документы, страницы, окно, шапка, подвал, скрипт сайта | `import.ts`, `src/` |
| Скрипт сайта: улучшения формы записи (подпись поля по каналу, «Спасибо, <имя>!») | `site/script.js` |
| Зерно бумаги для фона темы (SVG-шум оригинала, растрированный в PNG) | `assets/grain.png` |
| Логотип-картинка про запас: знак «Ve» и подпись, буквы в кривых (в шапке — логотип текстом) | `assets/logo.svg` |
| Снимки оригинала и переноса по частям, со склейками «оригинал \| перенос» (1440 и 375 px). Шлёт настоящую заявку «Боря» — только на localhost или с `--send-leads` | `compare/shoot.mjs` |
| Проверка поведения действием в Chromium: окно, отправка заявки, анимации, карточки, меню, без JS. Шлёт настоящие заявки — запускать на временной копии: на не-localhost нужен `--send-leads` | `compare/check.mjs` |
| Тесты: файл свежий и без ошибок, контент → страница, импорт и повторный запуск на настоящем API | `test/` |

Блоки — по секциям главной: `le-hero`, `le-goals`, `le-about`, `le-steps`, `le-reviews`,
`le-prices`, `le-faq`, `le-signup`; плюс `le-message` (страница 404) и места `le-header`,
`le-footer` (свои шапка и подвал). Поля повторяют `src/schema.js` исходного сайта (подписи,
подсказки, пределы), так что человек, который правил тексты в мини-админке, найдёт те же поля в
редакторе страницы.

## Как поставить

1. Установка Averra работает, у вас есть владелец (`pnpm user:create`). Нужны Node 24 и папка
   исходного сайта.
2. Запуск (из этой папки; зависимостей ставить не нужно):

   ```bash
   AVERRA_PASSWORD=… node import.ts \
     --source ../../../le-english --email owner@example.ru \
     --api https://admin.example.ru --origin https://admin.example.ru
   ```

   Пароль — переменной или скрытым вводом, не аргументом. Отдельного адреса у API нет: на установке
   Averra он живёт на адресе админки (`ADMIN_DOMAIN`, там Caddy отдаёт `/api/*`), поэтому `--api` и
   `--origin` — один и тот же адрес. `--origin` нужен потому, что API принимает изменяющие запросы с
   cookie только с адреса админки (`ADMIN_URL`). Скрипт ходит в API как
   владелец в админке: все проверки (схемы, контраст темы, ссылки меню) те же.
3. Без `--publish` страницы, тема, шапка, подвал и скрипт сайта остаются **черновиками**:
   откройте их в админке и сравните с оригиналом. Блоки публикуются всегда: без этого страница не сохранится (её проверяют
   по опубликованным блокам).
4. **Политика и согласие** скрипт делает черновиками из шаблона Averra (`/privacy`, `/consent`) —
   **после** страницы `/zapis` с формой: шаблон собирается по фактам сайта, и политика, созданная
   раньше, заявила бы «на сайте нет форм». Скрипт их не публикует: впишите реквизиты («SEO» →
   «Организация»), проверьте текст с юристом, удалите блок-пометку и опубликуйте сами. Старые
   адреса `/politika/` и `/soglasie/` уже перенаправлены на новые.
5. Опубликуйте сайт: запустите скрипт ещё раз с `--publish` (или опубликуйте страницы, тему, шапку,
   подвал и скрипт сайта в админке). `--publish` срабатывает, **только когда `/privacy` и `/consent` уже
   опубликованы**: форма записи собирает персональные данные, и без документов её ссылки на
   политику и согласие вели бы на 404. Пока документы — черновики, скрипт ничего, кроме блоков, не
   публикует и говорит, что сделать.
6. Скрипт можно запускать повторно — на чистой установке и на установке с прошлым переносом.
   **Вид — от набора, контент — клиента.** Блоки заменяются; тема, вид шапки и подвала (свой вид и
   настройки запасной стандартной), окно записи и скрипт сайта перезаписываются черновиками. Контент
   остаётся: страница, которую уже перенёс скрипт (главная со своими блоками набора, `/zapis` с
   формой, 404 с «Ой!»), не перезаписывается — в черновик дописывается только то, что нужно новому
   виду: «Открывать в окне» у кнопок записи (флажок, который клиент снял, остаётся снятым),
   настройка «Окно» у `/zapis`, если её нет и главную ещё не обновляла эта версия скрипта (у
   кнопок записи нет «Открывать в окне»): окно, которое клиент потом выключил, не возвращается.
   Поля для соцсетей в SEO дописываются, если их нет вовсе. Тексты шапки и подвала (знак и подпись
   логотипа, меню, кнопка, подписи своего вида, подпись подвала) после первого переноса тоже
   клиента. Перенос узнаётся не по текстам, а по установке и виду: главная уже со своими блоками
   набора, свой вид набора у шапки и подвала или вид прошлых версий скрипта. Чужая страница новой
   установки (демо-главная) и 404 прошлой версии скрипта, где клиент не правил ни одного поля,
   заменяются. `--reset-content` возвращает контент из исходного сайта (правки клиента в страницах
   и текстах шапки пропадут). «Скрипт сайта» скрипт ставит с меткой набора в первой строке и
   контрольной суммой в последней и заменяет новой версией, только пока сумма сходится. Свой
   скрипт интегратора и скрипт набора, в который дописали своё, не трогаются — скрипт только
   предупреждает. Фото с теми же
   именами не загружаются второй раз. **Документы** повторный запуск ведёт так:
   текст, который правил человек, не трогается, кроме одного случая: блока с фразой шаблона
   «нет форм заявок» (политику создала старая версия скрипта до страницы `/zapis`). Такой блок
   заменяется свежим блоком «Какие данные мы обрабатываем» из шаблона (если блок с таким id уже
   есть в черновике и сам не ложный, ложный блок убирается, а не дублируется), все остальные
   блоки и правки остаются. Переписанный юристом раздел про форму и пометка шаблона ничего не
   значат: черновики не попадают в историю версий, затёртое не вернуть. Поэтому перед любой заменой
   черновика скрипт кладёт его прежний текст в файл `<документ>-draft-<время>.json` в папке
   `~/.averra/le-english-backup/` (вне репозитория; другая папка — `--backup-dir`, путь пишется в
   лог): оборвалась связь или перезапустился API между заменой и возвратом текста — правки в
   файле, а вернуть их можно тем же запросом `PUT /api/sites/<сайт>/pages/<документ>` с этим
   файлом. Файл не удаляется сам: проверили
   страницу — удалите. Флаг `--rebuild-documents` заменяет черновики свежим шаблоном целиком
   (правки в них пропадут, но останутся в файле). У опубликованного документа
   заменяется только черновик, а опубликованная версия остаётся, пока вы не опубликуете новую.
   Если опубликованная политика говорит «нет форм заявок», скрипт предупреждает и не публикует
   сайт, пока вы её не поправите и не опубликуете; если слов про форму в тексте просто не нашлось,
   он только предупреждает. Настройки сайта при первом переносе — из исходного сайта (название,
   описание, шаблон заголовка, картинка для соцсетей, иконка, реквизиты «Организации», Telegram в
   соцсетях); адрес и телефон в «SEO → Организация» и вид уведомления о cookies остаются. При
   повторном запуске (главная уже перенесена, без `--reset-content`) настройки — клиента целиком:
   стёртый ИНН, убранный Telegram или очищенное описание не возвращаются, соцсети не
   объединяются. Скрипт дописывает только поля, которых у установки нет вовсе.
   Неопубликованные правки клиента в оставленных страницах, шапке и подвале с `--publish` на сайт
   не уходят: скрипт называет их в логе (`draftsBefore`) и ничего не публикует, пока вы не
   проверите правки в админке и не опубликуете их сами или не добавите `--publish-drafts`.
   Черновики, которые оставил сам скрипт (запуск без `--publish`, потом с ним), правкой клиента не
   считаются: их отпечатки лежат в папке `--backup-dir`, файл `drafts-<сайт>.json`.
   Всегда обновляются только редиректы со старых адресов документов (`/politika`, `/soglasie`) и
   страница политики для уведомления о cookies; `--reset-content` возвращает и настройки из
   исходного сайта. Кривой `--site-url` (не
   `https://домен`) скрипт отвергает до первых изменений.

## Как перенести живой сайт клиента

Контент живого сайта — не `content.default.json`, а `data/content.json` на его сервере (запись
`{ version, savedAt, content }`), а фото, которые клиент загрузил в админке, — `public/uploads/`.

1. Скопируйте с сервера `data/content.json` и `public/` (без `data/leads/`: заявки — персональные
   данные, их переносят отдельно и только с ведома клиента).
2. Запустите скрипт с `--content путь/к/content.json --public путь/к/public`. Реквизиты клиента
   из раздела «Документы» (`legal`) скрипт переносит в «SEO → Организация» — по ним собирается
   текст политики.
3. Проверьте в админке: тексты, цены, отзывы, вопросы, фото; в «SEO → Организация» — адрес;
   включите индексацию, когда сайт готов (новая установка скрыта от поисковиков).
4. Направьте домен на новую установку и оставьте на старом домене редиректы на новые адреса
   страниц (`/zapis/` остался тем же, документы — `/privacy`, `/consent`).
5. Заявки с формы — в «Заявки» и в уведомлениях Averra (почта, Telegram). Настройте получателей
   и подайте уведомление в Роскомнадзор на нового оператора данных, если оно меняется.

Если у клиента другие секции или поля, правьте `blocks/` и `src/content.ts`, затем
`pnpm --filter @averra/example-le-english build` и запускайте скрипт снова.

## Как устроен перенос

- **Тема** (`src/site-parts.ts`): фон, поверхность, текст, акцент и приглушённый — токены
  исходного сайта (`--color-page`, `--color-paper`, `--color-ink`, `--color-green`,
  `--color-muted`). Шрифты те же: Playfair Display (с настоящим курсивом) для заголовков, Manrope
  для текста, Caveat для рукописных подписей (`--font-accent`), JetBrains Mono для номеров и
  надзаголовков (`--font-mono`). Кольцо фокуса — ржавый оригинала `#b85418` (цвета акцента на
  тёмно-зелёной кнопке его не видно), строка браузера на телефоне — тёмно-зелёная, как
  `theme-color` оригинала. Фон — зерно бумаги узором из медиатеки (`assets/grain.png`: SVG-шум
  оригинала с `feTurbulence`, растрированный заранее). Контраст всех пар темы проверяет Averra.
- **Цвета бумаги** (терракота, розовая и бежевая бумага, скотч, маркер) — не роли темы. В CSS
  каждого блока они объявлены один раз переменными в начале файла; редактор блока предупреждает
  «цвет задан напрямую» — это ожидаемо, не ошибка.
- **Отступы секций** — как у оригинала: `:scope[data-custom-block] { padding: … }` (рамка секции
  Averra той же специфичности, что `:scope`, и иначе ставила бы свои поля 16 px на телефоне).
- **Шапка и подвал — свои виды** `le-header` и `le-footer` (места «шапка» и «подвал»), с разметкой
  и CSS оригинала. Почему не стандартные с настройками: настройками не повторить строку «Меню» под
  логотипом на телефоне и меню, раздвигающее страницу, знак 44 px, терракоту под мышью, последний
  пункт меню «Записаться на пробный урок →». Править клиент может то же, что и со стандартной:
  меню, кнопку и логотип (знак «Ve» и подпись «Vallex / English» текстом) — в «Шапке и подвале»;
  подпись строки «Меню», последний пункт меню телефона, рукописную подпись подвала и подписи ссылок
  на документы — в полях своего вида. Ссылки на документы подвал выводит сам, и строка документов
  Averra их не повторяет. Настройки стандартной шапки и подвала тоже заданы (без линии,
  «таблетка», кнопка в строке на телефоне, подвал фоном страницы) — это запасной вид: Averra
  покажет его, если свой вывести нельзя. У служебных страниц шапка короткая: логотип и «← На
  главную» (на 404 — только логотип, как у оригинала). Меню телефона раскрывается плавно
  (поведение `data-av-details`), пункты въезжают по очереди, бургер становится крестиком; Esc и
  выбор пункта закрывают его (скрипт шапки Averra); без JS — обычный `<details>`.
- **Окно записи.** Страница `/zapis` — окно (настройка «Окно»: заголовок «Попробуем?» из
  `signup.eyebrow`, широкое, фон — бумага, закрывается кликом мимо). Все пять кнопок записи
  (первый экран, отзывы, блок записи, кнопка шапки, последний пункт меню телефона) — с «Открывать в
  окне»: с JS форма открывается поверх главной, адрес не меняется, Esc, «Закрыть» и клик по фону
  закрывают, фокус возвращается на кнопку; без JS, Ctrl-кликом и по прямому адресу — страница
  `/zapis/` с той же формой (адрес со слэшем: без него сервер сайта отвечает лишним редиректом).
  Вид окна — бумажная карточка оригинала: рукописный надзаголовок, заголовок по центру, поля с
  рамкой 12 px, терракотовая кнопка-«таблетка» со стрелкой (CSS окон темы).
- **Форма записи** — встроенный блок «Форма»: своей формой её не сделать (в шаблоне своего блока
  `<form>` запрещён), а заявки принимает опубликованная страница с блоком «Форма» — с проверкой
  полей, согласием, защитой от спама и уведомлениями. Поля те же: имя, способ связи, контакт.
  Контакт проверяется по выбранному способу, как у оригинала: у каналов указан вид связи, у поля
  контакта — «проверять по способу связи», поэтому «Telegram» и «ab» не сохранится. Скрипт сайта
  (`site/script.js`) добавляет то, что у оригинала делал `lead-form.js`: Telegram выбран сразу,
  подпись, placeholder, клавиатура и подсказка поля контакта следуют каналу, после отправки —
  «Заявка у меня» и «Спасибо, <имя>! Свяжусь с тобой в Telegram…». В окне успех — как у
  оригинала: рукописное «Ура!», заголовок «Заявка у меня» и спасибо, без приглашения над формой
  (CSS окон темы). Окно после закрытия сбрасывает форму — скрипт снова выбирает Telegram.
- **Анимации** — CSS первого экрана (росчерки, маркер, посадка стикеров) и поведения Averra ниже:
  заголовки, карточки целей, шагов и цен, фото, пузыри отзывов (каждый со своей стороны), вопросы и
  карточка записи всплывают при прокрутке (700 мс, подъём и наклон оригинала в `--av-reveal-*`,
  карточки — лесенкой), линии под заголовками рисуются, первая карточка цели один раз
  поворачивается, ответы вопросов раскрываются плавно. Подъём кнопок и карточек под мышью и
  покачивание стикеров — CSS. Всё — только при `prefers-reduced-motion: no-preference`; без JS
  ничего не скрыто.
- **Карточки целей** переворачиваются без JS (скрытый флажок, клик и пробел). Скрипт блока
  (`blocks/le-goals/script.js`) добавляет оригинальное: Enter переворачивает, на широком экране
  мышью карточки раскладываются по доске, «↺ Разложить заново» (кнопку вставляет скрипт) возвращает
  их, подсказка меняется на «Перетаскивай карточки…».
- **SEO**: заголовок и описание для соцсетей (`shareTitle`, `shareDescription` оригинала) и
  описание картинки (`og:image:alt`) — поля SEO главной. В заголовке вкладки — «… — Vallex English».
- **404** — свой блок `le-message`: «Ой!» рукописным, «Такой страницы нет», тёмная кнопка-«таблетка».
- **Политика** — модуль политики Averra, а не тексты исходного сайта.

## Сходство и отличия

Снимки — `compare/shoot.mjs` (части страниц на 1440 и 375 px: шапка закрыта и открыта, каждая
секция, подвал, наведение на кнопки, открытый вопрос, окно и его успех после заявки, `/zapis/`, 404,
документ), поведение —
