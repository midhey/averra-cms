# Vallex English на Averra

Пример переноса самописного сайта на Averra: одностраничник репетитора английского
(`le-english`, свой Node-сервис, мини-админка, стили по блокам) становится сайтом на Averra —
восемью своими блоками, темой, встроенными шапкой, подвалом, формой записи и политикой.
Здесь же — скрипт, который ставит всё на установку через API.

Общий разбор переноса и его правила — гайд
[«Перенос самописного сайта на Averra»](https://midhey.github.io/averra-cms/dev/migrate-site/).

Папка называется `examples/le-english`: `examples/` — готовые наборы для студии, а имя совпадает
с именем исходного проекта, чтобы по нему находить, откуда набор взят.

## Что внутри

| Что | Файл |
|---|---|
| Исходники блоков: `block.json` (ключ, поля, пример), `template.liquid`, `style.css` | `blocks/<ключ>/` |
| Файл выгрузки блоков (`averra.custom-blocks`, версия 1) — его грузит «Свои блоки» → «Загрузить из файла» | `le-english.blocks.json` |
| Сборка файла выгрузки из исходников, проверка шаблонов и CSS | `build-blocks.ts` |
| Скрипт импорта: фото, блоки, тема, настройки, документы, страницы, шапка, подвал | `import.ts`, `src/` |
| Логотип для шапки: знак «Ve» и подпись, буквы в кривых | `assets/logo.svg` |
| Снимки оригинала и переноса для сравнения (1440 и 375 px) | `compare/shoot.mjs` |
| Тесты: файл свежий и без ошибок, контент → страница, импорт на настоящем API | `test/` |

Блоки — по секциям главной: `le-hero`, `le-goals`, `le-about`, `le-steps`, `le-reviews`,
`le-prices`, `le-faq`, `le-signup`. Поля повторяют `src/schema.js` исходного сайта (подписи,
подсказки, пределы), так что человек, который правил тексты в мини-админке, найдёт те же поля в
редакторе страницы.

## Как поставить

1. Установка Averra работает, у вас есть владелец (`pnpm user:create`). Нужны Node 24 и папка
   исходного сайта.
2. Запуск (из этой папки; зависимостей ставить не нужно):

   ```bash
   AVERRA_PASSWORD=… node import.ts \
     --source ../../../le-english --email owner@example.ru \
     --api https://api.example.ru --origin https://admin.example.ru
   ```

   Пароль — переменной или скрытым вводом, не аргументом. `--origin` — адрес админки установки
   (`ADMIN_URL`): API принимает изменяющие запросы с cookie только с него. Скрипт ходит в API как
   владелец в админке: все проверки (схемы, контраст темы, ссылки меню) те же.
3. Без `--publish` страницы, тема, шапка и подвал остаются **черновиками**: откройте их в админке и
   сравните с оригиналом. Блоки публикуются всегда: без этого страница не сохранится (её проверяют
   по опубликованным блокам).
4. **Политика и согласие** скрипт делает черновиками из шаблона Averra (`/privacy`, `/consent`) и
   не публикует: впишите реквизиты («SEO» → «Организация»), проверьте текст с юристом, удалите
   блок-пометку и опубликуйте сами. Старые адреса `/politika/` и `/soglasie/` уже перенаправлены
   на новые.
5. Опубликуйте сайт: запустите скрипт ещё раз с `--publish` (или опубликуйте страницы, тему, шапку
   и подвал в админке). `--publish` срабатывает, **только когда `/privacy` и `/consent` уже
   опубликованы**: форма записи собирает персональные данные, и без документов её ссылки на
   политику и согласие вели бы на 404. Пока документы — черновики, скрипт ничего, кроме блоков, не
   публикует и говорит, что сделать.
6. Скрипт можно запускать повторно: блоки заменяются, страницы, тема, шапка и подвал
   перезаписываются черновиками (правки в них после прошлого запуска пропадут), фото с теми же
   именами не загружаются второй раз. Настройки сайта дополняются, а не затираются: адрес и телефон
   в «SEO → Организация» и вид уведомления о cookies остаются. Кривой `--site-url` (не
   `https://домен`) скрипт отвергает до первых изменений.

## Как перенести живой сайт клиента

Контент живого сайта — не `content.default.json`, а `data/content.json` на его сервере (запись
`{ version, savedAt, content }`), а фото, которые клиент загрузил в админке, — `public/uploads/`.

1. Скопируйте с сервера `data/content.json` и `public/` (без `data/leads/`: заявки — персональные
   данные, их переносят отдельно и только с ведома клиента).
2. Запустите скрипт с `--content путь/к/content.json --public путь/к/public`. Реквизиты клиента
   из раздела «Документы» (`legal`) скрипт переносит в «SEO → Организация» — по ним собирается
   текст политики.
3. Проверьте в админке: тексты, цены, отзывы, вопросы, фото; в «SEO → Организация» — адрес;
   включите индексацию, когда сайт готов (новая установка скрыта от поисковиков).
4. Направьте домен на новую установку и оставьте на старом домене редиректы на новые адреса
   страниц (`/zapis/` остался тем же, документы — `/privacy`, `/consent`).
5. Заявки с формы — в «Заявки» и в уведомлениях Averra (почта, Telegram). Настройте получателей
   и подайте уведомление в Роскомнадзор на нового оператора данных, если оно меняется.

Если у клиента другие секции или поля, правьте `blocks/` и `src/content.ts`, затем
`pnpm --filter @averra/example-le-english build` и запускайте скрипт снова.

## Как устроен перенос

- **Тема** (`src/site-parts.ts`): фон, поверхность, текст, акцент и приглушённый — токены
  исходного сайта (`--color-page`, `--color-paper`, `--color-ink`, `--color-green`,
  `--color-muted`). Шрифты те же: Playfair Display (с настоящим курсивом) для заголовков, Manrope для
  текста и Caveat для рукописных подписей. Для третьего шрифта в тему добавлено необязательное поле
  **«Акцентный шрифт»** (`--font-accent`): без него рукописные подписи пришлось бы рисовать
  системным `cursive`. Контраст всех пар темы проверяет Averra.
- **Цвета бумаги** (терракота, розовая и бежевая бумага, скотч, маркер) — не роли темы. В CSS
  каждого блока они объявлены один раз переменными в начале файла; редактор блока предупреждает
  «цвет задан напрямую» — это ожидаемо, не ошибка.
- **Шапка и подвал** — встроенные. Меню ведёт на блоки главной по id (`goals`, `about`, …),
  кнопка «Пробный урок →» — на страницу записи.
- **Форма записи** — встроенный блок «Форма» на странице `/zapis`, куда ведут все кнопки
  «Записаться». Своей формой её не сделать: в шаблоне своего блока `<form>` запрещён, а заявки
  принимает опубликованная страница с блоком «Форма» — с проверкой полей, согласием на обработку,
  защитой от спама и уведомлениями. Поля те же: имя, способ связи, контакт.
- **Политика** — модуль политики Averra, а не тексты исходного сайта.
- **Анимации** — только CSS и только при `prefers-reduced-motion: no-preference`: рисование
  росчерков и посадка стикеров на первом экране, подъём карточек под мышью, переворот карточек
  целей. Всё, что держалось на JavaScript, не перенесено (см. отличия).

## Сходство и отличия

Снимки сделаны `compare/shoot.mjs` на 1440 и 375 px: у обоих сайтов нет горизонтальной прокрутки,
раскладка секций, ритм отступов, шрифты, бумага со скотчем, стикеры, переписка на тёмной полосе и
рваные края совпадают.

| Отличие | Почему |
|---|---|
| Фон страницы — сплошной цвет, без «зерна бумаги» | зерно — `url(data:…)` у `body`; у блока нет доступа к `body`, а CSS блока не пускает `data:` |
| Карточки целей не перетаскиваются, нет «Разложить заново» | перетаскивание — JavaScript; блоки Averra работают без него. Переворот — CSS (скрытый флажок, пробел с клавиатуры) |
| Блоки не «всплывают» при прокрутке, ответы вопросов не плавно раскрываются | то же: IntersectionObserver и анимация высоты — скрипты |
| Логотип «Ve» с подписью «Vallex English» — картинка (`assets/logo.svg`, буквы в кривых) | в шапке Averra логотип — картинка, а не текст своим шрифтом; цвет знака в картинке постоянный и не сменится вместе с темой |
| Шапка на 375 px: только «Меню», кнопка «Пробный урок» — внутри меню, а не пилюлей рядом | встроенная шапка Averra на телефоне прячет кнопку в меню, чтобы логотип и меню не теснились |
| Кнопка шапки со скруглением темы (8 px), а не пилюля; у шапки линия снизу | вид шапки — общий для всех сайтов Averra и берёт скругление и рамку из темы; скругление темы общее и для полей формы |
| Боковые поля на 375 px — 16 px, у оригинала 24 px | поля страницы задаёт рамка секций Averra, одинаковая для всех блоков |
| Шапка не липкая, как в оригинале | раскладку шапки задаёт Averra |
| Тёмная тема: бумага (розовая, бежевая, наклейки) остаётся светлой | её цвета — свои цвета блоков; на своей бумаге блоки сами задают и тёмный текст, поэтому он читается в любой теме, но бумага на тёмный фон не перекрашивается |
| Подвал — строка «© год, название» и документы; нет рукописной подписи «See you in class ♡» | подвал Averra — одна из трёх встроенных раскладок; их текст не редактируется |
| Форма записи — на странице `/zapis`, а не в окне поверх главной; нет плавающих подписей полей и подсказки, меняющейся от выбранного способа связи | встроенный блок «Форма» без JavaScript; зато заявка проходит ту же проверку, что любая заявка Averra |
| Моноширинный шрифт (JetBrains Mono) заменён системным | в теме три шрифта, моноширинного среди них нет; он стоит только у мелких подписей |
| Разметка для поисковиков: нет `Service`/`Provider` и `FAQPage` из своего блока вопросов | `<script type="application/ld+json">` в шаблоне запрещён; FAQPage Averra строит только по встроенному блоку «Вопросы» (его можно поставить вместо `le-faq`, потеряв вид). Организация — из «SEO → Организация» |
| Первый экран — `<h1>` внутри своего блока: редактор советует взять `h2` | h1 у страницы один, и именно этот блок — её первый экран; совет можно оставить |
| Тексты политики и согласия — шаблон Averra | требование: документы ведёт модуль Averra, чтобы реквизиты и сервисы подставлялись по настройкам |
